# 개발과 검증

## 재현 가능한 기본 환경

Node.js 22, npm, Git을 사용한다. `npm ci`는 lockfile의 버전을 설치한다. `.env`, 서비스 키, 게임 설치는 필요 없다. Python과 로컬 게임 DB는 선택적인 데이터 재생성에만 필요하다.

```sh
npm ci
npm run lint
npm test
npm run build
npm run preview
```

`predev`/`prebuild`가 라이선스 고지와 OCR 자산을 준비한다. OpenCV 실행 파일도 설치된 npm 패키지에서 `public/ocr/opencv.js`로 복사하므로 준비 단계를 생략한 직접 Vite 실행은 피한다. 최초 준비는 GitHub/Hugging Face 공개 모델 다운로드를 사용하고 고정된 리비전·SHA-256을 확인한다. `work/ocr`, `work/paddle`, `work/paddle-v6` 캐시와 `public/ocr`는 삭제 후 다시 만들 수 있다. 네트워크 차단이나 해시 불일치는 준비 오류이며 무결성 검사를 끄지 않는다.

코드·테스트는 OS 독립적인 상대 경로를 사용한다. 테스트는 `tests/*.test.ts`, 최소 회귀 입력은 `tests/fixtures/`에 있다. 실제 영상/전체 화면은 없어도 실행된다. CI의 Check와 Pages 배포도 lint → test → build 순서다.

## 브라우저에서 영상·이미지 검사

1. `npm run dev` 후 표시된 주소의 `/dev/scanner.html`을 연다.
2. 영상 하나 또는 이미지 여러 개를 선택한다. 이미지는 파일 이름순으로 처리한다.
3. **획득만 검사**를 선택하면 OCR 없이 검출·크롭 제외 사유를 확인한다. 전체 판독은 선택을 해제한다.
4. 실행이 끝나면 **결과 JSON 저장**으로 상태·진단을 로컬에 저장한다. 일반 앱의 목록·백업과 별개이며 시작 목록은 항상 비어 있다.
5. 수정 전후 같은 입력을 비교한다. 원본과 JSON에는 사용자 화면이 포함될 수 있으므로 공개 이슈에 그대로 올리지 않는다.

이 페이지는 영상의 실제 디코드 프레임을 순서대로 읽는 오프라인 검사다. 실시간 처리량·OS 화면 공유 권한·브라우저 스케줄링의 검증을 대신하지 않는다. 실제 공유는 메인 앱에서 직접 게임 창을 선택하여 검사한다. Dev 페이지는 프로덕션 엔트리에 포함하지 않는다.

`verify-scan.mjs`, `verify-screenshot-scan.mjs`의 라벨은 초기 특정 영상/사진에 대응한다. 새로 찍은 재고에 적용해 실패를 인식 오류로 단정하지 않는다. 검증용 정답은 입력 촬영 시점과 함께 별도로 작성한다.

## 변경에 따른 확인

- 인식: 정상/잘림/가림/저대비/0장과 최신 관측 충돌을 검사한다. 성능을 위해 확정 조건만 낮추지 않는다.
- 성능: 빈 목록 시작, 입력 길이·해상도·프레임률·장치/브라우저, 첫 결과, 공유 종료 때 확인 수, 최종 확인 수, 누락/추가/필드 차이, 보완 프레임 수를 기록한다.
- 계산: 공유 카드·중간 단계·자원 차감·미확인 입력과 마스터 참조 무결성을 검사한다.
- UI: 밝은/어두운 모드, 데스크톱/좁은 화면, 키보드 탭 이동, 스캔 중 탭 전환, CSV 잘못된 입력과 백업 복원을 확인한다.
- 자산 경로: `/`뿐 아니라 `PAGES_BASE_PATH=/loa-card/`로 빌드해 Worker·WASM·모델·고지 링크가 열리는지 확인한다.

단위 테스트 통과, 전체 영상의 수량 일치, 모든 필드의 수동 정답 일치는 서로 다른 검증이다. 공유 후 보완된 최종 결과를 실시간 결과로 보고하지 않는다.

## 남아 있는 진단 API

`runScanner`의 `debug` 인자는 프레임 기록/재현 등 개발 용도다. `debug-bundle.ts`는 LOACARD1 컨테이너 검증, `debug-capture.ts`는 프레임 순회, `debug-store.ts`는 임시 보관을 담당한다. 일반 사용자 UI에는 과거의 기록·재현 메뉴가 없다. 새 UI가 필요하면 현재 API와 해당 테스트를 사용하고 과거 개인 `work/*.html`에 의존하지 않는다.

## 문서 정리 시 검증 기록 (2026-10-08)

추적 파일과 새 개발 파일만 빈 폴더에 복사하여 기존 node_modules·개인 fixture·게임 DB·모델 캐시 없이 검사했다. Windows / Node 24.19.0 / npm 11.17.0에서 npm ci, lint, 378개 테스트, `/loa-card/` base 빌드가 통과했다. CI의 기준 Node는 22다. 최초 빌드가 공개 배포처에서 모델을 준비하고 해시를 검증했으며 개발 페이지는 dist에 포함되지 않았다.

개발 입력 페이지는 별도 사진 묶음의 한 장에서 40크롭 획득, 40종 판독·확인 필요 0건, JSON 저장을 확인했다. 입력에 표시된 전체 보관함은 384종이므로 이 단일 사진 검사로 전체 수집을 완료했다고 주장하지 않는다. 실제 OS 공유 전체 실행은 이번 문서 정리에서 다시 하지 않았다.

Mediabunny 배포 소스는 설치된 원본과 파일별 해시가 일치했다. 기존 큰 JS 청크 경고와 외부 라이선스 원문 누락 보고서의 두 항목은 남아 있다. 운영 배포 시에는 배포된 주소에서 전체 화면 공유를 별도로 검증한다.

## 중복 생성물 정리 검증 (2026-10-08)

OpenCV 중복 실행 파일을 npm에서 생성하는 방식으로 바꾸고 합성 픽셀 goldens 45개를 기존 바이트의 SHA-256으로 축소했다. 전체 테스트 371개·lint·Pages base(`/loa-card/`) 빌드·배포 고지 검사를 통과했다. 생성된 OpenCV는 이전 파일과 해시가 같으며 Pages 경로의 HTTP 응답·JavaScript MIME·해시를 확인했다. 실제 화면 공유·영상 전체 검사는 이번 정리에서 재실행하지 않았다.

이 정리 시점의 소스 파일 합계는 약 19.47 MB에서 5.94 MB로 감소했다. 이후 추가한 클라이언트 썸네일은 포함하지 않은 수치다. `node_modules`, 로컬 자료, 생성물과 Git 과거 이력을 제외한 작업 트리 기준이며 웹 배포 용량 감소를 뜻하지 않는다. OpenCV는 정적 배포에 계속 포함된다.

## 클라이언트 원화·상인 시간표 통합 검증 (2026-10-08)

클라이언트 원화 전환과 상인 시간표 추가 후 lint, 376개 테스트, 일반 빌드, `/loa-card/` base 빌드, 배포 의존성 검사가 통과했다. Pages 빌드의 자산 접두사, OpenCV·고지·원화 manifest 포함, 개발 화면과 개인 작업 폴더 제외도 확인했다. 원문 누락으로 추적 중인 두 의존성은 앱·Worker 모듈 553개와 검사한 사전 빌드 source map에서 참조가 없었다. 기존 큰 청크 경고는 남아 있다.

커밋 대상 약 9.35 MB에서 개인 절대 경로·원본 영상/DB/폰트·대표적인 비밀키 패턴과 깨진 문서 링크는 발견되지 않았다. 제한된 패턴 검사이며 과거 이력이나 모든 게임 자료의 배포 권리를 보장하지 않는다. 해시를 검사하는 외부 고지·OCR 문자표는 `.gitattributes`로 Git 줄바꿈 변환을 막아 원본 바이트를 유지한다. 화면 판독 비교와 사용자 화면 공유 확인의 범위는 [데이터 유지보수](data-maintenance.md)에 기록했다.
