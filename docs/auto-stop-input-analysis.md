# 자동 종료 입력 진단

개발 모드 화면 공유에서는 `ScannerState.completionInputDiagnostic`에 마지막 완료 검사 시점의 경량 집계를 둔다. 마지막으로 전달된 입력과 마지막으로 성공한 획득의 입력 ID·촬영 시각·도착 시각, 입장 생략 사유별 수, callback 보고 누락, ID 공백 및 순서·시각 오류를 확인할 수 있다. 개발 trace 콜백이 있으면 완료 검사 상태가 변할 때 집계도 `completion-input-diagnostic`으로 전달한다. 원본 픽셀과 개별 입력 이력은 이 집계에 기록하지 않는다. 상세 재현 기록의 입력 이벤트와 별도이며, 집계만으로 빠진 입력을 재생할 수 없다.

개발 검증 보고서에는 위 값을 `performance.completionInputDiagnostic`에 넣으며, 진단이 수집되지 않은 경우 `null`이다. 개발 전용 진단으로 배포 앱의 자동 종료 동작이나 사용자 화면을 변경하지 않는다.

`newerDeliveredInput`은 마지막 전달 ID가 마지막 성공 획득 ID보다 큰지만 나타내며, 어느 입력이 변했는지 또는 획득이 완료됐는지 증명하지 않는다. `null`은 비교에 필요한 값이 없다는 뜻이다. 실패 집계에는 명시적으로 보고된 획득 실패만 포함되므로 교체·예외 등을 모두 세었다고 해석하지 않는다. callback 누락 수가 없는 입력은 `sourceClockUnknown`으로 센다. 콜백이 보고한 누락이 없더라도 화면 캡처 생산 단계 전체의 누락이 없다는 증거가 아니다. 부분 기록, 마지막 검사의 시점 이후 전달, 교체·실패한 입력 및 소스의 미전달 프레임도 고려해야 한다.

`lastSkippedInputId`는 전달된 입력 중 생략 사유별 가장 큰 ID이고, `skippedAfterLastCompletion`은 그 ID가 마지막 성공 획득의 ID보다 큰지를 사유별로 나타낸다. 획득 완료가 비동기로 늦어져도 입력 ID로 비교한다. 성공 획득이 없거나 입력 순서·시각 오류 또는 전달 ID 공백이 있으면 비교 결과는 `null`이다. 이는 전달된 입력의 생략만 설명하며, 소스에서 전달되지 않은 프레임이 없다는 뜻은 아니다.

`pipeline`은 동결 후 대기열에서 일어난 `replaced`, `capacity`, `error`, `disposed`, `rejected` 해제를 사유별로 집계한다. 정상 해제는 손실에 넣지 않으며, 해제 자체의 실패는 손실 사유와 별도 `releaseFailures`로 기록한다. 사유별 마지막 입력 ID와 `lossesAfterLastCompletion`은 마지막 성공 획득보다 캡처 순서가 나중인 손실이 기록됐는지 보여 준다. 해제 사건은 획득 완료보다 늦게 도착할 수 있으므로 완료 시각이 아니라 입력 ID를 비교한다. 사건 순서·시각·입력 연결 오류, 기록 실패, 사건 부재 또는 입력 ID 공백은 비교를 `null`로 남긴다. 획득 이후 입력이 아직 처리 중이면 이미 관측한 손실은 표시하지만 관측하지 않은 사유는 `null`로 둔다. 교체나 판독 종료 후 해제 사건을 아직 받지 못한 경우에도 비교는 `null`이다. `open`은 아직 종결되지 않은 파이프라인 입력 수이며, `false`는 현재까지 관측된 해당 사유의 해제가 없다는 뜻이지 누락된 화면이 없다는 뜻이 아니다. 이 값 역시 완료 허용이나 재생 가능한 픽셀의 증거가 아니다.

`releaseFailureAtOrAfterLastAcquisition`은 마지막 성공 획득과 **같은 ID**의 해제 실패도 포함한다. 획득이 끝난 후 그 입력의 자원이 해제되기 때문이며, 해당 입력이나 이후 입력의 해제가 아직 끝나지 않았다면 `null`이다. 이 필드는 실패의 캡처 ID 범위를 나타내며 자원 해제 시각의 전역 순서를 주장하지 않는다.

이 값은 **개발 진단이며 자동 종료 조건을 변경하지 않는다.** 현재 운영 경로는 수집 주기 또는 원본 기록 용량 때문에 마지막에 전달된 입력을 생략할 수 있고, 생략된 입력의 내용이 바뀌었더라도 이전 카드·헤더 근거로 종료할 위험이 있다. 이를 재현하는 단위 검사는 `tests/completion-current-view.test.ts`다. 정확한 픽셀 비교 실험도 애니메이션·입력 크기·소스 시각 신뢰성 등의 제약이 있으므로 무조건 활성화할 수 없다. 실제 최신성 증명과 종료 성능 검증은 별도 작업이 필요하다.

판독 대기열이 가득 차 획득한 화면 전체를 처리하지 못하면 `droppedFrames`가 증가한다. 이 획득 손실은 카드 수량이나 이후에 확인한 카드만으로 해소하지 않고 자동 종료·복구 생략과 최종 지도 전체 확정 표시를 막는다. 마지막 손실 수가 없거나 유효하지 않아도 전체 확정을 표시하지 않는다. 현재 손실 카운터는 같은 스캔에서 해소할 수 없으므로, 경고는 화면 공유를 종료한 뒤 새 스캔을 시작하도록 안내한다. 새 스캔은 별도의 0 카운터로 시작한다. 이는 정상적인 주기 생략이나 동결된 대기 입력 교체까지 검증한다는 뜻은 아니다.

진행 표시와 목록 백업에는 미식별 목록 수와 ledger 미해결 그룹 수의 최댓값을 `unresolvedObservations`로 전달한다. 두 수는 같은 입력을 포함할 수 있으므로 더하지 않으며 실제 미해결 전체의 하한이다. 스캔 중 별도 진행 창도 같은 하한과 `droppedFrames`를 사용한다. 과거 백업에 하한이나 손실 상태가 없으면 해당 상태는 미확인이며, CSV처럼 스캔 입력이 없는 목록과 구분한다. 표시가 없어도 원본 픽셀이 없거나 누락이 없었다고 증명하지 않는다.

완료 및 원본 재사용 조건은 최신 필드 가드가 명시적으로 `true`일 때만 통과한다. `false`뿐 아니라 값이 없거나 유효하지 않은 경우도 미확정이다. 새 스캐너 실행은 공통 상태의 가드를 전달하며, 과거 기록에서 가드가 없었다는 사실을 확인된 `true`로 채우지 않는다. 이 변경은 구형 기록을 읽는 형식이나 과거 상태 재생 로직을 바꾸지 않는다.
