# 클라이언트 카드 렌더 재현 명세 (2026-11-05)

목표: 게임이 카드 한 장을 그리는 방식과 픽셀 수준으로 같게 재현한다. 이 문서는 **측정된 값**과 **아직 측정하지 못한 값**을 구분해 기록한다. 값은 모두 실제 캡처와 클라이언트 아틀라스 픽셀에서 역산했다.

## 클라이언트 원본 UV 확보 (2026-11-05)

`data3.lpk`(KR 프로필)에서 `IconInfo.loa`(3.2MB)와 `UIProperties.loa`를 추출했다. `work/extract-lpk/`(읽기 전용 추출기)와 `work/parse-iconinfo-full.py`로 45,252개 항목을 전부 파싱했다.

- 형식: `f32 version, u32, u32, u32 count` + 항목마다 `u32 nameLen/name`, `u32 atlasLen/atlas`, `u32 x,y,w,h,pad,strLen`, `strLen`바이트 태그, `u32 flag`. 45,252개 파싱 후 커서가 파일 끝과 정확히 일치해 형식이 검증됐다.
- 결과: 카탈로그 **452종 전부**에 클라이언트 자신의 아틀라스 이름·사각형이 있다.
  - 기존 시각 대조 맵과 비교 가능한 417종 중 **415종이 완전 일치**(아틀라스+좌표).
  - 불일치 2종(3200121·3200157)은 클라이언트 좌표와 기존 좌표가 **같은 그림의 중복 사본**을 가리킨다(`work/border-verify/artwork-uv-disagreement.png` 육안 확인). 즉 기존 맵도 결과는 맞고, 클라이언트 좌표가 권위값이다.
- 산출물: `work/client-data/IconInfo.json`(5.9MB), `work/client-data/artwork-uv-comparison.json`.

**한계:** 카드 보관함 UI 크롬(테두리·글로우·판·배너)은 IconInfo에 없다. 그 텍스처 시트(`cardstorageseason2_i2/i4e`)의 스프라이트 사각형은 `.upk` UI 패키지 내부에 있고 현재 도구로 파싱되지 않는다. 따라서 이 부분은 픽셀 측정값(프레임 내부 구멍 검증 포함)을 유지한다.

### 현재 카탈로그 적용 결과

- 카탈로그 420종 전부가 클라이언트 권위 사각형을 가진다 (`work/client-data/authoritative-artwork-map.json`).
- 기존 `scripts/client-artwork-map.json`과 비교: **415종 완전 일치**, 2종(3200121·3200157)은 같은 그림의 중복 사본을 가리켜 특징값이 최대 4/255만 다르다.
- 내부 ID 3종(`catalog:zakra-sarta`, `catalog:four-elders`, `catalog:illusion-moon`)도 `clientId`(3201111~3201113)로 조인하면 클라이언트 사각형이 있다. 2025-09-24 업무데이트로 추가된 누크만의 환영석 카드 3종이며 Grade 4(영웅)·MaxWakeUp 0(성장 불가)이다. 앱 ID는 호환성을 위해 `catalog:`를 유지하고 `clientId`로 연결한다.
- 따라서 **지금 배포 데이터를 바꿀 필요는 없다**. 권위 좌표로 재생성하면 2종의 특징이 미세하게 달라지고 `artwork-provenance.json`·NOTICE 해시를 다시 계산해야 하는데, 인식 결과 차이는 측정되지 않았다. 재생성이 필요해질 때 이 파일을 입력으로 쓰면 시각 대조 단계를 생략할 수 있다.

## 별도 트랙: `.upk` 언패커 (인식 목표와 분리)

`EFUI_CARDGAMESEASON2.upk`는 UE3 태그(`0x9E2A83C1`)·버전 868로 시작하지만 본문 엔트로피가 7.4~8.0이고 스프라이트 이름이 평문으로 없다. 즉 압축 또는 암호화되어 있어 현재 도구(원시 PNG 스캔)로는 열리지 않는다. 열려면 UE3 요약 파싱 + Oodle/zlib 청크 해석 또는 암호 키가 필요하다.

- **현재 영향 없음**: 카드 신원·원화 UV·아틀라스·폰트는 다른 경로로 확보했고, 카드 보관함 UI 크롬 좌표는 픽셀 측정과 프레임 내부 구멍 검증으로 고정했다.
- **착수 조건**: 다른 해상도·UI 배율 지원으로 UI 배치 상수를 재측정 없이 얻어야 할 때, 또는 `.upk` 안에만 있는 UI 상태(호버·선택·각성 연출) 좌표가 필요해질 때.
- **분리 이유**: 암호·압축 스킴 리버싱은 인식 정확도와 무관한 별도 프로젝트이며, 실패하면 인식 목표 전체를 막는다. 그래서 인식 파이프라인의 필수 경로에 넣지 않는다.

## 레이어 순서 (측정으로 확인된 것)

1. 원화(artwork)
2. 이름·하단 밴드를 덮는 어두운 판 (반투명, 런타임 알파)
3. 등급 테두리
4. 이름 텍스트 (등급색)
5. 각성 보석 5칸
6. 장착중 배너 (장착 상태일 때)
7. 카운터 아이콘 + `+N` (추가 장수)

## 아직 재현하지 못한 것

1. **이름·하단 판**: 아틀라스의 `(691,549) 161×61`, `(689,737) 163×54`는 **불투명 단색**(RGB 17,20,24)인데, 게임에서는 반투명으로 그려진다. 실측 런타임 알파가 카드마다 0.10~0.51로 흔들려 단일 스프라이트 모델로 설명되지 않는다. 그라디언트이거나 9-slice일 가능성이 있다.
2. **카운터**: 청록 카드 아이콘과 `+N` 글리프의 위치·크기·색을 아직 역산하지 않았다. 판독용 `counter-patterns.json`(48×20)과 클라이언트 스프라이트는 배율이 다르다.
3. **장착중 배너**: 아틀라스 `(520,860) 171×47`을 추출했지만 실제 그리기 위치·텍스트 크기는 미측정.
4. **강조 글로우**: `glow-0..3`을 추출했으나 어떤 상태(장착/선택/호버)에서 그려지는지 미확인.
5. **UI 배율**: 사용자 설정(현재 100%, 2560×1440)에서만 1:1이다. 다른 배율은 전 레이어 재측정이 필요하다.

## 완전 재현 절차 (제안)

1. **레이어별 역산 하네스**: 각 레이어를 단독으로 켜고 실제 캡처와 마스크 MAD를 최소화하는 (배율, 오프셋, 알파)를 카드 20~50장에서 동시에 푼다. 판·글로우처럼 값이 흔들리는 레이어는 카드별 분산을 먼저 본다.
2. **텍스트 메트릭**: 폰트·크기·stroke·자간·장평을 등급별로 따로 푼다. 현재 IoU 0.50은 폰트는 맞고 메트릭이 남았다는 뜻이다.
3. **카운터**: 아이콘 스프라이트와 숫자 폰트를 분리해 각각 위치·크기를 푼다.
4. **검증 기준**: 카드 50장에서 레이어별 MAD와 전체 MAD를 기록하고, JPEG 잡음 수준(내부 MAD ≤ 12)에 도달하는지 본다. 도달 전에는 "동일"이라고 쓰지 않는다.

## 한계

- 아틀라스에 스프라이트 UV 메타데이터가 없어 박스는 픽셀 측정값이다. 프레임은 내부 구멍 검증(`verify_border_boxes`)으로 고정했지만, 판·글로우는 같은 방법이 없다.
- 실제 게임의 그라디언트·블렌드 모드는 픽셀에서 역산한 근사이며 셰이더 수식이 아니다.
