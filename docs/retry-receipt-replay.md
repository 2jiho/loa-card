# 재시도 입장 원장 재생 실험

`retry-receipt-state.ts`와 `retry-receipt-replay.ts`는 스캐너에 연결하지 않은 실험이다. 타임아웃 뒤 재시도 입장 및 토큰 상태를 기록 순서대로 재생한다. OCR 판독, 카드 확정, 실제 화면 공유의 완료나 성능을 검증하지 않는다.

기록기는 이벤트마다 유효한 원장을 갱신하고 기록 번호, 정규화된 이벤트와 승인 여부·사유를 전달한다. 저장 콜백이 순서대로 기록하고 성공을 반환해야만 다음 상태로 진행한다. 동시에 쓰기를 허용하지 않으며 실패나 이벤트 50,000개 제한 이후에는 봉인되지 않은 체크포인트만 얻는다. 보관 주체는 모든 기록을 실제 저장한 뒤 체크포인트를 별도로 저장해야 한다. 기록기 자체는 이벤트 목록을 메모리에 쌓지 않으며, 원장 크기는 최대 2,048개다. 디스크·IndexedDB 저장 및 실패 복구는 구현하지 않았다.

재생은 빈 원장부터 실행하며 연속 번호, 결정 결과, 설정과 전체 이벤트의 SHA-256 연결 해시를 비교한다. 누락·순서 변경·변조·미봉인 체크포인트를 성공으로 취급하지 않는다. 체크포인트나 기록이 빠지면 복원할 수 없다. 체크포인트와 기록을 함께 교체할 수 있는 경우 해시만으로 위조를 막을 수 없으며, 저장 완료 또한 콜백의 계약에 의존한다.

기존 이벤트에 저장된 `origin: live`를 재생하는 것과 재생에서 새 이벤트를 발행하는 것은 다르다. 새로운 `origin: replay` 또는 `synthetic`은 라이브 재시도로 승인하지 않는다. 기존 원장은 같은 input ID 또는 sourceFrame ID의 재사용은 거부하지만, 서로 다른 문자열이 실제로 다른 물리 프레임임을 증명하지 못한다. 여러 카드가 같은 실제 프레임에 등장할 수도 있으므로 세션 전체에서 동일 frame ID를 일괄 중복 처리하지 않는다. 재생 성공 결과의 `physicalSourceVerified`와 `scannerIntegrated`는 항상 false다.

실제 경로에 적용하려면 먼저 획득 계층에서 물리 입력 출처와 별칭 관계를 검증하고, 저장 원자의 성공·불완전 기록·재시도 큐와 취소를 실제 이벤트로 연결해야 한다. 또한 기록 비용과 실제 스캔 정확도·지연을 별도로 검증해야 한다. 단일 체크섬이나 문자열 ID로 독립 관측을 확정하면 안 된다.
