# 레이드 카드 계산과 표시

## 데이터와 범위

`public/raid/master.json`은 `kr-2026-10-07` 로컬 데이터 기반의 19개 세트·93종 카드다.
버전은 성장 마스터와 공유한다. 실시간 게임 API나 파티 장착 상태를 조회하지 않는다.

- 딜러 7개: 세구빛·암구빛·화구빛·수구빛·토구빛·뇌구빛·알고 보면.
- 주요 서포터 7개: 남바절·암바절(신념의 길)·화바절·수바절·토바절·뇌바절·너계다.
- 대체 서포터 5개: 창의 달인·대사부 시험·루테란의 시련·에어가이츠 계획·하늘을 비추는 사막.
- 세우라제 등 조건부 조합, 방어·무력화·마나·공격력 효과는 피해 순위에 합산하지 않는다.

`scripts/build-raid-data.py`가 ignored `work/client-assets/db`의 SeasonCardBook,
SeasonCardEffect, GameMsg를 읽기 전용으로 연다. `BookType=2`의 구성 카드·단계·효과를
연결하고 성장 마스터의 카드 비용을 재사용한다. 소스 DB SHA-256과 stat enum 출처를 남긴다.
게임 원본 DB·폰트·원화는 이 마스터에 포함하지 않는다.

```sh
python -X utf8 scripts/build-growth-data.py
python -X utf8 scripts/build-raid-data.py
node --import tsx --test tests/raid.test.ts
```

일반 빌드와 CI에는 원본 DB가 필요 없다. 생성 시 선택 세트 누락, 중복 멤버/단계,
구성 수·각성 범위, 비용 데이터 연결을 검사한다. 게임 업데이트 후 재생성이 필요하다.

## 현재 각성과 성장

`raid-progress.ts`는 이름·각성을 확인한 카드 중 가장 높은 6장을 선택한다.
7종 세트도 각성 합계는 최대 30이다. 카드 추가 장수만 미확인이라면 현재 효과는 계산하고,
성장에는 확정된 장수만 사용한다. 중복 ID·이름/각성 오류는 미확인으로 남긴다.

성장 가능 각수는 현재 추가 장수로 올릴 수 있는 최대치다. 경험치 예산으로 자르지 않고
필요 경험치와 부족 여부를 별도로 표시한다. 다음 단계는 12·18·24·30각을 기준으로 한다.
`nextRaidPlan`은 6장 선택과 성장 단계를 DP로 탐색해 추가로 필요한 카드 수를 최소화하고,
동일하면 경험치가 적은 경로를 선택한다. 미등록 카드는 등록용 1장도 필요하다.
이름·각성이 미확인인 멤버는 선택에서 제외하되, 나머지 확정된 멤버만으로 구성이 가능하면
계획을 계산한다. 따라서 7종 중 선택하지 않을 1종이 미확인이라는 이유만으로 중단하지 않는다.
각성은 확인됐지만 추가 장수가 미확인인 카드는 현재 각성 그대로 참여할 수 있고,
그 카드의 추가 성장은 가정하지 않는다. 미확인 멤버가 남아 있으면 현재·성장 가능 각수는
확인된 카드 기준임을 표시한다. 새 판독 결과에 따라 더 좋은 구성이 생길 수 있다.

성장 추천은 효과가 생기는 단계까지만 계산한다. 예를 들어 최대 26각이 가능해도
24각 이후 효과가 없다면 24각까지만 추천한다. 부분 성장에 이미 투입한 경험치는 알 수 없어
남은 각성 단계의 경험치 전액을 계산한다. 각 세트는 독립 대안이며 여러 계획의 경험치를
동시에 차감하지 않는다. 레이드 화면은 조회·추천 전용이며 성장 완료 버튼은 도감작 기능이다.

## 피해 비교 모델

취약은 없음/10%/15%로 별도 선택한다. 딜러는 보스 취약 속성, 서포터는 파티 공격 속성을
선택한다. 무속성 스킬을 전제로 하며 고유 속성·별도 속성 보너스는 반영하지 않는다.

아래는 [실측 연구 글](https://www.inven.co.kr/board/lostark/4821/101866)에 근거한
**추정 모델**이다. 특히 취약과 속성 서포터 효과의 합산은 공식 확정 산식이 아니다.
클라이언트 마스터는 개별 효과 수치를 제공하지만 서버의 실제 피해 산식을 증명하지 않는다.

변수는 소수 비율이다. 예를 들어 15%는 0.15다.

- `D`: 딜러 카드의 누적 속성 피해 증가.
- `W`: 실제 공격 속성에 맞는 보스 취약. 속성이 다르거나 취약 없음이면 0.
- `S`: 속성 서포터 카드 효과, `G`: 너계다의 범용 효과.
- `A`: 카드 제외 기존 추가 피해, `C`: 알고 보면의 추가 피해.

딜러 속성 세트 + 속성 서포터:

```text
(1 + D) × (1 + W + S) - 1
세구빛 30 + 성 취약 10% + 남바절 30
= 1.15 × 1.135 - 1 = 30.525% (표시 30.53%)
```

범용 딜러 + 범용 서포터:

```text
(1 + C / (1 + A)) × (1 + G) - 1
```

딜러 순위는 각 세트에 가장 유리한 서포터 30각을 가정한다. 내 서포터 보유량은
사용하지 않는다. 세구빛에는 남바절, 암구빛에는 신념의 길 등이며 속성 전환 전에는
범용 세트만 적용한다. UI에 가정한 세트명을 표시한다. 수치는 무속성·양쪽 카드 미사용
기준 대비 취약과 두 카드 효과를 포함한 증가율이다. 실제 파티 전체 버프를 뜻하지 않는다.

서포터 순위는 이미 취약이 적용된 피해에서 해당 카드를 추가할 때의 실효 증가율이다.

```text
속성 서포터: S / (1 + W)
범용 서포터: G
남바절 3.5%, 취약 없음/10%/15% → 3.50% / 약 3.18% / 약 3.04%
```

UI의 큰 숫자는 서포터 카드 원래 효과이며, 실효율은 보조 문구로 표시한다.
대체 세트의 우열과 `%p` 차이는 반올림 전 실효율로 비교한다. 딜러와 서포터 화면의
분모가 다르므로 두 화면의 퍼센트를 직접 더하지 않는다.

## 화면과 모듈

- 선택한 속성 세트를 먼저 표시한다. 카드 부족·효과 미달성은 이유를 남긴다.
- 더 강한 대안이 있으면 가장 강한 대안과 동률 세트를 바로 표시한다. 같거나 약하면 숨긴다.
- 범용 카드는 목록과 대안에 유지하고 속성 선택에는 넣지 않는다.
- 목록/상세는 50:50, 좁은 화면은 세로 배치다. 긴 이름은 말줄임·전체 이름 툴팁을 사용한다.
- 비교 설정은 레이아웃을 밀지 않는 패널이며 바깥 클릭·Esc로 닫힌다.
- `raid-progress.ts`: 관측 검증·6장 구성·각성·성장 DP.
- `raid-ranking.ts`: 피해 산식·서포터 가정·추천 비교.
- `RaidCards.tsx`: 데이터 로드·선택·설정·목록. 전체 진행 계산을 한 번 만들어 공유한다.
- `RaidSetCard.tsx`: 선택한 세트 상세와 성장 카드.
- `RaidRecommendations.tsx`: 현재/성장 후 추천과 대안 표시.

회귀 검사는 구성 카드 부족, 미확인 필드, 등록·성장 비용, 7종 중 6장 선택,
선택하지 않은 7번째 카드의 미확인과 추가 장수 미확인 카드의 현재 각성 참여,
취약별 산식, 일반 추가 피해의 효율, 독립적인 서포터 가정, 효과 단계까지만 성장,
속성 우선 표시와 대체 세트 조건을 포함한다. 테스트 통과는 게임 산식의 실측 증명이 아니다.
