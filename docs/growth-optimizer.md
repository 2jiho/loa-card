# 도감 현황과 성장 계획

## 입력과 데이터

`도감작`은 현재 카드 목록과 스캔에서 읽은 경험치를 사용한다. 기본 선택은
힘/민첩/지능이며, 위쪽 수집 효과를 선택하면 해당 수집·성장 계획을 자동 계산한다.
CSV는 이름·각수·카드수만 담으므로 경험치가 없는 CSV 입력은 성장 탭 스캔이 필요하다.
실링은 무제한으로 취급하고 예상 소모량만 표시한다.

`public/growth/master.json`은 앱 카탈로그 420종, 도감 259개, 수집 효과 1,036개를 담는다.
버전 `kr-2026-10-07`은 마스터 생성일이다. SeasonCard/SeasonCardBook은
2026-10-03 로컬 추출본, SeasonCardEffect는 2026-10-07 같은 설치본의 데이터다.
소스 DB SHA-256을 기록하며, 이후 게임에서 추가된 데이터는 재생성이 필요하다.

`python scripts/build-growth-data.py`가 ignored `work/client-assets/db`를 읽기 전용으로
열어 마스터를 생성한다. 일반 빌드와 CI는 생성된 JSON을 사용한다. 원본 DB와
텍스처는 배포하지 않는다. PrimaryKey로 연결하고 이름·등급·최대 각성을 검증한다.
수동 카탈로그 ID 3종은 명시적인 ID 대응과 이름 검증을 거친다.

- `BookType=1`의 MemberCardId, CardCount, AwakeningLevelSum과 SeasonCardEffect를 연결한다.
- 피해량 효과 1단위는 0.01%p이며 단계별 효과를 누적 합산한다.
- 요구 카드 수가 멤버 수보다 작은 도감이 있어 원래 CardCount를 보존한다.
- 성장 비용은 단계 경험치 전액, 성장 실링(XP × 1.5), 별도 각성 실링을 합산한다.
  `SeasonCard.GrowthMoney`를 단계 전체 비용으로 사용하지 않는다.

## 현재 수집 효과

`currentBookProgress`는 확인된 카드의 각성·장수만 사용한다. 중복 ID, 판독 확인,
null, 범위 오류, countReliable=false는 확정 입력에서 제외한다. 미등록과 미판독을
구분하며 목록에 없는 카드를 현재 0각이라고 단정하지 않는다.

기본 능력치는 확인된 등록 카드 수가 요구량을 충족하면 합산한다. 각성 합을 알 수
없는 도감의 피해 효과는 확정하지 않는다. 미등록은 미완성으로, 실제 판독 오류만
확인 필요로 표시한다. 각 효과의 현재/최대 수치를 표시하며 최대 달성은 별도 표시한다.
힘·민첩·지능은 모든 관련 효과의 조건·수치가 같을 때만 묶고 수치를 세 배로 더하지 않는다.

삭제한 카드의 과거 달성 이력은 입력에 없어 게임의 영구 누적 도감 효과와 다를 수 있다.
이전 실제 387종 목록과 제공된 게임 화면을 대조했을 때 효과 441/1,036,
힘·민첩·지능 각 +209, 체력 +206, 인간 4.17%, 악마 3.16%가 일치했다.

## 피해량 성장 순서

`compareGrowthCandidates` → `growthSequence` → `collectionCandidates`가 현재 사용 경로다.
이전 예산/목표 모드 계산기와 별도 실행 계획 화면은 제거했다.

1. 각 도감의 다음 미달성 효과까지 필요한 각성 배분을 동적 계획법으로 생성한다.
   같은 각성 합에서 경험치가 적은 4개와 부족 장수가 적은 4개를 보존한다.
2. 선택 계열의 새 효과 / 이번 성장의 경험치로 순위를 정한다. 경험치가 0인 양의
   효과는 우선한다. 카드·경험치가 부족하다는 이유로 후보를 뒤로 옮기지 않는다.
3. 선택한 성장을 가상 상태에 적용하고 공유 카드가 만드는 효과를 모두 재계산한다.
   다음 효과만 비교하므로 중간 보상을 생략하지 않는다. 다른 도감의 중간 효과를
   여러 개 건너뛰는 공유 카드 배분도 제외한다.
4. 마지막 효과까지 반복한다. 상위 12개 같은 표시 제한은 없다. 앞 단계의 기여로
   다음 효율이 높아질 수 있어 표시 효율이 항상 내림차순인 것은 아니다.

순위용 가상 상태와 실제 자원 배분 상태는 분리한다. 실제 상태는 금색 단계만 실행하고
카드 부족/경험치 부족 단계는 건너뛰어 뒤 조합에 남은 자원을 사용한다.

- 금색: 앞 금색 단계를 실행한 뒤에도 현재 카드와 남은 경험치로 가능.
- 흰색: 카드가 충분하지만 남은 경험치 부족.
- 어둡게: 필요한 카드 부족. 목록 없는 카드는 최초 등록용 1장도 포함.

실제 실행 비용은 해당 도감의 목표 각성부터 다시 구한다. 앞에서 건너뛴 공유 카드
성장을 무료로 취급하지 않는다. 순위용 단계 비용과 실제 선행 성장 포함 비용이
다르면 둘을 구분한다. 경험치·장수는 각 단계에서 누적 차감하고 효과는 중복 합산하지 않는다.

이는 제한된 후보를 반복 비교하는 효율 추천이다. 전역 최소 경험치나 예산 내 최대
효과를 보장하지 않는다. 카드에 이미 투입한 부분 경험치와 카드 획득 비용은 반영하지 않는다.

전용 Web Worker에서 300ms 디바운스 후 계산한다. 입력 변경·탭 전환 시 타이머와
작업자를 종료하고 현재 카드/마스터/경험치/선택 효과에 일치하는 결과만 표시한다.
미확인 경험치는 계산하지 않으며, 0 경험치는 유효하다.

## 기본 능력치 수집

`statCollectionPlans`는 각성 대신 신규 등록 종수당 선택 능력치 증가량으로 정렬한다.
요구 종수만 충족하는 부분집합과 같은 카드로 열리는 다른 도감 효과를 함께 계산한다.
각 후보는 현재 목록에서 출발하는 독립 대안이므로 후보끼리 효과를 더하지 않는다.
효과당 최대 512개 부분집합을 비교하고 제한에 도달하면 알린다.
판독이 불확실한 카드가 들어간 도감은 제외한다.

## 성장 완료와 실행 취소

게임에서 성장한 뒤 첫 금색 단계의 `성장 완료`를 누르면 카드별 각성, 추가 장수,
보유 경험치를 한 번에 갱신하고 재계산한다. 아코디언을 열지 않아도 카드별 성장과
완료 버튼을 볼 수 있다. 뒤 금색 단계는 선행 성장을 가정하므로 먼저 완료할 수 없다.

`completeGrowth`가 현재 카드와 시작 각성, DB 비용, 보유 장수, 경험치를 재검증한다.
오래된 결과나 중복 적용을 거부하며 실패 시 일부 카드만 변경하지 않는다.
차감 경험치는 부분 투자량을 모르므로 예상으로 표시한다. 원래 카드 관측과 경험치를
브라우저 백업에 함께 저장하여 새로고침 후에도 순서대로 실행 취소할 수 있다.
새 스캔은 완료 이력과 예상 표시를 초기화하고 새 관측으로 값을 갱신한다.
게임 자체를 조작하는 기능은 아니다.

## 검증

- `growth-optimizer.test.ts`: 입력 신뢰 기준, 마스터 참조 무결성, 비용표, 현재 수집 효과.
- `growth-collection.test.ts`: 미등록 가정, 등록용 카드, 후보 비용, 예산과 무관한 순위.
- `growth-sequence.test.ts`: 중간 단계, 공유 카드, 부족 단계 건너뛰기, 선행 비용 복원.
  실제 420종 마스터의 12개 피해 계열에서 비용·장수·효과 보존과 최대 도달을 확인한다.
- `growth-completion.test.ts`: 완료/취소, 중복·오래된 입력 거부, 재스캔 갱신, 저장 후 취소.
- `stat-collection.test.ts`: 부분 수집 조건, 묶인 효과, 불확실 입력, 실제 마스터 최대 효과.

실제 게임 성장 후 재화 차감과의 대조는 별도 확인이 필요하다.

## 스캔 중 갱신

스캔 중에도 확인된 도감 효과와 계산 가능한 성장 단계를 표시한다. 전체 목록 확인 전에는 마스터의 미스캔 카드를 null/미확인 입력으로 채워 미등록 가정에 따른 구매 계획을 만들지 않는다. 재스캔은 기존 목록을 갱신하는 잠정 결과다. 성장 Worker는 한 번에 하나만 실행하며 작업 중 새 입력은 최신 한 건으로 대체한다. 연속 갱신 때문에 진행 중 계산을 계속 취소하지 않는다. 목표 변경·탭 이동 때는 취소하고 스캔 중 성장 완료 버튼은 비활성화한다.
