# 데이터와 모델 유지보수

## 일반 개발과 데이터 재생성의 경계

커밋된 `public/scanner`, `public/growth`, `public/raid`, 상인 JSON, `tests/fixtures`가 현재 실행과 회귀 테스트의 입력이다. 이 자료와 공개 npm/모델 배포처만으로 빌드한다.

다만 게임 원본 DB, 원화 원본, 개인 촬영 자료를 저장소에서 제공하지 않으므로 **원천 데이터까지 모두 재생성하는 저장소는 아니다**. 업데이트 시 공개 자료를 검증해 마스터를 수정하거나 적법하게 확보한 새로운 로컬 자료를 입력으로 생성한다. 개인 실험 폴더의 존재를 정상 빌드의 전제로 만들지 않는다.

| `artwork-details.json`, `screen-artwork-details.json` | 이름·장수·보석을 제외한 원화 특징. 같은 원화의 다른 카드 ID를 합치지 않는다. |

개수는 2026-10-08의 기준이며 하드코딩된 최신 게임 전체 수량으로 사용하지 않는다. 카드 420종과 도감 259개·효과 1,036개의 기준 버전/원본 해시는 JSON에 기록되어 있다.

## 카드 또는 판매 목록 변경

1. 게임 표기/공식 업데이트/출처의 이름·등급·성장 가능 여부를 대조한다. 새 외부 DB ID를 공식 API ID라고 표현하지 않는다. 확인되지 않은 ID는 기존 `catalog:` 내부 ID 체계를 따른다.
2. `cards.json`에 출처를 포함한 레코드를 추가하고 성장·도감·레이드·판매 마스터 참조를 연결한다. 이름만 같은 내부 변형을 자동 병합하지 않는다.
3. 그림 라벨은 이름과 별개 근거로 검증한다. 카드 파일명의 숫자와 atlas 순서를 연결하는 방법은 사용하지 않는다.
4. 인식 자료를 만든 입력과 별도의 실제 입력으로 이름·각성·장수를 검증한다. 출처·생성 조건·해시와 `public/scanner/NOTICE.txt`를 갱신한다.
5. `npm test`, lint, build를 실행한다. 카탈로그/성장/레이드/상인 참조 무결성 실패를 테스트 상수만 바꿔 숨기지 않는다.

카드 자료가 모두 있어도 새로운 이름·폰트·배율의 실제 스캔 지원은 별도 검증이 필요하다. 기존 테스트 fixture를 새 학습/보정 자료로 쓰면 더 이상 독립 정답 자료가 아니므로 새 holdout을 추가한다.

## 선택적 DB 내보내기

Python 3의 표준 라이브러리로 실행한다. 입력은 `work/client-assets/db/` 아래 `GameMsg.db`, `SeasonCard.db`, `SeasonCardBook.db`, `SeasonCardEffect.db`다. 각 DB에 같은 이름의 SQLite 테이블이 있어야 하며 스크립트는 `mode=ro`로 읽는다.

```sh
python -X utf8 scripts/build-growth-data.py
python -X utf8 scripts/build-raid-data.py
npm test
```

먼저 성장 마스터, 다음 레이드 마스터를 생성한다. 생성기는 PrimaryKey/SecondaryKey, 메시지 이름, 등급, 최대 각성, 도감 카드 수, 각성 합·효과, 비용을 검증한다. 클라이언트 Grade 1~5와 앱 rarity 0~4를 구분한다. `catalog:` 카드 대응은 생성기의 명시적 aliases에서 검증한다. 버전과 DB SHA-256을 갱신하고 게임 화면과 대조한다.

이 저장소는 게임 아카이브 추출기·복호화 키·원본 DB를 배포하지 않는다. 참고한 공개 형식 도구는 [lostark-explorer](https://github.com/Poyoanon/lostark-explorer)이며 초기 검토 리비전은 `dda4e63d50cb68dae71e224767e7e97a2fda6896`이다. 해당 도구와 현재 게임 형식의 호환성은 별도 확인한다. 원본 DB 없이도 현재 마스터를 검토·수정하고 테스트할 수 있다.

## 인식 자료 생성 도구의 범위

- `build-client-card-art.py`: `scripts/client-artwork-map.json`의 검토된 388개 좌표와 SHA-256으로 로컬 client atlas를 읽어 RGB/회색조 특징과 160×234 WebP 썸네일을 생성한다. Python의 OpenCV·NumPy·Pillow가 필요하다. 원본은 `work/client-assets/card-atlases/EFUI_ICONATLAS_C/Texture2D/`, DB는 앞서 설명한 로컬 디렉터리에서 읽는다. 420종 메타데이터를 DB와 대조하며, 매핑 없는 카드의 예전 특징/이미지는 유지하지 않는다. DB 또는 atlas 검증 실패 시 출력을 쓰기 전에 중단한다. 일반 build/dev는 생성물을 사용하므로 원본 게임 설치가 필요 없다.
- `prepare-screen-portraits.mjs <calibration.json>`: 검증된 records의 id/name/page/slot/alignment/portrait를 받아 보조 그림을 만든다. portrait는 정규화 24×32 중 x2/y9/20×10의 200바이트 회색조 base64다. page 1~10, slot 0~39, alignment ≥0.8과 중복을 검사한다. 기존 생성기는 입력 묶음 이름 `screenshots-1`을 기록하므로 새 입력의 출처 라벨도 함께 변경한다.
- `build-counter-patterns.py`: 과거 영상1 형식 `work/name-complete-video1.json`에 의존하는 실험 생성기다. 새 데이터로 쓰려면 rows(image data URL, values[이름,각성,장수], source, review)의 입력 형식과 독립 수동 라벨을 먼저 준비하고 고정 파일명/출처를 수정한다. 일반 설치 명령이 아니다.
- `prepare-*-probes.*` 등은 선택적인 입력 검증 도구다. 일반 빌드나 이름 OCR의 필수 생성 단계로 실행하지 않는다. 현재 판독과 연결되지 않는 옛 이름/장수 사전 생성기와 클라이언트 원화·폰트·UI·보석 비교 실험 도구는 제거했다.

`stars.json`은 현재 판독하는 회색·금색 표본 각 1개만 보관한다. 숫자 회귀 검사도 배포되는 `counter-patterns.json`을 읽으며 별도 중복 atlas를 만들지 않는다. 미사용 ORB·옛 숫자/헤더 atlas와 그 데이터 자체를 검사하던 테스트는 제거했다. 실제 정상/가림/이동/저대비 표본은 해당 회귀를 대체할 근거 없이 합성 그림만으로 교체하지 않는다. CSV는 실제 캡처를 포함하지 않으므로 불러온 카드의 `image`는 빈 값이다.

이름 가림 검사의 `tests/fixtures/name-visibility-samples.json`에는 실제 이름 형태 36개만 남긴다. 등급별 글자 폭·높이·픽셀 수·밀도의 최솟값/최댓값으로 고른 29개와 별도 크롭 7개다. 동률은 ID로 결정하며 판독 성공 여부로 선별하지 않았다. 각 표본의 출처와 선정 이유를 보존한다. 이 fixture는 이름 식별 사전이 아니라 저대비·배율·위치 변화의 가시성 검사 입력이다. 36개 회귀 통과가 전체 카드의 식별 정확도를 보장하지 않는다.

## 클라이언트 원화 대체 검토 (2026-10-08)

로컬 원화 조각 542개와 기존 외부 기준 그림 417개를 비교했다. 상관도 ≥0.99, 차순위 격차 ≥0.05, 평균 RGB 오차 ≤5 조건을 모두 만족한 388종을 별도 후보로 생성했다. DB의 이름·등급과 원본 atlas의 실제 크롭 바이트도 대조했다. 이 연결은 **기존 외부 기준 그림에서 이름을 전달한 시각적 대응**이며 DB가 제공하는 공식 UV 대응표가 아니다. 파일명 뒤 숫자를 atlas 좌표로 해석한 과거 연결은 잘못되어 사용하지 않는다.

후보를 별도 작업 디렉터리에서 검사해 테스트 371개가 통과했다. 두 스크린샷 묶음(각 400칸)의 원화 판독 비교에서 화면 보정 자료를 함께 사용하면 기존 판독 수 307/376을 유지하고 새 오인식은 없었다. 원화만 사용하면 첫 묶음은 185→186, 두 번째는 320→319였으며 후자의 ‘조롱하는 쿠크’가 미판독으로 바뀌었다. 이는 카드 전체 수집률이나 OCR까지 포함한 실시간 성적이 아니다.

동일 스캐너 코드에서 기존/후보 각각 빈 목록으로 영상 6개와 사진 10장씩 두 묶음을 끝까지 검사했다. 최종 카드 ID·이름·각성·추가 장수·확인 필요 항목과 경험치가 모두 같았다. 영상 1/2/4/6과 사진 두 묶음은 384/384종, 영상 5는 385/385종이었다. 영상 3은 양쪽 모두 ‘하이비 집행관’ 1종이 빠진 383/384종으로, 전체 입력 통과로 보고하지 않는다. 수집된 카드의 확인 필요는 모두 0건이었다.

영상 1의 수동 정답 11종과 추가 장수 표본 37개, 사진 첫 묶음의 수동 정답 5종도 통과했다. 이는 전체 카드 필드의 독립 정답 검증이 아니다. 이 검사는 브라우저의 오프라인 영상 디코딩/사진 입력으로 실행했으며 실제 OS 화면 공유는 검사하지 않았다. 단일 순차 실행 시간에는 차이가 있어 속도 동등성이나 개선을 결론내리지 않는다. 재현 시 두 데이터 구성을 분리하고 입력 해시·실행 순서·빈 초기 목록을 기록한 뒤 `verify-scan.mjs`와 `verify-screenshot-scan.mjs`로 해당 수동 표본을 대조한다.

위 비교는 388종만 바꾸고 나머지 외부 원화를 유지한 중간 후보의 결과다. 이후 클라이언트 전용 구성으로 전환해 388종의 특징·썸네일만 배포하고 나머지 32종의 기존 외부 원화 특징을 제거했다. 게임 화면 보조 자료가 있는 28종은 이를 사용한다. 찢겨진 발탄·아슈타로테·악몽의 게헤나·죽음의 계율자, 벨가르딘 4종은 이름 OCR만 지원하며, 이 4종의 실제 화면 판독은 별도 검증이 필요하다. 미등록 목록에는 검증된 388종의 클라이언트 썸네일만 표시하고 나머지는 이미지 없음 표시를 사용한다. 카드 이름·등급·성장 가능 여부 420종을 클라이언트 DB와 대조했으며 기존 앱 ID는 유지한다. 후보 생성에 사용한 기준 그림을 독립 검증 표본으로 다시 세지 않는다. 로컬 후보·비교 보고서는 `work/client-assets/replacement/`에만 있으며 일반 개발·빌드의 필수 입력이 아니다.

클라이언트 전용 최종 구성은 영상 5(385/385종)와 사진 두 묶음(각 384/384종)을 빈 목록으로 재검사했다. 기존 결과와 카드 ID·이름·각성·장수·확인 필요·경험치 차이는 없었다. 사진 첫 묶음 수동 필드 5종도 통과했다. 테스트 372개, lint, 일반/Pages 하위 경로 빌드와 미등록 원화의 밝은/어두운/좁은 화면 표시를 확인했다. 앞서 비교한 전체 영상 6개 결과를 최종 구성의 전수 재검사 결과로 재사용하지 않는다.

이후 2026-10-08 사용자가 실제 게임 화면 공유로 정상 동작을 확인했다고 보고했다. 이 확인에는 별도의 처리 시간·누락 수·전체 필드 정답 측정값이 없으므로 정량 성능이나 전체 420종 검증으로 집계하지 않는다. OCR 전용 4종의 실제 화면 판독 검증은 남아 있다.

## OCR 모델과 외부 코드

`public/ocr/opencv.js`는 npm lockfile로 설치한 `@techstark/opencv-js`에서 복사하는 생성물이다. 저장소에 실행 파일을 중복 보관하지 않는다. 준비 단계와 라이선스 생성기가 `licenses/third-party/manifest.json`의 SHA-256 및 패키지 버전을 검사한다. 런타임과 관련 고지를 함께 갱신한다.

`tests/fixtures/observation-plans.json`은 합성 입력의 seed·크기와 기존 예상 픽셀의 SHA-256을 보관한다. 45개 사례의 전체 출력 바이트를 검증하며 실제 게임 픽셀은 포함하지 않는다. 회귀 실패 시 현재 구현 결과로 예상 해시를 자동 갱신하지 않는다.

`scripts/prepare-ocr-assets.mjs`가 공개 배포처의 리비전·모델 SHA-256·문자 사전 해시를 고정한다. 모델과 문자 사전은 함께 바꾼다. 해시 오류를 우회하거나 런타임 외부 API로 자동 전환하지 않는다. `public/ocr`는 생성물이다.

의존성 변경은 `package-lock.json`과 `npm run notices` 결과를 검토한다. Mediabunny 소스와 라이선스는 실제 설치 버전에서 함께 배포한다. [외부 자산 고지](../THIRD_PARTY_NOTICES.md)의 예외·미확인 사항도 확인한다.

사전 빌드된 워커/WASM의 추가 원문은 `licenses/third-party/manifest.json`으로 관리한다. 패키지 버전이나 해당 소스를 갱신하면 상위 저장소의 실제 사용 리비전과 고지를 다시 확인하고 해시도 갱신한다. 검사를 통과시키기 위해 내용 확인 없이 버전/해시만 바꾸지 않는다. `npm run audit:distribution`은 웹 번들·Worker·주요 사전 빌드 source map에 원문 누락 패키지가 포함되는지 확인하고 `work/legal-review/bundle-audit.json`을 만든다. 게임 자료의 권리나 모든 WASM 내부 코드의 구성은 이 명령으로 증명하지 않는다.

## 갱신 검토 기록

`data-review.json`은 검토 날짜와 런타임 마스터·수동 관측 근거의 JSON 내용 SHA-256을 고정한다. Git 줄바꿈 변환에 영향받지 않도록 JSON을 파싱한 후 직렬화한 문자열을 해싱한다. `npm run audit:data`와 prebuild가 변경 누락, 카드 이름·등급·도감·레이드·상인 참조를 검사한다. 데이터 수정 시 원본 출처/버전/검증 결과를 먼저 검토하고 이 파일의 날짜·해시를 함께 갱신한다. 해시만 갱신하는 것으로 게임 적용 여부 검증을 대체하지 않는다.

`work/data-audit.json`에는 개별 출시 근거가 아직 문서화되지 않은 카드가 남는다. `--require-release-evidence`는 전수 근거가 없으면 실패한다. 현재 커밋된 수동 게임 관측 라벨은 6종이다. 다른 카드의 출시 근거가 이 보고서에 없다는 뜻이며 나머지 카드가 미출시라는 뜻이 아니다. 이미지 매칭 수, 스캔 수량, 클라이언트 DB 수량을 출시 여부의 전수 검증으로 보고하지 않는다. 앱에는 카탈로그 기준 날짜를 표시하며 자동 최신 동기화를 주장하지 않는다.
