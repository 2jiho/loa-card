# 설계 결정과 알려진 한계

## 유지하는 선택

| 선택 | 이유 / 변경할 때 필요한 근거 |
|---|---|
| 브라우저 정적 앱 | 화면 외부 전송 없이 Pages에서 실행. OCR용 서버나 비밀 키를 전제하지 않는다. |
| 개별 카드 획득 | 40칸 전체 정지 대기는 빠른 스크롤에서 정상 카드까지 놓친다. 각 카드의 네 변과 필드를 검사한다. |
| 이름 OCR + DB | 글자 템플릿은 배율·압축·색상·다른 이름에 취약했다. 기존 이름 템플릿은 회귀 입력으로만 남는다. |
| 그림은 독립 보조 근거 | 같은 그림을 공유하는 카드가 있어 최고 점수 하나만으로 ID를 확정할 수 없다. |
| 장수 1~15 전체 패턴 | 고정 숫자 형태를 빠르게 비교하되 후보 격차, 각성 상한, 반복/OCR 근거를 함께 검사한다. |
| 0장 별도 처리 | 0은 게임에서 숫자·아이콘이 없다. OCR 실패와 명시적 표시 부재를 구별해야 한다. |
| 획득과 판독 Worker 분리 | 긴 OCR 재시도가 새 화면 획득을 막지 않게 한다. 캐시와 중복 제거도 이름·숫자·보석 변화는 보존한다. |
| 원본 보완은 RGBA 직접 전달 | 일반 판독에서 PNG 압축→base64→재디코드를 반복하지 않는다. 명시적 진단 내보내기에만 압축을 사용한다. |
| 공유 종료 / 검증 완료 분리 | 카드 화면을 확보한 뒤 장수 재시도 때문에 계속 공유할 필요가 없다. 전체 검증 없는 보완 생략은 금지한다. |
| 로컬 성장 완료 + 취소 | 실제 게임 조작이나 계정 조회 없이 사용자가 실행한 성장을 예상 목록에 반영한다. |

클라이언트 카드 그림 파일명의 숫자를 atlas 좌표로 간주한 방법은 잘못된 매핑을 만들었다. 다시 사용하지 않는다. 원화 라벨은 독립 검증이 필요하다. 클라이언트 보석/테두리 sprite를 단순 축소한 템플릿도 기존 방식보다 안정적이지 않아 운영 판독기로 채택하지 않았다.

## 한계

- 카탈로그 420종에 참고 자료가 있지만 420종 전체의 실제 화면·해상도·배율·압축을 수동 검증한 것은 아니다. 게임 업데이트를 자동 동기화하지 않는다.
- 툴팁으로 가린 필드를 복원하지 않는다. 네 변이 보여도 내부가 가릴 수 있다. 단색 이름 가림은 빠르게 제외하지만 글자가 있는 툴팁과 부분 가림은 미확정으로 남거나 재시도할 수 있다.
- 빠른 스크롤에서 입력 자체가 놓친 프레임은 알고리즘만으로 복원할 수 없다. 기록·메모리 한도, 저사양 장치, 백그라운드 탭에 따라 처리량이 다르다.
- 이미지 관측 묶음 수는 고유 카드 수가 아니다. 보관함 수량 일치도 각성/장수 정답의 증명은 아니다.
- 모든 정렬의 완전한 카드 위치 지도를 사용하지 않는다. 같은 슬롯이나 대략 비슷한 원화로 미확정 관측을 없애지 않는다.
- 부분 투자 경험치, 삭제한 카드의 과거 영구 도감 달성 이력, 실제 파티 장착 상태는 입력에 없다.
- 도감 성장 추천은 제한된 후보의 순차 효율 비교이며 전역 최적해 보장이 아니다. 레이드 피해 산식 일부는 실측 자료에 근거한 추정이다.
- 계정 프로필 전환은 없다. CSV는 경험치와 사진을 보존하지 않는다. 브라우저 저장소만을 영구 백업으로 취급하지 않는다.

## 과거 검증에서 남길 사실

2026-10-05 당시 전체 입력 검사에서 영상 1/2/4는 384/384종, 영상 5는 385/385종이었다. 영상 3은 툴팁으로 가린 하이비 집행관 때문에 383/384종으로 남겼다. 그림 보정에 사용한 사진 묶음 1과 별도 검증인 묶음 2를 구분했다. 당시 수량·기존 결과와의 일관성 검사이며 최신 코드의 전수 정답 증거가 아니다.

2026-10-08 단색 이름 가림 검사는 기존 사진 20장의 800칸 중 사용 가능했던 768크롭을 유지하고, 합성 단색 가림 768개를 제외했다. 저대비 이름 변형 3,420개를 보존했다. 글자가 있는 툴팁이나 모든 카드 인식 성적을 뜻하지 않는다. 원본 자료는 개인 화면을 포함해 배포하지 않으며 이후 검증은 공개된 개발 입력 화면과 새 독립 자료로 수행한다.

과거 숫자·가림·같은 그림·경계 문제의 최소 회귀는 `tests/fixtures/`와 관련 테스트에 남긴다. 검증 절차는 [개발 문서](development.md)를 따른다.
