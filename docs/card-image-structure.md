# 카드 이미지 구조

140×210 카드 크롭의 픽셀 구조와 그 근거를 정리한다. 인식 결과나 정답률이 아니다. 좌표는 카드 크롭 기준(140×210, 왼쪽 위 원점, 폭×높이)이고, 2560×1440·UI 100%에서 잰 값이다. 다른 배율에서는 같은 비율로 그려진다고 보고 크롭을 140×210으로 맞춘다.

측정에 쓴 크롭·기록·작업 파일은 비공개(`work/`, `fixtures/local/`)이며, 날짜별 측정 메모는 그 옆의 `fixtures/local/notes/`에 둔다. 이 문서에는 지금 코드가 따르는 구조와 다시 재는 방법만 남긴다.

## 요소의 의미 (사용자 확인)

- **청록 카드 `+N`**: 카드수(등록 1장과 각성 소모분을 제외한 추가 장수). CSV의 `카드수`와 같다.
- **각성 보석 5칸**: 금색 = 각성 수, 회색 = 5 − 각성 수. 금색 보석(채워진 육각)과 회색 보석(속이 빈 육각)은 모양 자체가 다르다.
- **왼쪽 아래 금색/회색 아이콘**: 즐겨찾기 버튼이다. 장수 값이 아니며 판독 근거로 쓰지 않는다.
- 이름은 한 줄이 아닐 수 있다(예: `도철을 다루는 웨이`).

## 판독 영역 (지금 코드)

| 영역 | 코드의 상자 | 비고 |
|---|---|---|
| 이름 | `(6,14,128,36)` | 좌측 테두리와 겹칠 수 있고, 긴 이름은 상자 경계에 닿는다. 좌우 제외·아래로 옮기는 안은 빈 이름 카드(음성 표본) 검증 전에는 적용하지 않는다. |
| 장수 아이콘 + 숫자 | `(56,141,82,31)` | 0/양수 판정은 `+N` 글리프와 아이콘 부재 증거로만 한다. |
| `+N` 글리프 | `(89,143,50,22)` | 바깥 여유는 `matchCountPattern`의 위치 탐색 여유다. 글자 범위에 맞춰 줄이지 않는다. |
| 각성 보석 | y 172부터 31px 띠에서 슬롯별 위치 탐색(`recognition/star-pattern.ts`) | 하단 고정 상자 `(14,176,112,24)`는 판독이 아니라 관측 식별 키용이다(`acquisition/field-pixel-regions.ts`, `acquisition/observation-pixels.ts`). |

형태 템플릿은 에셋 기반이다: 보석 `stars.json`, 숫자 `counter-patterns.json`, 창 검출 앵커 `header-anchor.png`·`growth-tab.png`. 위치 기하만 고정 오프셋이다.

## 고정 요소의 위치

크롭을 등급별 클라이언트 테두리에 맞춰 겹쳐 쌓고, 상태가 다른 카드 묶음의 평균 차이로 잰 범위다(아래 "카드 배치도"). 상자는 평균 차이의 30% 이상인 픽셀 범위라 경계가 1~2px 흔들릴 수 있고, 옅은 빛 번짐의 끝은 포함하지 않는다.

| 요소 | 위치 | 비고 |
|---|---|---|
| 즐겨찾기 버튼 | (4,136) 32×33 | 주변 광채 포함 |
| 장수 아이콘 + 숫자 | (61,138) 69×34 | 아이콘 x 61~108, 숫자 x 111~130 |
| 각성 보석 5칸 | x 24/45/65/86/106, y 170, 각 15×26 | 광채 포함. 보석 몸통은 15×20(y 176부터) |
| 장착중 배너 | y 101~137, 폭 전체 | "장착중" 글자는 y 109~127 |
| 이름 글자 | y 약 15~30 (한 줄 이름) | |

- 즐겨찾기 버튼과 각성 보석 뒤에는 빛 번짐이, 장수 아이콘 뒤에는 어두운 받침이 깔린다. 원화 대조에서 이 요소를 가린다면 아이콘 윤곽이 아니라 번짐 범위까지, 상태(금색/회색, 켜짐/꺼짐)별로 따로 재야 한다.
- 가릴 자리는 카드 후보와 무관하게 UI 상태(장착 여부, 장수 표시 여부)로만 정한다. 1등 후보에 맞춰 픽셀을 빼지 않는다.
- 이름 판과 하단 판은 클라이언트 아틀라스에서 위·아래가 어둡고 가운데가 투명한 그라디언트 한 장일 가능성이 높다([클라이언트 카드 렌더](client-card-rendering.md)).

## 격자 간격

카드 창의 10×4 격자 간격은 **열 472/3 ≈ 157.33px, 줄 728/3 ≈ 242.67px**(2560×1440)이다. UI가 1080p 기준으로 설계되어 1440p에서 4/3배로 그려지기 때문으로 보인다(열 118, 줄 182). `acquisition/layout-geometry.ts`의 `DEFAULT_LAYOUT`이 이 값을 쓴다.

- 줄 시작(`gridY`)은 그대로 두고 간격만 728/3으로 했다. 위쪽 두 줄을 내리는 안과 줄 사이 상대 위치는 같지만, 칸별 세로 정렬(`alignCardBorders`)이 받아들이던 위쪽 두 줄의 자리를 건드리지 않는다.
- 격자가 정수 좌표라 열·줄에 따라 최대 약 0.5px의 위상 차이가 남는다. 없애려면 소수 좌표로 다시 샘플링해 잘라야 한다.
- 격자 값을 바꿀 때는 비공개 화면 공유 기록 재실행으로 카드 목록·각성·장수·확정 수가 기준 실행과 같은지 확인한다. 간격과 원점을 함께 바꾸면 칸별 세로 정렬이 새로 발동해 결과가 달라질 수 있다.

## 측정 도구

- `dev/card-structure.html`: 크롭에 고정 마스크를 겹쳐 그린다(3배 확대, 10px 격자). 값을 판정하지 않는다.
- **카드 배치도** `dev/card-map.ts`(재실행 방식 `cardmap`, `node scripts/run-recording-replay.mjs --id <id> --mode cardmap`): 기록에서 스크롤 위치마다 한 프레임씩 크롭을 모아, 그 등급의 클라이언트 테두리(비공개 추출본)에 ±3px 안에서 가장 잘 맞는 자리로 옮겨 겹쳐 쌓는다. 고정 요소는 평균에서 선명하게 남고 원화는 뭉개진다. 산출물은 `work/card-map/`. 장착·즐겨찾기 분류는 밝기·색으로 나눈 것이며 사람이 확인한 분류가 아니다.
- **격자 맞춤** `dev/grid-fit.ts`(방식 `gridfit`, 계산 `dev/grid-fit-math.ts`, 테스트 `tests/grid-fit-math.test.ts`): 테두리 추출본의 바깥 윤곽을 칸마다 ±4px에서 옮겨 가며 "안쪽이 바로 바깥보다 밝은 정도"를 더하고(점마다 상한), 최대 자리를 포물선 보간해 소수 위치를 얻은 뒤 한 프레임의 칸 전부로 격자(첫 열, 열 간격, 첫 줄, 줄 간격)를 최소제곱으로 맞춘다. 색은 쓰지 않는다. 윤곽의 안팎 가장자리를 모두 쓰면 좌우 변의 두 선 때문에 가로가 2px 단위로 엇갈리므로 바깥 윤곽만 쓴다. 원점의 절대값은 추출본 캔버스 기준이라 판독 좌표계와 상수만큼 다를 수 있다. 스캐너가 아니다.

## 클라이언트 UI 에셋

- 등급 테두리 5종은 `scripts/build-composed-card-templates.py --borders-only`로 클라이언트 UI PNG에서 뽑는다(해시는 `scripts/client-card-ui-map.json`). 추출 전에 `verify_border_boxes()`가 상자마다 투명한 프레임 내부가 정확히 하나이고 두께가 좌우 2~3px·위 10px·아래 7px 범위인지 확인하고, 어긋나면 중단한다. 아틀라스에서 프레임이 맞닿아 있어 색·알파 기준 자동 분리는 이웃으로 번지므로, 상자는 보정값을 두고 이 검사로 고정한다. 결과는 `work/` 아래에만 두며 게임 폴더는 읽기만 한다.
- 등급별 추출본끼리 가로로 약 1px 어긋나 있어, 이 추출본만으로 가로 원점을 1px 안쪽으로 확정할 수 없다. 화면에 그려진 테두리와 추출본은 색도 달라 색 대조의 구분력이 약하다. 원점은 윤곽 기준 비교나 다른 고정 요소(보석 자리, 즐겨찾기 버튼)와 함께 맞춘다.
- 스캐너의 `stars.json`(10×17)은 클라이언트 보석 스프라이트와 배율이 다르다. 클라이언트에서 뽑은 강조·빈 칸·배너·판·보석 스프라이트는 표시·대조용이며 판독 경로를 바꾸지 않는다.
- 클라이언트에는 UI 크기 조절이 있어 같은 카드도 설정에 따라 다른 픽셀 크기로 그려진다. 140×210 픽셀 일치는 한 설정에서만 성립하므로 검증 기준은 비례 정렬이다.

## 아직 모르는 것

- 이름 상자의 좌우 테두리 제외: 빈 이름 카드에서 금색 테두리만으로 이름 픽셀 게이트를 넘는지 확인하지 않았다.
- 보석 금색·회색 개수가 항상 `gold + gray = 5`인지, 이름 색 마스크가 장착·호버 상태에서도 같은지.
- 반투명 판의 범위, 두 줄 이름, 선택·호버 상태의 광채, 아틀라스의 즐겨찾기·장수 아이콘 원본과의 대조.
- 다른 해상도·UI 배율·창 위치에서의 격자 원점.
