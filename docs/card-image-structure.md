# 카드 이미지 구조 감사

이 문서는 인식 결과가 아니라 **140×210 카드 크롭의 실제 픽셀 구조**를 확인한 기록이다. video-7 필드 검토 크롭 4장에 고정 마스크를 겹쳐 그린 `work/card-structure/*-structure.png`를 근거로 사용했다.

## 확인 방법

- 입력: `work/video7-field-review/3201009-gusto.jpg`, `3201018-way.jpg`, `3201013-nina.jpg`, `3200813-beskal.jpg`
- 오버레이: `dev/card-structure.html` → `work/card-structure/*-structure.png`
- 카드 원본 크기: 140×210, 10px 격자, 3배 확대
- 이 감사는 카드 ID·각성·장수 값을 판정하지 않는다.

## 관찰된 구조

| 영역 | 현재 고정 마스크 | 실제 관찰 | 상태 |
|---|---|---|---|
| 외곽 등급 테두리 | 없음 | x≈2–8, y≈2–8, 카드 전체 테두리 | 구조만 확인 |
| 이름 | `(6,14,128,36)` | 이름 텍스트는 x≈16–128, y≈16–50. 좌측 테두리가 포함됨. 후보: 좌우 4px 제외 | **미적용 · 구조 정의 필요** |
| 원화 | 없음 | y≈50–140 | 구조만 확인 |
| 기본 카드 아이콘 | 없음 | x≈34–60, y≈145–165. 금색/회색 카드 모양 | 의미 확인 필요 |
| 추가 장수 클러스터 | `(56,141,82,31)` | 청록 카드 + `+N`은 x≈64–130, y≈143–165. 마스크가 기본 아이콘 오른쪽 일부를 포함 | 대체로 일치 |
| `+N` 글리프 | `(89,143,50,22)` | `+N`은 x≈95–132, y≈145–162 | 대체로 일치 |
| 각성 보석 | `(14,176,112,24)` + 별도 template search | 보석 5칸은 x≈28–126, y≈180–202. 후보: 하단 28px 확장 | **미적용 · 구조 정의 필요** |

## 중요한 발견

1. **이름 크롭은 테두리를 포함한다.**
   - `x=6` 크롭은 카드 좌측 테두리와 겹친다.
   - 좌우 4px을 `nameMask`/`hasNamePixels`에서 제외하는 후보를 검토 중이며, **아직 코드에 적용하지 않았다.**
   - 이름 색상 마스크가 등급별 금색/보라/파랑/초록/회색을 선택하므로, 실제 이름이 없는 카드에서 테두리만으로 35px 게이트를 넘지 않는지 사람 라벨로 확인해야 한다.

2. **장수 마스크는 기본 카드 아이콘을 판독에 사용하지 않는다.**
   - 사용자 확인 완료: CSV `카드수` = 등록 1장·각성 소모분 제외 추가 장수, 청록 카드 `+N` = 카드수.
   - 금색/회색 기본 카드 모양(x≈34–60, y≈145–165)은 장수 값이 아니므로 `+N` 판독 근거로 쓰지 않는다.
   - `(56,141,82,31)` 마스크가 기본 아이콘 오른쪽 일부를 포함하는 것은 구조상 여유이며, 0/양수 판정은 `+N` 글리프·아이콘 부재 증거로만 한다.

3. **각성 보석은 고정 사각형이 아니라 template search로 찾는다.**
   - `star-pattern.ts`는 y=172부터 31px 밴드를 검색하고, 슬롯별로 x·y 오프셋을 찾는다.
   - `bottom (14,176,112,24)`는 보조 영역이며, 실제 보석은 y≈202까지 내려갈 수 있다. 28px 확장 후보는 아직 적용하지 않았다.
   - 고정 박스만으로 보석을 잘라내면 각성 판독이 흔들릴 수 있다.

4. **이름은 한 줄이 아니다.**
   - `도철을 다루는 웨이`처럼 두 줄로 나뉘는 이름이 있다.
   - `(6,14,128,36)` 박스가 두 번째 줄을 충분히 포함하는지 카드별로 확인해야 한다.

5. **등급·장착 배너·호버 효과가 같은 영역을 덮을 수 있다.**
   - 장착 배너는 원화 매칭의 `above-badge` 고정 영역으로 가리지만, 이름·각성 영역과 겹치는지 별도 확인이 필요하다.

## 의미 확인 (사용자 확인 완료)

- **CSV `카드수`**: 등록 1장과 각성 소모분을 제외한 추가 장수.
- **각성 보석 5칸**: 금색 = 각성 수, 회색 = 5 - 각성 수.
- **청록 카드 `+N`**: 카드수(추가 장수).

이 확인으로 “금색/회색 기본 아이콘”과 “각성 보석”을 혼동하지 않도록 문서를 분리한다. 장수는 청록 카드 `+N`으로 읽고, 기본 카드 아이콘 색은 장수 판독에 사용하지 않는다.

## 아직 모르는 것

- 5각 0장, 성장 불가 카드 예외, 각성별 최대 장수 공식의 전체 카드 적용.
- 보석 5칸의 금색/회색 개수가 실제 각성 수와 항상 `gold + gray = 5`를 만족하는지.
- 이름 색상 마스크가 등급뿐 아니라 장착·호버 상태에서도 같은지.

## 에셋으로 마스크를 잡는 방향 (2026-11-05, 실측 후 정정)

처음에는 `public/scanner/artwork/*.webp` 420장만 보고 "에셋에 프레임 UI가 없다"고 기각했다. 사용자 지적 후 전체를 확인한 결과, 그 기각은 성급했다.

실제 에셋 구성:

- `artwork/` 420장: 160×234 초상화만. 테두리·이름·보석·카운터 없음 (`work/cdp-asset-probe.mjs`, `work/asset-probe.json`). 신원용으로만 유효.
- `stars.json`: 회색/금색 보석 10×17 템플릿. 이미 `readStarObservation`이 형태 매칭에 사용 중. **위치는 여전히 수동**(슬롯 x·y172 밴드 탐색).
- `counter-patterns.json`: 1~15 숫자 글리프 템플릿. 이미 `matchCountPattern`이 형태 매칭에 사용 중. **위치는 여전히 수동** `(89,143,50,22)`.
- `header-anchor.png`(138×24), `growth-tab.png`(256×48): 창 검출용 UI 앵커. 이미 검출에 사용 중.
- **없는 것**: 이름 밴드 배경, 청록 추가 카드 아이콘, 빈 카운터 배경의 템플릿. 등급 테두리는 2026-11-05 클라이언트 원본으로 복원됨 (`work/composed-card-templates/borders/border-{0..4}.png`, 해시 대조됨, work 한정).

즉 형태 템플릿은 이미 에셋 기반이고, 수동인 건 **위치 기하**뿐이다. 사용자 제안(게임상 모든 이미지의 에셋화 + 패턴매칭 위치 결정)은 방향으로 맞다. 다만 순서가 있다:

1. 부족한 UI 템플릿을 실제 게임 캡처에서 잘라 에셋으로 등록 (출처·해상도·버전 명시).
2. 고정 좌표와 템플릿 검출 위치를 라벨 크롭에서 대조 검증.
3. 검출이 고정이와 동등 이상일 때만 전환. 그 전까지 고정 좌표 유지.

이 순서 전에는 위치 결정을 바꾸지 않는다.

## 기준점 고정 방향 (2026-11-05, 사용자 확인)

런타임에 패턴매칭을 돌려 매번 위치를 찾는 게 아니다. 에셋(등급 테두리·앵커 등)을 **좌표계 기준점**으로 써서 카드 프레임의 원점·스케일을 정확히 고정하고, 이름·보석·장수 같은 상대 위치는 게임 UI 설계상 고정 오프셋으로 읽는다.

- 절대 위치(어디에 있나): 에셋 기준점으로 검출·보정.
- 상대 기하(프레임 안에서 어디인가): 고정 오프셋. 이 값의 검증은 실측(`work/mask-measure.json`)과 사람 라벨로 한다.
- 이렇게 하면 해상도·배율이 바뀌어도 기준점부터 다시 고정하면 되고, 프레임별 검출 노이즈는 상대 위치에 타지 않는다.
- 전제 조건은 같다: UI 템플릿의 에셋 등록(출처·해상도·버전 명시)과 라벨 크롭 대조가 먼저다.

- 아이콘 박스 상단(y=141): 아이콘이 상단에 닿는 카드 7장 이상. 상단 여유 0.
- 글리프 박스: 전부 안쪽에 들어감. 다만 하단 여유 0인 카드 다수.

- 예외: 3200003(국왕 실리안)은 상하 어두운 테두리 픽셀이 거의 없음(밝은 풀블리드 원화). 테두리 검출의 별도 케이스로 기록만 한다.

결론: 마스크가 틀린 게 아니라 여유가 없다. 좌우 4px 제외·아이콘 상단 여유 후보는 라벨 대조 테스트로 검증할 단계가 됐다(라벨 56종 확보됨).

1. 이름 테두리 제외 후보를 실제 이름·빈 이름 카드로 검증하고, 검증 전에는 코드에 적용하지 않는다.
2. 사람이 직접 확인한 카드 30~50장으로 이름·각성·장수 라벨을 만든다.
3. 각성 보석 검색 밴드·슬롯 중심을 실제 검출 좌표로 보정한다.
4. 청록 카드 `+N`과 각성 금색/회색 5칸을 실제 카드에서 대조한다.
5. 위 구조 검증 전에는 새로운 임계값·휴리스틱을 추가하지 않는다.
