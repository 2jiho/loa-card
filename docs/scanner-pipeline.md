# 스캐너 파이프라인

> **v0.3.0 이전 구조.** 이 문서는 이전 프레임 단위 스캐너 루프(`runScannerInternal`)의 큐·병렬 판독·보완 구조를 설명한다. 그 루프와 앱의 "스캔 진단"(진단 기록·입력 재현)은 v0.3.0에서 제거됐고, 화면 공유는 줄 중심 스캔(`orchestration/row-scan.ts`, `row-scanner.ts`)으로 읽는다. 공통 원칙(획득·판독·병합의 분리, 최신 캡처 기준, null과 0의 구분)은 그대로이며, 현재 경로의 동작·측정은 [화면 공유 기록](dev-recording.md)과 [개발과 검증](development.md)을 따른다.

카드 OCR 작업자 풀이 이전 세대의 종료를 기다려 용량 한도에 도달하면, 해당 카드 판독은 기존 시간 예산 안에서 정리 완료를 비동기로 기다린다. 예산 만료는 그 카드의 미판독이며 새 예산이나 추가 독립 관측을 만들지 않는다. 취소·정리 실패는 별도 처리하고 작업자 한도를 늘리지 않는다. 보관함 수량 등 별도의 예산 없는 메타데이터 OCR은 기존 자원 한도 오류를 유지하므로 이 변경만으로 모든 자원 오류가 해결된 것은 아니다.

입력 → 창·카드 획득 → 품질 선별 → 병렬 판독 → 최신 관측 병합 → 수량·필드 검증의 흐름이다. 진입점은 `src/features/card-scanner/orchestration/scanner.ts`의 `runScanner`다. 메인 UI는 화면 공유만 제공하고 영상·이미지 입력은 개발 화면에서 사용한다.

입력 처리가 끝나도 미식별 관측이 남으면 완료 문구에 그 수를 함께 표시한다. 보관함 수량과 카드 종류 수가 일치한다는 이유로 미식별 입력을 지우거나 숨기지 않으며, 사진·순차 영상·화면 공유에 같은 규칙을 적용한다.

## 1. 입력과 획득

추적 중인 헤더 영역은 좌표·크기와 RGBA 전체 바이트가 동일할 때만 위치 후보를 재사용한다. 정밀 검사가 필요한 낮은 점수의 후보도 재사용할 수 있지만, 원본 해상도 정밀 영역과 성장 탭은 각각 현재 픽셀을 독립적으로 비교·검사한다. 위치 후보 캐시가 최종 창 판정이나 카드 판독 근거를 대신하지 않는다.

창 검출의 고정 회색조 기준 이미지는 정수 출력 크기별로 재사용한다. `detector-template-cache.ts`는 최대 32개·4MiB의 픽셀을 유지하며 오래된 항목과 종료 시 OpenCV Mat을 해제한다. 상한보다 큰 기준 이미지는 해당 비교에서만 사용하고 해제한다. 입력 화면·검출 점수는 이 캐시에 포함하지 않으며 크기 보간 방식과 판정 기준은 동일하다. 상한은 기준 이미지 픽셀에 대한 값으로 OpenCV 전체 메모리 상한은 아니다.

- 화면 공유는 `displaySurface: "window"`로 창 선택을 우선 요청한다. 브라우저가 표시 순서를 결정하며, 공유 대상은 사용자가 직접 선택한다.
- `input-source.ts`, `live-frame-clock.ts`, `track-frame-source.ts`: 실제 표시 프레임/지원되는 트랙 입력을 수집하고 취소·종료를 감시한다. 미지원 환경에는 타이머 대체 경로가 있다.
- `decoded-frames.ts`: Mediabunny/WebCodecs로 저장 영상의 실제 디코드 프레임을 순서대로 읽는다. 일정 간격 seek 횟수를 원본 프레임 수로 취급하지 않는다. 출력 canvas pool은 2개이며 소비자는 다음 프레임 전에 필요한 픽셀을 복사한다. 디코더 내부의 선행 프레임 큐는 별도이므로 이 값으로 전체 디코더·GPU 메모리 상한을 증명하지 않는다.
- 캔버스로 입력을 고정할 때 `copyScannerInput`으로 전체 프레임을 교체한다. 투명한 새 입력에 이전 화면의 픽셀이 섞이지 않으며, 원본 크기와 소유권은 호출자가 관리한다. 모든 브라우저의 색 변환이 같은 바이트를 만든다는 보장은 별도 검증 대상이다.
- `detector.ts`: 카드 창 기준점, 배율·위치, 선택된 성장 탭을 확인하고 10열×4행 논리 좌표와 메타데이터 영역을 반환한다.
- 위치·배율 정밀 탐색은 영역의 RGBA 픽셀과 좌표·크기가 모두 동일할 때만 재사용한다. 성장 탭 검사는 계속 수행하며 창 이동·배율 변화·픽셀 변경 시 다시 탐색한다. 영상 프레임 사이에는 지원 브라우저의 `scheduler.yield()`로 UI에 실행 기회를 주고, 미지원 환경에서는 타이머를 사용한다.
- `card-borders.ts`, `border-integrity.ts`, `card-acquisition.ts`: 슬롯 주변에서 테두리를 보정하고 네 변의 연속성을 검사한다. 화면 밖·가려진 테두리의 카드는 제외한다. 전체 40칸이 온전할 필요는 없다.
- `grid-scroll-probe.ts`, `pixel-region.ts`: 10열 고정·정수 행 상하 이동을 크롭 전에 추정한다. 카드 영역을 한 번 읽고 그 픽셀을 행 비교와 카드별 테두리 검사에 함께 쓴다. 최소 한 행(10칸)의 겹침에서 80% 일치와 차순위 격차를 요구하며 창 위치·배율이 바뀌면 연결을 끊는다. 이동 추정은 캐시 후보 조회에만 사용한다. 같은 열의 이전 슬롯과 패딩 포함 RGBA 전체·크기·정수 이동이 같고 테두리가 온전할 때만 검사 결과와 pixelKey를 재사용한다. 숫자·이름·가림이 한 바이트라도 달라지면 원래 검사로 돌아간다. 이전 캐시 스냅샷은 현재 프레임 처리 동안만 유지하며, 이동량으로 카드 정체성·수량 일치·완료를 증명하지 않는다.
- 같은 슬롯의 정수 좌표와 전체 패딩 영역이 같으면 공유 그리드의 행 간격을 반영해 RGBA 전체를 직접 비교한다. 이때 임시 영역 복사만 생략하고 최종 카드 이미지는 현재 프레임에서 새로 자른다. 이동·부분 잘림·특수 픽셀 전송은 기존 경로를 유지한다. 이 최적화의 실제 브라우저 화면 공유 성능은 별도 측정이 필요하다.
- `capture-quality.ts`, `grid-motion.ts`: 같은 열의 수직 이동과 이름·숫자·보석 관측으로 반복 프레임을 묶는다. 더 선명하거나 안정된 관측으로 후보를 교체한다. 작은 원화 유사도만으로 다른 카드 관측을 제거하지 않는다. 대표 특징이 바뀌면 검색 버킷도 함께 이동한다. 최근 사용한 관측 그룹 4,096개의 특징만 유지하며 퇴출한 그룹 ID는 재사용하지 않는다. 퇴출 후 다시 보인 카드는 새 입력으로 검사한다.
- `name-visibility.ts`: 이름 첫 줄이 완전히 평탄한 가림을 빠르게 제외한다. 흐린 글자 전체를 제외하는 샤프니스 문턱이 아니며 부분·문자 포함 툴팁을 모두 검출하지는 못한다.

실시간 수집에서 기존 가림 양성 신호가 관측되면 같은 입력의 캡처 시각에 묶인 짧은 안내를 본 화면과 진행창에 표시한다. 입력 누락 안내가 더 우선이며, 가림 안내의 만료나 신호 없음은 가림이 해소됐다는 증거가 아니다. 화면이 움직이는 것으로 오분류된 가림은 이 안내에도 나타나지 않을 수 있다. 타이머와 렌더가 중단된 동안 만료 표시는 지연될 수 있고 실제 공유 성능은 아직 측정하지 않았다.

인식용 내부 좌표계는 140×210이다. 썸네일의 장식 여백이 포함된 사진을 이 좌표계에 그대로 리사이즈하지 않는다. 획득 시각·슬롯·좌표·거절 사유·관측 그룹은 `scan-ledger.ts`와 진단 상태에 남긴다.

위치 추정에 사용된 같은 임시 그룹에서 서로 다른 카드 ID가 확인되면 그 그룹을 이번 세션 동안 모호하게 유지한다. 해당 그룹에서 파생됐을 수 있는 위치 앵커와 진행창 위치를 함께 지우고, 모호한 그룹이 포함된 화면을 통째로 위치 등록하지 않는다. 이는 위치 표시의 보호이며 카드 판독이나 자동 종료 근거를 바꾸지 않는다. 그룹이 재사용됐으나 새 신원이 아직 확인되지 않은 구간까지 이 충돌 검사만으로 해결되는 것은 아니다.

## 2. 큐와 병렬 처리

`live-original-capture.ts`는 실시간 입력과 보완 기록의 저장 주기를 공유한다. 입력 수락 시 고정 프레임의 저장 ID를 예약하고, 그 ID를 이미지·캡처 시각과 함께 획득 단계로 전달한다. 뒤늦게 검출을 마쳤더라도 그 사이 저장된 다른 프레임에 결과를 연결하지 않는다. 대기 중 교체된 프레임은 분석 미완료 원본으로 남는다.

화면 공유 입력 콜백은 스크롤 위치를 먼저 게시하고, `freeze-live-frame.ts`로 해당 프레임과 캡처 시각을 함께 고정한다. `live-capture-pipeline.ts`는 브라우저에 실행 기회를 준 뒤 기존 획득 경로를 실행한다. 처리 중인 프레임 1개와 대기 프레임 최대 2개를 유지하며, 같은 고정 프레임의 위치 힌트로 서로 다른 구간의 대표 입력을 우선 남긴다. 위치 힌트가 같아도 픽셀·가림·품질이 같다고 보지 않는다. 다른 구간의 대표 입력이 없고 바이트 한도가 허용하면 같은 구간의 오래된 입력과 최신 입력을 함께 보존한다. 힌트가 없어도 오래된 대표 입력과 최신 입력을 유지한다. 교체·폐기한 입력은 해제하며 입력 종료 시 남은 대기도 처리한다. 취소 시 사용 중인 프레임은 소비자가 끝난 뒤 해제한다. 대기 단계에서 교체된 입력을 판독 완료·독립 관측으로 집계하지 않는다. `VideoFrame`이 없거나 고정에 실패하면 즉시 CPU 캔버스로 복사한다. 이 대체 경로와 전체 화면의 CPU 복사 비용은 남아 있으므로 모든 환경의 무지연 표시를 보장하지 않는다.

획득 Worker(`acquisition-client/worker.ts`)는 OCR 완료를 기다리지 않고 계속 수집한다. `candidate-queue.ts`는 같은 관측 그룹의 대기 후보 하나를 보관하고 교체한 캔버스를 해제한다. 시각 판독 Worker와 독립 OCR 세션이 큐를 소비한다. `fresh-observation.ts`의 일반 미해결 재시도는 완료된 이전 작업·새 픽셀·안정된 입력·750ms 간격을 요구한다.

유휴 판독기는 새 후보나 보조 재시도가 실제 큐에 들어오면 알림을 받고 기존 우선순위에 따라 작업을 다시 선택한다. 알림 누락에 대비해 기존 30ms 대기도 유지한다. 공유가 끝난 뒤에는 큐가 잠시 비어도 다른 판독 작업이 진행 중이면 유휴 판독기가 남아, 그 작업이 나중에 생성하는 재시도를 처리할 수 있다. 시간 초과나 취소는 기존 작업 종료·정리 경로를 따른다. 알림은 판독의 최신성이나 정확성을 증명하지 않으며, 실제 화면 공유에서의 지연은 따로 측정한다.

시각 판독 Worker는 단일 요청을 처리하는 동안에만 캔버스를 빌려 쓰고, 다음 크롭을 그리기 전에 투명하게 지운다. 크기 변경과 그리기 실패 뒤에도 이전 픽셀이 남지 않도록 하며, 4MiB 픽셀 예산을 넘는 크롭은 재사용 캐시에 남기지 않는다. 이 예산은 캔버스의 논리적 픽셀 크기이며 Worker·브라우저·GPU 전체 메모리 상한이 아니다. 캔버스 재사용만으로 전체 스캔 시간 개선을 보장하지 않는다.

이름·장수·각성 영역의 실제 RGBA가 바뀐 입력은 별도로 보존한다. 정수 좌표의 140×210 크롭에서는 기존 40칸 exact 캐시의 필드 영역을 모든 채널로 비교해 선택용 `fieldRevision`을 재사용한다. 필드 밖 원화만 바뀌면 revision을 유지한다. 다른 크기·샘플링 위상·캐시 미적중은 새 revision을 부여한다. 추가 readback·픽셀 사본·래스터 저장소는 만들지 않는다. revision은 카드 정체성·원천·필드 확정 근거가 아니다.

카드 상태 공간은 고정 마스크로 제한한다. 140×210 카드에서 이름 `(6,14,128,36)`, 장수 영역 `(56,141,82,31)`, 하단 `(14,176,112,24)`, 장수 글리프 `(89,143,50,22)`, 각성 보석 5칸은 고정 좌표를 쓴다. 장수는 1~15 템플릿과 아이콘 없는 0을 구분하고, 각성은 0~5의 보석 형태·금색 비율로 판독한다. 각성별 최대 장수는 `15-a(a+1)/2`이며 0각 15, 1각 14, 2각 12, 3각 9, 4각 5, 5각 0이다. 이름은 등급별 고정 색상 마스크를 사용한다. 장착 배너는 원화 매칭의 고정 `above-badge` 영역으로 가리지만 장착 여부 자체는 카드 상태로 저장하지 않는다. 마스크는 판독 영역을 줄이는 근거이며, 가림·블러·이동 프레임의 값을 추정으로 채우지 않는다.

저장 preview 재판독은 새 관측을 만들지 않고 같은 캡처의 다른 원본을 다시 읽는다. 장수 `null` 리뷰 카드는 stable 관측 preview를 우선으로 최대 8개 재검사하며, `iconPresent:false`인 명시적 0장 또는 다중 관측에서 flat 아이콘 영역 + 텍스처 숫자 영역이 모두 빈 경우만 0으로 확정한다. 강한 단일 숫자 후보와 두 OCR 판독이 일치하는 trailing-glyph 사례는 artwork 획으로 설명할 수 있을 때만 확정하고, 낮은 gap·약한 후보는 계속 거부한다. 같은 group/slot의 이전 canonical-row gray는 0.5초 안에서만 캐시해 두 번째 관측의 독립 2프레임 근거로 사용한다. 최종 구조 복원은 2프레임 일치와 preview 필드 판독이 모두 성공한 누락 카드만 추가하며, 필드를 읽지 못하면 추가하지 않는다.

고대비 achromatic checkerboard/dither가 counter 영역을 덮으면 `highFrequencyCounterCover`가 0장 후보를 거부한다. median neighbor difference ≥38, 수평·수직 edge 비율 ≥0.80, 양방향 edge 비율 ≥0.45를 모두 만족할 때만 cover로 보며, 단일 프레임과 다중 프레임 preview에 동일하게 적용한다. 밝은 글리프 일부·평평한 회색 patch·일반적인 저주파 원화는 이 veto에 걸리지 않는다. 이 규칙으로 단일 프레임 고대비 텍스처 cover의 false-zero TODO 2건을 정식 회귀 테스트로 승격했다.

품질을 통과한 새 필드 입력은 이전 판독의 진행·성공 여부와 750ms 간격에 관계없이 정상 판독 후보가 된다. 처음에는 불안정했던 입력이 정지해도 한 번 더 판독할 수 있지만 exact 픽셀의 판독 예산을 초기화하거나 이전 이름을 빌리지 않는다. 더 오래된 캡처는 최신 대기 후보를 교체하지 않는다. 큐에 수락한 뒤에만 최신 수집 메타데이터를 갱신하므로, 큐 거절 뒤 같은 입력을 다시 보여 줄 수 있다.

이름·필드 보조 재시도는 근사 그룹이 같다는 이유로 서로 다른 원본 출처를 교체하지 않는다. 같은 출처라도 이름 판독과 특정 카드의 필드 판독은 별개 작업이다. 재시도 큐가 가득 차 새 입력을 보관하지 못하면 이름과 필드 양쪽 모두 이번 스캔의 카드 확인 근거 손실로 표시하고 자동 종료를 막는다. 같은 큐 안에서 캔버스 등 소유 자원이 중복되면 안전하게 스캔을 중단한다. 이는 큐 진입 이전의 근사 중복 생략이나 서로 다른 큐 간 자원 중복을 검증한다는 뜻이 아니다. 출처를 더 많이 보관하므로 대기·메모리와 포화 빈도는 실제 화면 공유에서 별도로 측정해야 한다.

새 수집 관측이 미식별·필드 실패·큐 거절 상태라면 이전 카드 수량이 맞아도 공유 자동 종료와 기록 생략을 허용하지 않는 것이 목표다. 현재 기본 그룹 정책은 서로 다른 출처를 같은 근사 그룹으로 묶을 수 있어 이 조건을 모든 경우에 보장하지 못한다. 개발용 출처별 정책은 이를 보수적으로 분리하지만, 저장 원본을 다시 읽은 결과와 이전 미식별 출처를 안전하게 연결하는 경로가 아직 완성되지 않았다. 관련 한계와 실험은 `scanner-unknown-source-policy.md`에 정리한다. 최신 필드 변경 근거는 최대 2,048개 그룹의 메타데이터로 보관하고 미해결 근거가 상한에서 퇴출되면 부분 상태를 유지한다. 픽셀 비교만으로 필드 뒤의 원화 애니메이션과 숫자 변화를 구분할 수는 없으므로 실제 입력의 재판독 빈도와 처리량은 별도 검사한다.

현재 스캔에서 같은 카드의 유효한 양수 장수 판독 뒤에 아이콘 부재 기반 0장이 관측되면, 촬영 순서로 비교해 최신 필드를 확인 필요로 둔다. 늦게 완료된 과거 양수도 충돌을 드러낼 수 있으며, 이전 스캔의 seed와 같은 화면 0장의 반복은 충돌을 해소하는 근거가 아니다. 최신 양수 또는 유효한 5각·성장 불가 카드의 규칙상 0은 이후 충돌을 해소할 수 있다. 그렇지 않으면 게임에서 확인한 뒤 새 스캔이 필요하다. 이전 값을 정답으로 복원하지 않으며 확인 전 자동 종료·계산·CSV 확정을 막는다. 양수 관측 없이 가려진 단일 입력에서 0으로 오판하는 경우는 이 정책이 막지 못한다.

이 상태는 목록 seed v6의 `countConflictPolicy`와 출처별 상태 해시로 기록하고 같은 목록 리듀서에서 재생한다. 정책 1은 `fixed-zero` 진단이 있는 고정 0만 인정하며, 정책 2는 실제 판독기처럼 진단 없이 반환된 유효한 규칙상 0도 인정한다. 새 스캔의 정책 3은 같은 촬영 순서에서 신뢰된 각성·장수쌍이 서로 다르면 결과 도착 순서와 무관하게 확인을 보류한다. 동일한 판독의 재시도는 충돌이 아니며, 더 최신의 유효한 판독으로 동시점 충돌을 해소한다. 양수 이후 아이콘 부재 0장에 대한 별도 보류 규칙은 계속 적용한다. 진단이 없는 일반 0장도 이 충돌 규칙을 우회하지 않는다. v1~v5 및 이미 기록된 v6 정책 1·2의 의미는 유지한다. 상태 해시 일치는 기록된 사건의 재생 검증이며 픽셀·이름·장수의 정답 인증이 아니다.

화면 공유 자동 종료는 기본 그룹 정책에서도 판독 대기열과 보조·전체 재시도가 비어 있을 때까지 기다린다. 종료 직전에는 기존 카드 ID와 이름·필드 확인 순서가 해당 관측보다 같거나 최신이고, 해당 재시도의 보관된 이름에 확인 표시가 없는 필드 전용 작업만 정리한다. ID별 확인 순서는 그 재시도와 동일한 물리 입력의 판독 증명이 아니므로 이 정리는 출처 결합을 완성하지 않는다. 새 입력이 계속 들어오면 완료가 지연될 수 있으며, 스캔 화면에 판독 대기 안내를 표시한다. 이 조건은 큐에 들어오기 전에 근사 중복으로 생략되거나 같은 그룹에서 대체된 다른 입력을 복원하지 못한다. 실제 공유에서의 10초 목표와 종료 정확성은 별도 측정이 필요하다.

한 프레임의 카드들을 대기열에 넣는 도중 용량이 차면, 실시간 입력의 해당 프레임을 누락으로 기록한다. 같은 프레임의 여러 칸이 거부돼도 입력은 한 번만 센다. 이 기록은 카드 수가 일치하더라도 자동 종료를 막고 다시 스캔하도록 안내한다. 용량 초과와 기존 그룹의 교체·중복 생략은 별개이며, 이 처리만으로 후보 교체로 인한 누락을 해결한 것은 아니다.

최신 화면 비교의 축소 실험은 비공개 `work/count-reduction-evidence.mjs`와 결과 JSON으로 보관한다. 로컬 실험 자료와 2560×1440 영상이 있는 환경에서 `node work/count-reduction-evidence.mjs <local-video-file>`로 재실행하며 FFmpeg가 필요하다. 기존 수기 라벨 숫자 크롭에서 추출한 획을 동일 배경에 합성해 비교한 것으로, 실제 같은 카드의 시간상 변화를 재현한 것은 아니다. 선택된 서로 다른 장수 175쌍 중 고정 위상의 최근접 1/8 축소는 28쌍, 1/16은 135쌍의 차이를 놓쳤다. 8×8 평균은 이 표본에서 완전 충돌이 없었지만 전체 영역 평균 차이는 임계값에 묻힐 수 있다. 채널 변환·축소는 최신 필드가 같다는 근거로 쓰지 않는다. 영상 프레임에 대한 Node 메모리 내 비교 시간에는 브라우저 화면 캡처·Canvas·GPU 전송·할당·UI 지연이 포함되지 않으며, 실제 화면 공유의 성능이나 정확성을 증명하지 않는다.

같은 입력의 다른 비공개 실험은 `node work/gate-roi-video6-evidence.mjs <local-video-file> <새-결과.json> full`로 실행한다. 저장된 검출 레이아웃에서 계산한 고정 영역을 영상 전체에 적용해 10Hz로 복원한 121프레임의 연속 120쌍은 모두 RGB 픽셀이 달랐다. 최소 차이 쌍은 성장 탭이 아니며, 성장 탭에서 카드·스크롤 위치가 육안상 거의 고정돼 보이는 한 쌍도 1,928,808픽셀 중 10,127픽셀이 달랐다. 영상 압축을 포함한 사례이고 영상의 선택된 프레임 PTS는 보관하지 않아 변화 원인과 실제 화면 공유의 동작을 단정할 수 없다. Node 버퍼 복사·비교 시간은 Canvas readback이나 브라우저의 총 지연·메모리와 다르다. 이 사례만으로 정확한 픽셀 일치 또는 허용 임계값을 배포 종료 조건으로 채택하지 않는다.

관련 비공개 탐색은 `node work/latest-field-temporal-probe.mjs <local-video-file> <새-결과.json>`과 `node work/latest-field-video-probe.mjs <local-video-file> <첫-결과.json> <새-결과.json>`으로 재현한다. 한 영상의 한 프레임에서 수동 추정한 장수 영역 40곳에 고정 좌표를 적용해 10Hz로 비교했을 때 120쌍 중 27쌍이 같았으며, 카드가 보이는 한 정지 유사 구간에 네 쌍 연속 일치가 있었다. 가장 긴 18쌍은 잠금 화면이므로 카드의 안정성으로 세지 않는다. 두 정지 유사 프레임 쌍에서는 장수 영역이 모두 같았지만 수동 추정한 카드 전체 영역은 한 쌍에서 일부 달랐다. 별도로 수기 라벨 크롭의 숫자 획을 한 프레임의 동일 배경에 합성한 175쌍은 추정 장수 영역에서 모두 달랐다. 이 합성은 실제 게임 값 변화가 아니다. 고정 좌표는 검출·위치 이동을 검증하지 않으며 장수 영역만으로 이름·각성·정렬·가림을 확인할 수 없다. 원본 PTS와 실제 화면 공유·Canvas readback·UI 지연을 측정하지 않았으므로 종료 조건 또는 임계값의 안전성·성능 근거로 쓰지 않는다.

장기 전체 프레임 복제를 줄이는 후보로 기본 Canvas 획득의 재사용 프레임에서 완료 직전에 ROI를 비교하는 방식을 검토할 수 있다. 비교 대상은 실제 성공한 마지막 획득이 소유한 픽셀과 동일 세대의 헤더여야 하며, 수집 작업이 없는 동기 구간에서 샘플·근거 확인·종료가 이루어져야 한다. `preparedSources` 또는 native 경로에서는 재사용 Canvas의 픽셀 출처가 같은지 입증되지 않아 이 조건을 적용할 수 없다. 지원되지 않거나 비교가 실패하면 성공으로 처리하지 않고 재관측과 수동 종료 경로를 제공해야 한다. ROI 바깥의 변화와 콜백 사이 변경 후 복귀는 이 비교로 증명하지 못한다. 복사·readback 지연과 피크 메모리, 창 이동·가림·애니메이션·카운터 변화, 영상 및 실제 화면 공유의 정지·복구를 검증하기 전에는 제품 경로에 연결하지 않는다.

경험치·정렬·보관함 OCR은 같은 OCR 세션을 사용하는 주 reader만 기다린다(`metadata-scheduling.ts`). 독립 reader와 새 화면 획득은 계속 진행하며, 메타데이터 정리 중 중복 요청을 시작하지 않는다. 이번 스캔의 이름·최신 각성·장수 근거가 모두 확인된 뒤에만 수집을 잠시 예약해 최종 메타데이터를 확인한다. 이름 수량만 맞은 상태에서는 계속 수집·판독한다. 병렬 reader들은 UI 실행 기회를 주는 8ms 예산을 공유한다. 화면 공유의 카드 수집도 진행 표시 콜백이 있을 때 반복문이 8ms 이상 점유하면 그때까지 처리한 칸을 기존 그리드 명령으로 기록·발행하고 실행을 양보한다. 아직 처리하지 않은 칸은 미확인으로 남고, 정렬 변경과 위치 초기화는 프레임 입장이 끝난 후 함께 적용한다. 대기열로 넘기지 않은 캔버스는 중단·오류 시 정리한다. 중간 표시는 카드 신원이나 자동 종료의 근거가 아니며 저장 픽셀 재판독이 실시간 실행의 스케줄을 재현한다는 뜻도 아니다. `liveInputPipeline` 진단은 입력·처리·대기 교체 횟수와 고정·대기 시간을 기록하며, 카드 판독률이나 실제 모니터 출력 지연과는 다르다.

판독 작업을 합류한 뒤 독립 엔진의 종료를 각각 시도하고 모두 기다린다. 한 엔진의 종료 실패나 선택적인 종료 진단 기록 오류 때문에 다른 reader 정리를 생략하지 않는다. 준비 묶음과 이름 reader의 중복 종료 요청은 같은 정리 작업에 합류한다. Tesseract 인스턴스를 만든 뒤 초기 설정이 실패하면 해당 인스턴스를 종료하고 원래 설정 오류를 전달한다. 이 예외 경로 보강은 모든 조기 중단·브라우저 자원의 즉시 해제를 보장하는 것은 아니다.

OCR 요청은 소유한 캔버스를 사용하고, 시간 초과된 작업의 종료 여부를 확인하기 전에는 해당 세대를 재사용하지 않는다. 정리 대기나 실패로 용량을 확보할 수 없으면 불확정 상태로 중단하며, 이전 인식 엔진의 정리가 확인되지 않은 동안 새 스캔을 막는다. 화면 공유 선택 중 중복 선택과 목록 변경도 막는다. 전체 진척 감시는 화면 획득이 계속되는 동안 개별 판독의 영구 정지를 모두 탐지한다는 보장이 없고, 실제 브라우저 자원의 물리적 해제도 별도다.

미식별 관측의 활성 용량을 초과하거나 같은 그룹에 확인된 이름 근거가 충돌하면 이번 스캔의 입력 근거 손실을 유지한다. 기록 보관만 실패한 경우와는 구분하며, 카드 수만 맞춰 자동 종료하거나 위치를 확정하지 않는다. 앱은 입력 손실·미확정 값 등 확인된 부정 근거가 있으면 결과를 미완료로 표시하고 정상 백업과 CSV 저장을 막는다. 개발 환경에서는 미완료 카드 후보의 별도 저장을 시도하고 읽기 전용으로 복원할 수 있다. 이 저장은 실패할 수 있고 정상 백업·다음 스캔의 시작 목록·입력 재현 기록을 대신하지 않는다. 부정 근거가 없는 것과 별도로, 현재 공유의 최종 헤더와 최신 이름·필드 관측 및 처리 완료를 확인한 근거가 있어야 완료로 표시한다. 복구한 관측이 확인한 헤더보다 나중에 촬영됐다면 그 헤더로 완료를 확정하지 않는다. 이 완료 조건의 실제 화면 공유 검증은 아직 필요하다.

현재 `liveLanePlan`은 논리 CPU 8개 이상에 시각 2/reader 4, 4~7개에 1/2, 그 아래 1/1을 사용한다. 모든 reader가 독립 모델·캐시 상태를 가지며 실제 역할 분리는 `scanner.ts`와 `liveOcrLane`이 결정한다. 짧은 OCR 경로가 긴 정밀 재시도 뒤에 직렬로 막히지 않게 한다. 단일 reader 환경도 `LiveReaderSchedule`을 통해 공유 중 OCR을 실행한다. 재시도가 대기하면 빠른 판독을 연속 8회 처리한 뒤 OCR에 기회를 주며, 새 입력이 없으면 즉시 재시도한다. 공유 중 주 reader가 보조 OCR을 수행할 때에는 같은 OCR 세션에 메타데이터 작업을 중복 투입하지 않는다.

`live-work-priority.ts`는 미시도 관측과 필드 재시도의 처리 기회를 분배한다. 짧은 OCR을 연속 8회 처리하면 대기 중인 정밀 OCR에도 기회를 주며, 이름 재시도가 8회 이어지면 아직 해결되지 않은 각성·장수 재시도를 우선한다. 다중 OCR lane에서는 첫 lane을 짧은 작업에 남겨 정밀 판독이 새 이름 처리를 막지 않게 한다. `field-retry.ts`는 더 최신 결과로 해결된 재시도를 제거한다. `exact-pixel-cache.ts` 등 캐시는 같은 픽셀의 반복 작업을 줄이며, 캐시 재사용은 새로운 독립 판독 근거가 아니다.

`retry-candidate.ts`는 후보 교체를 작업 완료 시각이 아닌 캡처 순서로 판단한다. 더 오래된 후보나 안정된 후보를 불안정하게 만드는 교체를 거절하고, 같은 시각·안정도라면 테두리 정렬이 더 나은 후보만 선택한다. 교체할 때 이전 캔버스와 ledger/grid의 진행 상태도 함께 끝내므로 폐기된 작업이 다음 재관측을 막지 않는다.

수집 시 저장하는 무손실 원본에는 같은 프레임에서 계산한 창 좌표·카드 영역·테두리/품질 검사·특징과 관측 ID를 연결한다(`saved-acquisition.ts`). 원본 저장 ID로만 연결하며 가까운 시각의 영상 프레임에 적용하지 않는다. 최대 128프레임의 검사 정보를 보관하고, 정보가 없거나 크기가 다르면 원래 검출·획득 경로로 돌아간다. 원본 프레임은 검사 정보가 퇴출돼도 버리지 않는다.

서로 다른 캡처의 카드 픽셀과 위치가 같더라도 이전 프레임의 관측 객체·시각을 새 저장 프레임에 복사하지 않는다. 새 프레임이 중복으로 분류되어 읽히지 않았다면 해당 저장 슬롯은 미확인으로 남겨 복구 대상에 포함한다. 같은 물리 원본을 다시 읽는 복구는 그 원본에 연결된 기존 관측과 순서를 유지한다. 이 변경의 A→B→A 순서 검사는 합성 상태·저장 슬롯 경계이며, 실제 영상에서 해당 역전이 발생했거나 해결됐다는 증거는 아니다.

일반 canonical 입력과 개발용 prepared 입력의 관측 별칭은 세션 ID와 실제 물리 원본 ID를 사용한다. 대체 raw 인코더는 검증한 읽기 요청 ID를 `raw-source` 영역으로, 가져온 기록의 명시적인 물리 원본 ID는 `archive-source` 영역으로 구분한다. 서로 다른 producer의 숫자 ID를 같은 저장 원본으로 취급하지 않는다. 분석 캐시가 퇴출되거나 크롭 위치를 다시 보정해도 같은 원본의 재시도는 독립 반복 관측이 아니다. 물리 원본 연결이 없는 구버전 이미지·독립 디코드 입력에는 임의의 저장 ID를 차용하지 않는다. 프레임 진단의 별칭은 새 관측의 기준이며, 저장한 셀 근거를 재사용하면 그 셀은 이전 별칭을 유지할 수 있다.

기록 검사에서는 해당 원본의 이름이 확정됐고 같은 시각 또는 더 최신의 각성·장수 근거가 있으면 크롭 재생성과 판독을 생략한다. 저장된 분석이 없는 크롭도 이름을 실제로 식별한 뒤 더 최신의 확정 필드 근거가 있으면 숫자·각성 재판독을 생략한다. 이때 위치·이름 연결만 갱신하고 새로운 필드 관측을 만들지 않는다. 더 최신의 미확정 필드가 있다면 확인 필요 상태를 유지한다. 미해결 관측은 원래 프레임 ID·시각을 유지해 재시도하므로 새 독립 관측으로 집계되지 않는다.

`recovery-pipeline.ts`는 기록 프레임을 순서대로 획득하면서 독립 reader들이 병렬로 판독한다. 저장된 분석이 없으면 실시간과 같은 Acquisition Worker에서 검출·크롭한다. 기본 대기열 상한은 80개이며 한 프레임에서 추가되는 후보까지만 초과할 수 있다. 빠른 판독·짧은 보완·전체 OCR 재시도를 함께 배분해 마지막 프레임까지 기다린 뒤 재시도가 몰리지 않게 한다. 오류·취소 시 진행 중인 수집·판독을 합류하고 입력 iterator를 정리한 후 픽셀을 해제한다.

무손실 원본은 이번 실행의 최신 필드·재확인한 보관함 수량·미처리/누락 조건을 모두 만족할 때, 해당 원본의 검사 정보도 해결됐으면 파일 읽기 전부터 생략한다. **남은 원본 전부의 검사 정보까지 해결됐음이 확인된 경우에만** 나머지 읽기를 종료한다. 가림·미식별·누락된 검사 정보는 종료를 막는다. 별도로 녹화된 압축 영상은 이런 연결 근거가 없으므로 계속 검사한다. `recoveryReuse`는 재사용 프레임·관측 및 생략 원본 수를 기록한다.

`metadata-order.ts`는 경험치와 정렬 각각 마지막으로 읽힌 캡처 시각과 입력 순서를 보관한다. 메타데이터 OCR을 시작한 프레임의 시각·순서를 작업에 연결하므로 뒤늦게 완료된 과거 영상이 최신 경험치·정렬을 덮지 않는다. 같은 합성 시각을 사용하는 사진들은 입력 순서로 구분한다. 경험치 판독 실패는 마지막 성공 값을 유지한다. 최신 정렬 판독 전체가 실패하면 이전 정렬을 미확인으로 전환하고 위치 연결을 초기화하며, 더 오래된 정렬 결과가 이를 복원하지 못한다. 최신 정렬 종류를 읽었지만 방향을 읽지 못하면 과거 방향으로 채우지 않고 미확인으로 둔다. 방향의 확인·미확인 전환은 위치 연결을 초기화하며 카드 판독 결과는 지우지 않는다. 방향이 미확인이면 이름순 위치 복원도 수행하지 않는다. 두 정렬 검사 사이에 바뀌었다가 돌아오는 상황은 이 규칙만으로 감지하지 못한다. 카드 후보에는 그 프레임에서 읽은 정렬을 별도로 유지해 과거 관측의 이름순 보정 근거를 보존한다.

성장 화면을 찾다가 놓친 입력은 그 사이 정렬·필터의 연속성을 증명하지 못한다. 라이브 획득 중 위치가 확인된 상태에서 화면을 놓치면 위치·스크롤 연결을 초기화하고 정렬을 미확인으로 전환한다. 미검출 입력의 시각과 순서는 늦게 끝난 이전 정렬 OCR이 위치를 되살리는 것을 막는다. 시각이 없거나 음수이거나 뒤로 간 경우에는 정규화하지 않고 획득 순서로 이전 정렬 결과를 차단한다. 카드 판독·그룹 작업과 마지막으로 유효했던 경험치는 유지한다. 기록된 상태 재생은 위치 초기화 명령을 재생하지만, 그 명령만으로 원본 화면의 모든 변화를 복원하지는 못한다.

후보 썸네일은 `candidate-preview.ts`가 `createImageBitmap`으로 고정한 뒤 `candidate-preview-worker.ts`로 전송한다. Worker 안에서 `OffscreenCanvas.convertToBlob`으로 JPEG 0.92를 압축하고 data URL을 만든다. 정상 지원 경로에서는 메인 스레드의 `HTMLCanvasElement.toBlob`을 사용하지 않아 화면 렌더링에 밀리는 인코딩 대기를 피한다. 별도의 카드 크롭으로 이름·각성·장수 판독을 동시에 진행하고, 식별된 카드의 결과와 진행 표시는 사진 인코딩보다 먼저 게시한다. 이미지가 도착하면 해당 관측의 세션 내 토큰에만 연결하며, 최신 표시 이미지가 바뀌지 않는 경우에는 과거 관측에만 보관한다.

인코더가 썸네일 캔버스를 소유하고 재시도는 같은 작업을 공유한다. bitmap 생성 중인 요청까지 실행당 최대 4개로 제한하며, 각 요청에는 750ms 타이머를 적용한다. 시간 초과는 해당 요청의 사진만 생략하고 Worker를 유지한다. 아직 끝나지 않은 native 작업은 늦은 응답이 올 때까지 슬롯을 차지하므로 작업이 무한히 쌓이지 않으며, 늦은 응답은 이미 종료된 결과를 바꾸지 않는다. 전송 전에 늦게 반환된 bitmap은 닫는다. 실제 Worker 오류에는 해당 Worker를 종료하고 진행 중인 요청의 사진만 생략한다. Worker 미지원·생성 실패 시, 또는 실행 중 Worker 오류 뒤의 요청은 같은 상한의 `toBlob`·`FileReader` 경로를 사용하며 동기 인코딩으로 대체하지 않는다.

성공한 카드의 사진 부착은 원래 관측의 표시 토큰으로 검증하며 판독 작업과 별도로 마친다. 인코딩 슬롯이 포화되면 최대 4개·추정 8MiB의 캔버스만 최대 750ms 동안 자리를 기다린다. 인코딩 자체에도 별도 750ms 제한이 있으므로 포화 시 대기가 완전히 없어지는 것은 아니다. 사진을 만들지 못하면 기존 원화 또는 빈 이미지 대체 경로를 사용하고, `resultPresentation.previewOmitted`에는 빈 사진이 반환된 **성공 판독 횟수**를 기록한다. 고유 카드 수는 아니다. 미식별 카드의 이미지 수명과 판독 대기는 유지한다. 카드 판독·입력·최신성·헤더 확인을 마친 뒤에는 선택적 사진 작업을 기다리지 않고 자동 공유를 종료하며, 남은 부착은 최종 목록 발행·저장 전에 정리한다. 자동 종료 시점의 부착·인코딩 결과·credit 대기 호출 수와 최종 부착 정리 시간은 별도 진단이다. 대기 수는 서로 겹칠 수 있으며, 시간 초과 후에도 진행 중인 네이티브 작업이나 고유 카드 수가 아니다. 이 값은 충분한 입력 시점이나 10초 목표 달성의 증거가 아니다. 이 변경의 실제 공유 속도와 메모리 사용량은 아직 측정하지 않았다.

`progress-backup.ts`는 스캔 중인 화면 상태를 별도 IndexedDB에 최대 2초 간격과 `pagehide`/숨김 시 저장한다. `inventoryBackupState`와 같은 검증·상한 규칙을 재사용하되 카드 이미지·미식별 이미지·성장 실행 취소 기록을 제거해 저장량을 제한한다. 복원 시 `status='스캔 중지'`, `interrupted='cancelled'`로 고정해 완료 스캔과 구분하고 CSV 확정을 막는다. 모든 지도 칸은 `historical:true`로만 복원하며 `liveTracking`·`liveTop`·`recent`·`recentFrame`은 저장·복원하지 않는다. 완료된 스캔은 체크포인트를 지우고, 중단·실패 스캔은 마지막 최종 상태를 체크포인트로 남긴다. 저장 실패나 마지막 2초의 변화는 복원되지 않을 수 있다. 복원 카드 목록은 새 스캔의 시작 목록으로 쓰이며, 사용자가 `저장된 목록으로 돌아가기`를 선택하면 완료 백업을 다시 읽고 체크포인트를 지운다.

최종 미식별 관측은 하나의 카드 ID와 matcher gates(corr ≥ .94, margin ≥ .2)를 만족하고 그 ID가 이미 최종 카드 목록에 있을 때 중복 관측으로 분류한다. 중복은 `unidentified` 배열에서 제거하고 `duplicateUnidentifiedObservations` 진단 수로 보존하며, 해결된 관측 수만큼 ledger의 미해결 하한에서 차감한다. 새 카드 ID·경쟁 ID·약한 gates는 중복으로 인정하지 않는다. 최종 구조 복원으로 추가한 카드는 `confirmPreviewCard`로 identity/name/field proof를 같은 캡처 순서에 연결하고, 필드 미확정 카드는 리뷰로 남긴다.

늦은 이미지는 해당 처리 항목의 사진만 갱신하며 최신 카드 결과나 처리 순서를 덮어쓰지 않는다. 결과가 이미 게시된 뒤 사진만 기다리는 작업은 화면의 판독 중 수에서 제외하되, 실제 판독 lane과 자동 종료의 대기는 유지한다. 보조 판독이 시작되면 화면의 판독 중 수가 다시 늘어난다. 따라서 이 변경은 진행 표시를 앞당기는 것이며 스캔 처리량이나 자동 종료 시간이 단축됐다는 뜻은 아니다. 인코딩 대기 중인 후보도 자동 종료의 유휴 입력으로 취급하지 않는다. 스캔 종료·취소 시 남은 작업을 정리하며 원본 판독 크롭·실패 진단 PNG·저장 data URL 형식은 유지한다. 같은 source라도 중복 관측이 새 토큰 없이 거부됐다면 별도의 사진 작업이 같은 크롭이라는 증거가 없으므로 과거 빈 사진을 임의로 채우지 않는다.

## 3. 필드 판독

진행 표시에서는 대기열에 들어간 관측을 `판독 대기`, 실제 reader가 가져간 관측을 `판독 중`, 최신 이름·각성·장수가 확인된 카드를 `완료`로 구분한다. 진행창은 전체 대기 작업 수와 활성 판독 수를 관측 단위인 `건`으로 보여 주며, 전체 완료 수는 중복을 제외한 `종`으로 유지한다. 칸 상태와 작업 수는 33ms 경량 발행 경로로 갱신하며 전체 목록 갱신이나 스캔 종료를 기다리지 않는다. 지도 위치를 아직 연결하지 못한 작업도 전체 작업 수에는 포함된다. 같은 관측의 재시도가 겹치면 판독 시도 토큰으로 늦은 이전 시도의 상태 갱신을 막는다. 진행 상태는 판독 근거·완료 조건에 사용하지 않는다.

새 출처가 기존 근사 그룹에 들어오면 그리드의 이전 이름 연결을 무효화하고 이 동작을 새 그리드 명령에 기록한다. 이전 출처의 판독이 늦게 완료돼도 현재 trace와 다르면 새 칸이나 그룹 위치에 이름을 붙이지 않는다. 기록에 이 명령이 없는 과거 세션은 원래 명령 그대로 재생하며, 이 명령을 모르는 구버전에서는 새 기록을 재생할 수 없다. 복구 출처에 현재 그리드 trace가 없으면 그룹 기반 위치 연결도 생략한다. 다만 별도 상대 위치 그래프와 보관함 위치 계산은 여전히 근사 그룹을 사용하므로 다른 좌표에서 오래된 위치가 재구성될 위험은 남는다. 이 변경은 위치 추정이나 카드 수로 신원을 확인했다는 뜻이 아니다.

새 세션의 진행 지도는 이번 관측의 판독 상태와 이전에 판독 처리한 추정 위치를 구분한다. 이력은 같은 관측의 실제 판독 종료와 위치 기록이 연결됐을 때만 표시하고, 현재 카드 신원·최신 필드·자동 종료 근거로 쓰지 않는다. 정렬이나 감지된 화면 기하 변경 시 위치 이력을 지우며, 명시된 다른 카드·빈칸과 충돌하거나 같은 카드의 더 최신 관측이 다른 위치에 연결되면 해당 이력을 보수적으로 정리한다. 새 표시 규칙과 이력은 명령 및 상태 해시에 포함해 재생하고, 구 기록은 기존 규칙으로 재생한다. 이는 위치 추정의 정확성을 보증하지 않으며, 감지되지 않은 필터 변경도 구분하지 못한다.

등급·보유 필터, 검색어와 알림 설정 체크 상태는 아직 별도로 인식하지 않는다. 현재 자동 종료가 이 설정들이 전체 보기인지 증명하는 것은 아니므로, 사용 안내에서는 스캔 전 설정을 초기화하고 변경했다면 다시 시작하도록 안내한다. 최종 보관함 헤더는 획득한 픽셀에 묶인 등록 수와 용량을 초기 판독 쌍과 함께 비교한다. 서로 다르면 위치 근거를 초기화하고 자동 종료와 완료 영수증을 보류한다. 초기 OCR 오류와 실제 변경을 구분할 독립 근거는 없어서 원래 쌍이 다시 확인되지 않으면 재스캔이 필요하다. 헤더 충돌은 다른 경고와 별도로 표시하고, 실패한 재판독은 충돌을 해소하지 않는다. 아직 획득되지 않은 최신 화면이나 필터·검색 변경을 검증하는 것은 아니며 실제 용량 변경 상황에서의 화면 공유 검증도 필요하다.

`recognizer.ts`, `name-reader.ts`, `neural-reader.ts`, `counter-evidence.ts`, `count-confidence.ts`, `star-pattern.ts`가 각 근거를 관리한다. 공백·줄바꿈/NFKC·숫자 문맥 정규화와 이름 DB 보정은 다른 과정이다. 잘린 접미사를 정규화로 복원하지 않는다. 각성 상한에 맞추려고 차순위 숫자를 선택하지 않는다.

한 자리 장수 패턴의 오른쪽에 높은 대비의 숫자 형태 획이 더 보이면 선택된 패턴이 두 번째 숫자를 놓쳤을 수 있으므로 장수를 미확정으로 둔다. 밝은 배경에 획이 붙은 경우도 더 밝은 획을 재검사한다. 같은 한 자리 OCR 결과나 안정성만으로 이 충돌을 해소하지 않고, 5각의 0장 단축 경로에서도 보류한다. 이는 일부 누락 획을 감지하는 보수적 검사이지 모든 두 자리 오독·그림 반사를 구분하는 증명은 아니다. 수동 크롭과 템플릿 기반 회귀의 범위는 별도로 기록하며, 실제 입력에서 미확정 증가와 최종 결과를 확인한다.

시각 판독의 재사용 작업 캔버스는 매 입력을 투명 픽셀까지 교체한다. 일반 source-over 합성을 사용하면 다음 카드의 투명한 장수 영역에 이전 카드의 픽셀이 남아 0장으로 잘못 확정될 수 있다. 투명 영역을 합성한 카드 크롭 회귀와 브라우저 캔버스에서 교체 결과를 확인했다. 이는 불투명한 툴팁·커서 가림의 안전성을 증명하지 않는다.

추가 확인 카드의 최신 미확정 관측에 장수 영역 불명확 진단이 남아 있으면 어둡거나 가려졌을 가능성을 안내한다. 카드 ID와 관측 순서를 확인하며 이전 관측 진단으로 새 값을 설명하지 않는다. 이는 사용자 안내이며 원인이나 0장을 확정하는 근거는 아니다.

그림 비교용 축소는 최근 하나의 가로 픽셀 겹침 계획을 재사용한다. 너비·출력 열 수가 달라지면 다시 계산하며, 보관하는 크기에 상한을 둔다. 서로 다른 크기의 교차 입력과 실제 픽셀 fixture에서 이전 계산과 같은 출력 바이트를 확인했다. 브라우저 함수 단위 비교는 `work/area-gray-cache-browser-20261104.html`에서 재현하며 전체 스캔 또는 화면 공유 성능을 증명하지 않는다.

정확히 일치한 OCR 문자열이라도 전체 사전의 다른 ID 이름·별칭 안에 포함되면 잘린 이름일 수 있다. 등급 필터 전에 이름·별칭의 관계를 계산하고, 이런 짧은 문자열은 단독 확정하거나 이름 캐시에 넣지 않는다. 다른 OCR 영역을 계속 읽거나 두 영역의 독립적인 원화 판정으로 확인한다. `complete=allowRaw`와 반복된 같은 글자는 텍스트가 물리적으로 완전하다는 증거가 아니다. 그림 순위는 겹치는 이름의 경쟁 ID에 유효한 참조가 모두 있어야 하며, 빠진 참조나 같은 그림의 동점은 확인 대기로 둔다. 이 규칙은 누락된 참조가 있는 카드의 판독 지연을 늘릴 수 있으며 실제 화면 공유의 정확성·시간은 별도로 검증한다.

빈 장수 판정에서는 숫자 영역이 매우 평탄하거나 핵심 영역에 불투명하지 않은 픽셀이 있으면 0장을 확정하지 않는다. 단색과 낮은 대비의 합성 가림을 보수적으로 거르는 검사이며, 자연스럽게 평탄한 0장 이미지도 미확정이 될 수 있다. 더 강한 질감의 합성 가림에서 0장 오판이 재현되어, 이 검사를 전체 가림 제거 또는 안전한 0장 판정의 증명으로 사용하지 않는다. 5각과 성장 불가 카드의 0장 규칙은 별도다.

기본 스캐너의 `currentCountReliability`는 장수 확정에 `stable-frame`이나 `repeated-pattern`을 사용하지 않는다. 현재 안정성은 이전 획득과 같은 열의 이름·숫자·보석 영역이 비슷한지 비교하는 신호로, 서로 다른 물리 입력이나 숫자 영역의 가림 없음을 증명하지 못한다. 처리 프레임 ID가 다르다는 사실도 독립 관측의 증거가 아니다. 안정성 신호는 수집·스케줄링과 표시에 계속 사용하며, 장수에는 명확한 패턴, 숫자 OCR 보조, 명시적 빈 카운터 또는 성장 불가·최대 각성의 0장 등 별도 근거가 필요하다. 근거가 부족하면 미확인으로 남기고 가림 없는 화면을 다시 보여 줘야 한다. 독립 물리 입력을 입증하는 출처 연결은 아직 기본 확정 경로에 연결되지 않았다.

원화 대조는 기존 정수 위치 탐색에서 통과하면 바로 반환한다. 개발 화면의 `?fractional=1` 실험에서만 정밀 재시도 중 테두리 근거가 있는 미확정 크롭에 24×32 특징 좌표의 0.25칸 단위 위치 보정을 추가한다. 기본 앱·빠른 시각 Worker·일반 판독에는 추가하지 않는다. 원화의 두 영역이 각각 0.85 이상이고 평균 0.90 이상인 경우에만 최대 81개 위치를 모든 카드 ID·모든 참조에 똑같이 적용한다. 이름·장착 배너 위의 고정 영역과 기존 상관도·서로 다른 ID 간 격차 기준을 유지하며, 이름 후보에 맞춰 비교 영역을 골라내지 않는다. 정밀 reader들은 같은 규칙을 사용하고 설정 사건에는 `portraitRegistration` 버전을 기록한다. 실제 보정으로 통과한 근거만 `registration: 'quarter-cell-v1'`을 남긴다. 같은 프레임의 위치 보정은 독립 반복 관측이 아니다. 크롭 검사의 개선만으로 실제 수집 처리량이 좋아졌다고 보지 않으며, 기록 ON/OFF의 회귀 검증 전에는 기본값을 켜지 않는다.

`portrait-matcher.ts`, `artwork-verifier.ts`는 이름·장수·보석을 제외한 원화 영역을 비교한다. 이름과 독립된 후보가 일치하고 충분한 격차가 있을 때 보완 근거로 사용한다. 같은 원화의 다른 이름 카드가 있어 그림 최고 점수 하나로 확정하지 않는다.

원문·모델·전처리·신뢰도·후보·실패 분류는 `name-diagnostics.ts`에 남긴다. 평탄한 이름은 독립 원화 판독 경로 확인 뒤 불필요한 OCR/정밀 재시도를 막는다. 알려진 ID의 숫자/각성 재시도까지 막지는 않는다.

## 4. 병합과 검증

`consensus.ts`, `count-corroboration.ts`, `live-inventory.ts`는 카드 ID와 관측 근거로 결과를 병합한다. 각성·장수를 실제로 함께 관측한 유효 조합을 우선하며 최신 **캡처 시각**을 사용한다. 늦게 끝난 과거 OCR이 최신 결과를 덮지 않는다. 추가 장수는 합산하지 않는다.

`current-scan-fields.ts`는 보존된 목록 값과 이번 스캔의 최신 확인 근거를 구분한다. 과거에 0장을 읽었더라도 더 최신 캡처의 필드가 미확정이면 기본적으로 게시 목록에 `최신 각성·장수 확인`을 남기고 CSV·성장 계산에 확정값으로 사용하지 않는다. 다만 **확정된 각성·장수 쌍이 있고 이후 관측이 그 값을 바꾸지 않았으며 가장 최근 캡처가 같은 추가 장수를 읽은 경우**에는 미판독 `null`만으로 그 확정 쌍을 지우지 않는다. `null`을 0으로 바꾸는 것이 아니며, 이후 관측이 다른 각성·장수를 읽으면 즉시 확인 필요로 돌아간다. 최신 실패 사진·시각·사유는 `pendingFields`로 별도 전달하며, 이전 정상 사진과 숫자의 출처를 바꾸지 않는다. 스캔 종료·브라우저 복원 후에도 확인 필요 상태를 유지한다.

이미 판독을 마친 관측 그룹이라도 같은 카드의 더 최신 필드가 미확정이면, 750ms 이후 새로 수집한 안정된 화면을 다시 판독할 수 있다. 픽셀·기하가 정확히 같은 과거 확정 관측은 이름만 재사용하고 각성·장수는 새 캡처에서 검사한다. 저장 프레임 재생이나 같은 작업의 OCR 재시도는 이 새 관측 경로에 포함하지 않는다.

이 새 캡처의 시각 판독은 최대 3초·1회로 제한하며, 기존 픽셀의 공유 시간 예산을 초기화하지 않는다. 시각 판독이 실패하면 같은 픽셀을 반복 투입하지 않고 변경된 관측을 기다린다. 이전 버전 백업에 카드 ID 없이 판독 수 차이만 남아 있는 경우에는 전체 재스캔을 안내하고, 최신 목록 전체를 확인할 때까지 CSV·계산 사용을 보류한다.

같은 OCR 실행·동일 프레임을 여러 번 세어 신뢰도를 올리지 않는다. 이름/각성/장수의 확인 상태를 분리한다. `384 / 450`은 보유 종류 수/용량이지 추가 장수 합계가 아니다. 고유 DB ID 수, 관측 그룹 수, 통과 크롭 수는 서로 다르다.

`confirmed-name-groups.ts`는 이번 실행에서 이름이 확정된 관측 그룹과 캡처 순서를 기록한다. 같은 그룹의 더 최신 이름 판독이 있으면 과거 기록의 시간 초과가 미식별 알림을 다시 만들지 않는다. 이름 확인이 필요한 후보·서로 다른 ID가 충돌한 그룹·더 최신 미식별 입력에는 적용하지 않는다. 이름 해결은 각성·장수를 확정하지 않으며 해당 필드의 확인 필요 상태와 수량 검증은 별도로 유지한다.

이름 마스크 캐시는 그림 보조 근거 없이도 최종 이름 확정 조건을 통과한 결과만 재사용한다. 후보가 최종 식별에서 거절되면 정밀 재시도는 캐시를 우회해 새 OCR을 한 번 수행한다. 기존 카드 시간·횟수 예산은 유지하며, 진단에는 캐시 재사용/우회와 이름 영역 사전 검사 거절을 구분해 남긴다.

장수 OCR 캐시는 최대 1,024개 원본 영역을 보관하며, 영역 크기·각성별 장수 상한·전체 RGBA 바이트가 같을 때만 재사용한다. 흰 숫자 마스크는 검색 후보를 고르는 용도로만 사용한다. 같은 마스크라도 원본 색상이나 명암이 다르면 원본·숫자 영역 OCR 결과가 달라질 수 있으므로 다시 판독한다. 캐시 적중은 새 독립 관측이나 최신 필드 확정 자체를 뜻하지 않는다.

`unknown-observations.ts`는 동일 그룹의 더 최신 실패가 들어오면 사진·사유·캡처 순서도 함께 갱신한다. 같은 시각에는 최종 실패를 대기 상태로 되돌리지 않는다. 서로 다른 미식별 그룹은 비슷한 원화라는 이유로 병합하거나 지우지 않는다. 대표 미식별 목록은 최대 128개이며 이 목록의 길이는 전체 입력 누락 수가 아니다.

`observation-history.ts`는 같은 캡처 순서·프레임에서 필드, 신뢰 상태, 이름·숫자 근거까지 동일한 재시도만 중복 제거한다. OCR 재시도마다 새로 생성한 `readingId`는 차이로 세지 않는다. 다른 프레임이나 달라진 판독 근거는 보존하며, 최신 일부만 남기는 방식으로 합의 결과를 바꾸지 않는다. 이 보존 정책과 관측 특징 LRU는 서로 다른 저장 범위다.

정렬은 인식·표시하고 변경 시 이동 추적을 초기화한다. `confirmSortedNames`는 같은 캡처의 이름순/역순과 앞뒤 고신뢰 이름으로 제한된 보정을 한다. 이웃 이름의 exact OCR은 실제 카드명·별칭과 일치해야 하며, 전체 DB의 다른 이름에 포함되는 짧은 이름이면 독립 그림 근거가 있어야 한다. 기록에 모호성 필드가 없는 구버전은 현재 DB로 다시 계산한다. 다른 정렬을 DB 배열 순서로 대체하거나 슬롯을 영구 ID로 사용하지 않는다. 스크롤 바는 누락 구간 안내용 보조 근거다.

과거 상태 기록에 남은 미확정 이름은 서로 다른 시각이나 OCR 엔진으로 반복해서 읽혔다는 이유만으로 `이름 확인`을 해제하지 않는다. 새 `nameAmbiguous` 근거는 관측과 재생 기록에 보존한다. 상태 재생은 당시 기록된 `name-confirmed` 사건 자체를 새 OCR 결과로 소급 변경하지 않으며, 구버전의 이미 확정된 seed 역시 자동으로 정답 검증하지 않는다. 필요하면 보존된 이미지 입력을 현재 판독기로 **재판독**해 별도로 비교해야 한다.

변경 전 기록과 현재 상태 갱신의 차이는 `npm run corpus -- replay-state <기록-또는-보고서.json>`의 구성요소 해시로 검사한다. 리듀서 규칙이 변경된 구버전 기록은 해시 불일치가 정상일 수 있고, 일치하더라도 해당 기록 범위의 상태 재생만 뜻한다. 영상6의 로컬 상태 기록 3개(22,185·30,353·28,024 이벤트)는 이 이름 근거 변경 후 기존 inventory 해시와 일치했으나, 이 비교는 OCR 재판독이나 그 밖의 기록 전체에 대한 정확도 검증이 아니다.

## 5. 공유 종료와 보완

- **공유 종료**: `auto-completion.ts`는 이번 실행에서 확인한 고유 이름·최신 이름 근거·보관함 수량·획득 상태와 저장된 성장 탭 헤더를 검사한다. 최신 이름·각성·장수 근거가 모두 준비된 경우에만 최종 확인을 위한 수집·판독 일시정지를 예약한다. 이름 수량만 맞고 필드가 미확정이면 수집과 판독을 계속한다. 이미 수락한 입력을 정리한 뒤에도 조건을 다시 검사한다. 같은 이름 목록이 1초 유지되면 새 프레임이 없어도 판단하고 마지막 헤더 수량을 다시 OCR한다. seed만으로는 종료하지 않는다.
- **판독 완료**: 공유를 종료해도 AbortSignal로 취소하지 않는다. 남은 크롭과 필요한 원본/연속 기록 보완을 처리한다.
- **보완 생략**: `recovery-completion.ts`는 이번 실행의 이름·각성·장수 전체 증거, 정확한 수량, 미처리/누락 조건과 헤더를 다시 확인한다. 미식별 관측이나 미해소 그룹이 남으면 수량이 일치하거나 자동 종료됐어도 기록 보완을 생략하지 않는다. 자동 공유 종료 검사에도 이 조건을 적용하며, 미식별 입력의 위치는 재촬영 안내일 뿐 해소 근거가 아니다. 과거의 잡음이나 별도 그룹이 해소되지 않으면 불필요한 보완 또는 종료 지연이 생길 수 있다. 이름 확정 등 기존의 근거 있는 해소가 필요하며 수량만으로 해당 관측을 없애지 않는다. 이미 확정된 개별 원본은 해당 원본의 정확한 획득 receipt를 별도로 확인한 경우에만 건너뛸 수 있다.
- `capture-originals.ts`, `continuous-capture.ts`, `merge-frames.ts`는 원본/녹화 보완을 시간순으로 공급한다. 일반 경로는 RGBA 원본을 한 장씩 직접 읽고 디버그 파일 내보내기만 PNG 변환한다.
- 정상 종료·취소 때 Worker, bitmap, stream, 임시 원본을 해제한다. 해당 실행 외의 브라우저 백업을 지우지 않는다.

`shareEndInventory`는 공유 종료 당시 성적이고 최종 cards는 이후 보완된 결과다. 현재 실행의 종료 성적은 그 순간 공통 목록 reducer의 최신 이름·필드 근거와 표시값이 일치할 때만 확정으로 집계한다. 근거를 전달하지 않은 구형 호출은 미확인으로 남는다. 예전 보고서는 이 검사를 적용하기 전에 생성됐을 수 있으므로 새 수치와 비교할 때 정책 차이를 고려한다. 이 결과는 자동 종료 근거가 아니며 완료 수량이나 대표 미식별 사진 수만으로 전수 정답을 주장하지 않는다. 검증 절차는 [개발 문서](development.md), 미해결 사례는 [설계 결정](decisions.md)을 따른다.

## 최초 준비와 실패 처리

`scan-watchdog.ts`는 상태 문구 대신 처리한 프레임·판독·선별 완료 건수와 단계 전환을 감시한다. 7초간 진척이 없으면 지연을 안내하고, 15초간 진척이 없으면 해당 실행을 취소한다. 진행 중인 긴 스캔은 계속 처리하며, 큐와 활성 판독이 비어 있는 화면 공유 대기는 `capture`뿐 아니라 `reading` 단계에서도 사용자의 스크롤을 기다리는 상태로 제외한다. 복구·정리 단계는 자체 진행 신호와 한도를 유지한다. 스캐너 호출의 초기 준비 한도는 180초이고 개별 초기화 한도와 별도로 적용한다.

같은 픽셀 키의 크롭은 출처별로 시각 판독 1회와 짧은·전체 OCR 각 1회를 예약한다. 서로 다른 출처도 해당 픽셀의 활성 판독 시간 3초를 공유하며, 겹쳐 실행한 시간은 한 번만 세고 대기열 시간은 제외한다. 이 제한은 판독 결과나 카드 신원을 다른 출처로 이전하지 않는다. 시간 초과 작업은 취소하고 미해결로 남기며 다른 카드를 계속 처리한다. OCR Worker는 필요하면 재생성한다. 시도 기록은 픽셀 키 20,000개, 전체 출처 40,000개, 같은 키당 출처 16개로 제한하며, 이 구조 한도에 도달해 새 관측을 판독할 수 없으면 근거 손실을 표시하고 완료를 막는다. 개발 보고서의 예약 개수는 실제 heap 크기가 아니다. 기록 재검사에서도 같은 픽셀의 공유 시간 예산을 재사용한다. 이미 확인된 이름은 장수 재시도 실패 때문에 미식별 카드로 중복 등록하지 않는다. UI 타이머는 탭 실행 정지나 메인 스레드의 동기 연산 중에는 지연될 수 있다.

빈 슬롯, 잘린 테두리, 평탄하게 덮인 이름 영역에 더해 카드 내부의 긴 회색 경계선과 평탄한 어두운 배경을 갖는 툴팁 패널을 제외한다. 모든 커서·툴팁 모양을 식별하는 검출기는 아니며, 불확실한 가림은 판독 근거와 재관측으로 처리한다. 제외한 가림을 미보유나 0장으로 바꾸지 않는다.

하단만 가려진 카드의 추가 안내는 불완전 테두리와 아래쪽 어두운 띠를 가진 크롭에서 같은 원본의 양쪽 카드 경계까지 띠가 이어질 때만 발생한다. 이는 스캔 중 짧게 보이는 **가림 가능성 안내**로, 품질 분류·카드 식별·완료 조건은 바꾸지 않는다. 어두운 UI 등도 후보가 될 수 있고 신호가 없다고 가림이 없는 것은 아니다. 같은 패딩 픽셀을 재사용하는 경우 기본 품질 캐시는 유지하고 안내 검사만 따로 처리한다. 후보 검사는 크롭 최대 280×420픽셀, 획득 프레임당 최대 4칸으로 제한하며 나머지는 다음 입력에서 검사한다. 신규 프레임이 중단되거나 지원하지 않는 픽셀·기하에서는 안내가 생략될 수 있다. 실제 화면 공유 지연이나 가림 전체에 대한 검출률은 아직 측정하지 않았다.

서로 인접한 불완전 카드 위의 어두운 영역을 찾는 프레임 후보기는 진단용이다. 영상 3의 툴팁 가림 명목 크롭 세 개는 기존 개별 품질 분류에서 `moving` 또는 `uncertain`으로 처리돼 가림 부채가 생기지 않았으며, 다른 모든 완료 근거가 이미 충족된다는 합성 상태에서는 종료 조건을 통과했다. 실제 획득·종료를 재현한 결과는 아니다. `node --import tsx work/tooltip-fence-poc-20261102.mjs`로 저장된 비공개 픽셀 검사 결과와 공통 종료 조건을 대조할 수 있다.

`node --import tsx work/frame-panel-real-sampling-20261102.mjs <로컬-영상6-경로>`는 영상 3·6의 선택 프레임에서 진단 후보와 시간을 기록한다. 해당 표본의 영상 6 약 9.3초 빈 슬롯 화면과 약 10.2초 잠금 화면에서도 후보가 검출돼, 이 후보만으로 가림 부채나 툴팁을 확정해서는 안 된다. 위치는 수동 추정이고 seek 시각의 실제 PTS는 확인하지 않았으며, 눈으로 본 제한적인 화면 확인은 독립 정답이 아니다. Node 내 후보 계산 시간에는 브라우저 화면 readback이 포함되지 않는다. 정지·스크롤·빈 슬롯·잠금·툴팁의 추가 실제 자료와 원본 연결 검증이 필요하다.

별도 실험 `node --import tsx work/hybrid-tooltip-holdout.mjs <영상1> <영상2> <영상3> <영상4> <영상5> <영상6>`은 기존 후보에서 균일한 어두운 띠의 가로 길이가 일정 범위인 경우를 살펴본다. 2560×1440의 수동 추정 칸과 선택된 75개 프레임에서, 눈으로 확인한 영상 3의 칸을 가리는 툴팁 7개에는 후보가 남고 영상 6의 빈칸·잠금 표본에는 남지 않았다. 성장 탭이 아닌 영상 3·5 시작 화면에서도 후보가 생겼고, 위치가 이동한 영상의 칸도 수동 추정이었다. 양성은 한 영상에만 있고 일부 화면만 육안 확인했으며 실제 PTS, 서로 독립적인 정답과 브라우저 캡처·검출·readback 비용은 확인하지 않았다. 후보 검색 자체도 결과 제한으로 잘릴 수 있어 빈 결과는 가림 부재를 뜻하지 않는다. 띠 길이 조건은 탐색 가설이며 제품의 가림 부채나 종료 판단에 연결하지 않는다.

추가 비공개 실험 `node --import tsx work/tooltip-screenshot-holdout-20261102.mjs <사진폴더>`에서는 사용자가 제공한 별도 스크린샷 두 묶음 20장에 동일 후보를 적용해 후보가 없었다. 전 화면의 가림 여부를 독립적으로 확인한 정답은 아니며 고정 수동 좌표를 사용했다. `node --import tsx work/tooltip-panel-transplant-20261102.mjs <툴팁사진> <사진1> <사진2>`는 한 툴팁 픽셀 영역을 두 사진의 여러 위치에 합성한 16건에서 후보를 찾았다. 같은 패널을 옮긴 합성 입력이므로 실제 화면의 별도 양성 사례나 가능한 모든 가림의 검증이 아니다. 반환 후보는 전체 가림 범위나 카드 ID가 아닌 일부 겹친 칸이다. `work/bench-obstruction-prefilter-20261102.mjs <사진폴더> <툴팁사진>`의 Node 메모리 내 조기 필터 비교는 표본의 출력이 같았으나 뚜렷한 평균 속도 이득이 없었다. 모든 비용 측정에서 브라우저 캡처·픽셀 전송·테두리 검사·스케줄링은 빠져 있다. 입력과 실행 조건의 해시는 비공개 `work/` 결과에 보관하며 제품 경로에는 연결하지 않는다.

빈 슬롯의 고정 뒷면 무늬는 작은 커서 가림도 고려한다. 이름 영역 밖의 한정된 국소 오차만 제외하고 나머지 전체 무늬를 더 엄격하게 비교한다. 이름 영역 가림·넓은 패널·분산된 변화는 이 예외로 버리지 않으며, 수량 일치를 이유로 미식별 입력을 제거하지 않는다.

미식별 카드에는 캡처 시점의 스크롤 비율·열 위치를 기록한다. 안정된 관측에서 스크롤바 크기와 행 경계가 일치할 때만 위에서부터의 예상 행을 표시한다. 위치는 캡처 당시 정렬·필터 기준의 안내이며 카드 ID, 중복 제거 또는 수집 완료 증거로 사용하지 않는다. 실제 품질과 필드가 달라진 새 관측을 같은 위치라는 이유로 버리지 않는다.

녹화 종료 이벤트 대기는 10초, 마지막 자원 정리 단계는 15초로 제한한다. 수동 취소·시간 초과는 Worker와 공유 트랙을 중단하고 호출자를 반환시킨다. 브라우저 작업이 취소에 응답하지 않아 뒤늦게 끝나더라도 이전 실행의 콜백은 새 스캔 결과에 반영되지 않는다. 브라우저 전체가 정지되거나 탭 실행이 보류되면 타이머도 지연될 수 있다.

중단 시 읽은 카드 목록은 화면에 유지하지만 스캔 완료로 표시하거나 완료 백업에 덮어쓰지 않는다. 미판독 필드를 0으로 채우지 않으며, 사용자는 남은 목록을 확인하고 다시 스캔할 수 있다. 회귀 테스트는 진척 있는 장기 작업, 무응답 판독·정리, 녹화 종료 이벤트 누락, 수동 취소, 늦은 콜백 차단을 검증한다.

저장된 화면 재검사가 30초를 넘으면 프레임이 계속 처리되고 있어도 대기 또는 수동 중지 안내를 표시한다. 이는 시간 안내이며 전체 검사 시간 제한이나 자동 완료가 아니다. 무진척 중단 기준은 별도로 적용되고, 재검사가 끝나면 이 안내는 사라진다.

페이지의 첫 렌더링 뒤 `scanner-preparation.ts`가 검출기, 이름·숫자 OCR 세션, 병렬 판독 Worker를 백그라운드에서 준비한다. 준비가 끝나면 화면 공유 버튼을 활성화하며, 실패하면 공유를 시작하지 않고 재시도 버튼을 표시한다. 준비 중에도 CSV·기존 목록은 사용할 수 있다. 보조 Tesseract는 필요한 판독이 생겼을 때 생성한다.

`prepared-slot.ts`는 준비된 엔진의 소유권을 한 스캔에만 넘긴다. 공유 선택을 취소하면 준비된 엔진을 유지하고, 스캔에서 인계받으면 다시 초기화하지 않는다. 스캔 종료 시 해당 세션과 캐시는 폐기하고 다음 스캔용 새 세션을 준비한다. 준비 취소·실패·페이지 해제에서는 미사용 엔진을 정리한다. 개발용 영상·이미지 입력은 준비된 엔진 없이도 기존 초기화 경로로 실행할 수 있다.

이름/숫자 모델은 HTTP 캐시에서도 읽을 수 있으므로 `불러오는 중`으로 표시하며 Worker가 읽은 바이트 수를 전달한다. 이후 ONNX 세션 생성은 `인식 엔진 준비 중`으로 구분한다. 페이지의 상세 준비 상태는 같은 단계가 700ms 이상 지속될 때만 표시하며, 바이트 수 갱신은 같은 단계로 취급한다. 완료·오류는 지연하지 않는다. 초기 준비 대기는 120초, 카드 외 메타데이터 OCR 요청은 30초로 구분한다. 카드 판독은 앞서 설명한 공유 3초 예산을 우선 적용한다. 첫 recognizer 준비 실패는 아직 반환되지 않은 reader도 해제하며 취소 신호는 모델 Worker를 종료한다. 검출기 준비를 취소한 뒤 늦게 완성된 인스턴스도 dispose한다. 네트워크 오류는 준비 다시 시도로 재시도할 수 있고 판독 신뢰도 규칙에는 영향을 주지 않는다.

## 실시간 판독 큐

- 8코어 이상에서는 fast 레인 2개와 OCR 레인 2개를 사용한다.
- OCR 레인은 short/full 재시도를 우선한다. 재시도가 없고 메인 큐가 `readers × 16` 이상으로 클 때만 fast 큐를 돕는다.
- 실제 398장 공유에서 1분 39초에 `확인 133 / 398`, `대기 729`, `판독 중 2`가 관찰됐다. 이때 OCR 레인 2개가 유휴 상태였고, fast 레인 2개만 메인 큐를 처리하고 있었다.
- 위 보조 규칙은 재시도를 빼앗지 않으면서 큰 백로그에서 유휴 리더를 활용한다. 작은 큐에서는 기존 OCR 전용 예약을 유지한다.
- OCR 보조 레인에는 전용 visual Worker가 없다. fast 작업을 보조할 때 lane 0의 visual Worker를 공유하면 `동시 시각 판독 요청`으로 스캔이 중단되므로, OCR 보조 레인은 `visual=null`로 reader 내부 경로를 사용한다.
- 스캔 중지는 최초 입력 후 2분 하드 캡이 아니라 **2분 무진행 + 5분 하드 캡**이다. 입력·판독·이름 수가 갱신되면 무진행 타이머가 다시 시작된다. 복구 단계에서는 `recoveryFrames`·`percent`·`workPhase` 변화와 대기/판독 중 작업도 진행으로 계산한다. 사용자가 다른 창을 보는 동안에는 두 타이머 모두 숨김 시간을 제외하므로, 화면을 확인하거나 대화하는 동안 스캔이 만료되지 않는다. 배포본에는 이 앱 타이머가 없었으므로, 수동 스캔을 30초 만에 끊던 이전 동작은 회귀였다.
- 확인이 필요한 카드(`review`가 남은 카드)가 있으면 **idle 중지를 보류**한다. 사용자가 해당 카드를 다시 보여줄 시간을 주되, 5분 하드 캡은 유지한다. 진행 UI에는 확인 필요 카드 이름을 직접 표시한다.
- 카드 영역을 찾지 못한 프레임에서는 `최신 확인` 대신 **`마지막 확인`**으로 표시하고, 현재 화면에서 카드 영역을 찾지 못했다는 안내를 함께 보여준다.
- 표시의 `판독 완료/마지막 판독` 기준은 매 프레임 40칸 판독 상태를 요구하는 `gridReady`가 아니라 **현재 카드 영역이 잡혔는지(`located`)** 다. 최근 프레임은 `begin()`과 `record()` 사이에 사라지므로 표시 컴포넌트가 마지막으로 커밋된 프레임을 유지한다. 이는 표시 전용이며 grid 증거를 바꾸지 않는다. 실제 공유에서 30초 목표 달성 여부는 아직 재측정하지 않았다.

## 목록 백업

`scan-backup.ts`는 카드 값·판독 근거·목록 이미지, 경험치·성장 실행 취소, 이번 스캔의 완료 근거와 실패 안내만 같은 origin의 IndexedDB에 저장한다. `null`과 0, 필드 신뢰 상태, 미식별 카드 사진을 유지한다. 실시간 지도, 활동 썸네일, 전체 ledger, 검사 샘플과 성능 로그는 목록 백업에서 제외하고 종료한 작업 대기 수는 0으로 복원한다. 이전 전체 상태 백업도 같은 최소 필드로 읽는다.

저장소 열기는 5초, 트랜잭션은 8초 한도다. 다른 연결의 잠금·오류·시간 초과를 안내하고, 늦게 열린 연결과 중단 트랜잭션을 정리한다. 실패한 작업은 저장 대기열을 막지 않아 다시 시도할 수 있다. revision 비교로 다른 탭의 최신 목록을 덮어쓰지 않으며, 카드 백업은 아래의 진단 저장 완료를 기다리지 않는다.

## 스캔 세션 기록과 재현

미식별 입력의 그림 매칭 진단은 실제로 평가한 영역별 상위 두 후보의 점수·격차·위치 보정과 판정 조건을 남긴다. 한 크롭의 마지막 판독에서 시각·정밀·텍스트 보조 경로별 최대 한 건씩, 총 세 건만 보존한다. 캐시 측정 재사용은 새 계산과 구분하며, 진단을 위해 픽셀이나 유사도를 다시 계산하지 않는다. 이 선택적인 데이터는 같은 경고 버전의 sidecar에만 연결하고 기존 메타데이터 예산에 포함한다. 진단 누락·불량·예산 초과는 카드 정체성이나 경고 상태를 바꾸지 않으며 원화 전체·전체 후보 순위는 저장하지 않는다.

화면 공유는 기본으로 진단 요약과 제한된 문제 이미지만 보관한다. 문제 재현용 상세 기록을 켜면 `beginReproduction`이 스캔마다 새 세션 ID와 시작 상태를 만들고, 선택·획득된 입력과 실행 이벤트, 미리보기 영상을 청크로 저장한 뒤 종료 상태와 진단 요약을 봉인한다. 모든 전달 화면의 픽셀이 보존된다는 뜻은 아니다. 새 스캔으로 이전 세션을 덮어쓰지 않는다. **사용법 → 문제 해결 → 스캔 진단**의 **상세 입력 기록 · 문제 재현용**에서 다음 스캔의 입력 보관을 켤 수 있으며, 끈 경우에도 세션별 진단 요약은 남긴다. 기록 Worker 준비 실패는 스캔을 영구 차단하지 않으며 입력이 없는 요약·부분 기록으로 구분한다. 카드 목록 자동 저장은 진단 저장과 독립적이다.

`reproduction-session-store.ts`는 IndexedDB의 세션 색인·세부 정보·청크를 분리한다. 목록 조회는 입력 Blob을 읽지 않는다. 입력 보관의 기본 한도는 최근 8개·총 512MiB이며, 한도에 닿으면 종료된 미고정 세션부터 오래된 순서로 정리한다. 고정 세션과 진행 중인 세션은 자동 삭제하지 않는다. 이 보호 조건 때문에 새 입력을 보관할 수 없으면 기존 기록을 지우지 않고 부분 기록 사유를 남긴다. 입력이 없는 실패 색인 한 개는 개수 한도 밖에 추가로 남을 수 있다. 브라우저 자체 할당량이 부족한 경우에도 같은 보관 한도를 달성한다고 보장하지 않는다.

활성 세션은 15초마다 갱신하는 2분 lease로 보호한다. 페이지 중단 후 마지막 활성 확인에서 2분이 지나면, 다음 기록 목록 조회 때 만료 세션을 부분 기록으로 복구한다. 이미 저장된 연속 청크만 사용하며 잘린 마지막 엔트리는 입력 재현에서 제외한다. 누락 프레임 수나 처리 시간을 알 수 없으면 미확인으로 남기고 0으로 채우지 않는다. 다른 탭의 유효한 활성 세션은 복구 대상으로 바꾸지 않는다.

진단 요약은 결과·처리 시간과 카드 크롭 최대 32장, 인코딩 문자열 합계 1MiB를 담는다. 요약 자체에는 원본 프레임·전체 관측 로그를 넣지 않으며, 상세 입력 기록과 별도로 읽고 저장할 수 있다.

최신 필드 미확정 카드의 사진을 우선 보관하고, 판독된 과거 값과 별도로 최신 캡처 시각·장수 미확정 사유·안정 여부·테두리 점수를 작은 메타데이터로 남긴다. 따라서 과거 정상값이 목록에 남아 있어도 실패한 최신 관측의 원인을 확인할 수 있다.

필드 실패 사진은 테두리를 포함한 JPEG 미리보기 대신 실제 판독에 사용한 카드 크롭의 무손실 PNG를 우선한다. 같은 획득 키만으로 다른 인코딩 작업의 픽셀이 같다고 단정하지 않고 현재 소유한 크롭을 인코딩한다. 최대 12개·인코딩 합계 1MiB만 유지하며, 더 최신 관측이 확정되면 해제한다. 요약의 `images.source`로 실제 입력과 미리보기를 구분한다. 아이콘 감지·숫자 후보/점수/격차·OCR 결과도 제한된 메타데이터로 남기며, 전체 프레임 녹화 없이 작은 색상 차이를 재현할 수 있다.

미식별 관측도 별도의 최대 32개·1MiB 캐시에 실제 판독 PNG를 남긴다. 최신 미식별 상태에 맞춰 이미지를 투영하므로 퇴출한 이미지를 상태 배열에 계속 붙잡지 않는다. 최종 요약은 두 이미지 캐시와 미리보기를 합쳐 위의 32장·1MiB 상한을 지킨다. `unidentifiedObservations`는 별도 1,000건·1MiB 상한으로 그룹·원본 관측·위치·OCR 후보를 보존한다. 미기록 OCR은 `null`, 실제 0회는 `[]`로 구분하며 후보로 정체성을 강제하지 않는다. 실제 판독 PNG와 표시용 미리보기는 서로 다른 입력이고, 요약의 이미지 인덱스는 원본 URI가 같을 때만 연결한다. 사진이 빠져도 메타데이터와 생략 건수를 남기며, 전체 경고 발생·퇴역 순서의 검증은 별도 실행 사건이 필요하다.

0장 판독의 아이콘 잔여 검사는 청록 픽셀 수·연결된 모양·주변 명도 대비를 함께 본다. 흐린 원화의 선이나 면이 색상 조건을 넘더라도 주변과 구분되는 경계가 없으면 아이콘으로 단정하지 않는다. 선명한 청록 잔여·주변 대비가 있는 아이콘 몸체/가장자리·숫자 획이 남은 관측은 계속 미확인으로 처리한다. 숫자 OCR 실패를 0장으로 치환하지 않는다.

아이콘 또는 숫자 영역이 불투명하지만 색상 변화가 작으면 가림과 구분할 수 없어 0장 대신 미확정으로 둔다. 자연스러운 저대비 원화도 보류될 수 있으며, 색상 변화가 큰 가림은 이 검사만으로 판별하지 못할 수 있다. 이 경계는 `tests/count-textured-occlusion.test.ts`에서 확인하고 알려진 고대비 반례를 `tests/count-pattern-runtime.test.ts`의 TODO로 유지한다.


회색 카드 표식과 숫자 영역의 배경이 정해진 형상 검사에 맞으면 `gray-card-marker-and-visible-background` 근거를 별도로 남긴다. 표식만으로 0장을 확정하지 않고 숫자 획과 활성 아이콘으로 판단되는 특징도 확인한다. 이 검사는 일부 가림을 걸러내지만 가림이 없거나 배경이 실제 원화라고 증명하지는 못한다. 특히 질감 있는 덮개와 다른 0장 카드의 장수 영역을 이식한 합성 반례에서 양수 장수가 0장으로 잘못 판정될 수 있다. 이 근거는 유효한 각성 판독과 함께 확인하며, 판독 실패를 0으로 바꾸는 보정으로 사용하지 않는다.

입력 기록 Worker는 공유 전에 준비한다. 저장소 예약과 청크 쓰기는 카드 획득을 기다리게 하지 않으며, 저장이 밀리거나 실패하면 이미 보관한 구간을 부분 기록으로 남긴다. 세션 ID·소유권·청크 순번을 검사하므로 늦게 끝난 이전 저장이 새 세션의 입력을 교체하지 않는다. 재현용 데이터는 이 브라우저에만 보관하며 외부로 자동 전송하지 않는다.

진단 화면에서 세션을 선택해 고정·삭제·파일 저장을 할 수 있다. 가져온 파일은 임시로 열며 저장된 세션이나 내 카드 목록을 교체하지 않는다. **입력 재현 시작**은 저장한 검출 전 픽셀을 현재 인식기에 다시 넣고, **원래 실행 기록 확인**은 당시의 관측·지도·카드 근거·입력 선택 사실을 공통 상태 갱신 코드로 재생한다. 픽셀 없는 실행 기록은 후자만 사용할 수 있다. 두 경로 모두 내 카드 목록을 수정하지 않는다. 요약 JSON은 입력 재현 파일이 아니다. 공유 화면과 시작 목록이 포함되므로 파일을 외부에 공유하기 전에 내용을 확인한다.

파일 읽기·검사·재현은 중지하거나 창을 닫아 취소할 수 있으며 오래된 작업 결과는 무시한다. 일반 불러오기·삭제는 30초, 실행 이벤트 검사는 120초, 전체 재현은 10분 한도로 중단한다. 스캔·진단 저장 중에는 설정 변경·불러오기·삭제·재현을 잠그되 닫기는 허용하며, 저장이 끝나면 열린 진단 창을 갱신한다.

### 무손실 입력과 실행 기록

아래 동작과 한도는 입력 기록 보관을 켠 스캔에 적용한다. 획득 Worker에 도착한 입력을 기록하는 것이며, 공유 원본의 모든 프레임을 저장한다는 뜻은 아니다.

- Acquisition Worker가 검출·품질 필터 이전의 RGBA 픽셀을 읽고 별도 기록 Worker로 버퍼 소유권을 넘긴다. 복구 단계에서 추가로 사용한 입력도 같은 채널에 기록한다.
- 기록 Worker는 이전 프레임과 바이트 단위로 같은 블록을 생략하고, 바뀐 블록의 XOR 차이를 LZ4로 저장한다. 축소·색상 양자화·JPEG/WebM 재압축을 인식 입력으로 사용하지 않는다. 매 프레임 SHA-256을 저장하고 복원 때 검사한다.
- 프레임 ID·캡처 시각·입력/복구 단계, 입력 수락/건너뜀, 획득 영역, 품질/대기열 결정, 판독 시작/종료, 카드 갱신 및 종료 결과를 순서 번호와 함께 보관한다. 메인 스레드는 작은 이벤트 배치만 전송한다.
- 시작 목록, 브라우저, lane 설정, 카탈로그 버전, Git 식별자, 소스·인식 데이터·lockfile·고정 모델 구성의 SHA-256을 함께 저장한다. 개발 서버의 구성 해시는 시작 시 계산하므로 코드 수정 후 버전 비교 검증은 서버를 재시작한다. 재판독은 저장 당시 코드가 아닌 현재 로드된 코드로 실행한다. 구성 해시가 없으면 미확인으로 표시하며, 해시가 같아도 HMR 이후 실제 로드된 코드가 같다는 근거가 되지 않는다.

### 메모리·저장 한도

기록 입력은 최대 3프레임이며 합계 64MiB를 넘기지 않는다. 한 프레임은 32MiB까지다. Worker는 이전 입력 한 장과 현재 압축 작업 버퍼만 유지한다. 입력 대기 한도에 걸리면 스캔을 기다리게 하지 않고 기록 누락을 집계하며, 완전 기록으로 표시하지 않는다. 압축 작업 버퍼·OCR·캔버스까지 포함한 탭 전체 메모리가 64MiB라는 뜻은 아니다.

기록 Worker는 OPFS SyncAccessHandle을 사용하고, 미지원 환경에서는 비동기 파일 쓰기로 대체한다. 작은 이벤트는 배치로 쓴다. OPFS 압축 임시 파일은 최대 1GiB, 이벤트는 최대 4개 전송 배치와 1MiB 대기로 제한한다. 이 임시 파일 상한과 IndexedDB의 세션 합계 512MiB 한도는 별개다. 디스크 오류·기록 누락·이벤트 누락은 부분 기록 경고로 남기고 스캔 결과는 유지한다. 정리 단계에서 임시 파일을 해제하며, 비정상 종료된 24시간 이전 임시 파일만 다음 시작 때 자체 폴더에서 정리한다.

`recording-journal.ts`는 통상 256KiB·최대 4MiB 청크를 순차 저장하며 공통 저장 대기는 8MiB로 제한한다. exact Worker의 전송 크레딧과 영상 저널도 각자 대기 상한을 갖는다. 저장이 느리다고 프레임 획득을 기다리게 하지 않고 기록의 완전성을 철회한다. SyncAccessHandle 경로는 진행 중인 파일 구간을 읽어 저널에 옮긴다. 비동기 OPFS 쓰기 경로는 파일을 닫은 뒤에야 exact 바이트를 저널로 옮기므로, 중간 크래시에서 복구할 수 있는 exact 입력이 없을 수 있다. 어떤 경로에서도 아직 청크로 저장되지 않은 입력의 복구를 보장하지 않는다.

별도 WebM은 미리보기와 기존 스캔 복구 경로에 사용한다. 기존 MediaRecorder를 재사용하며 최대 256MiB, 쓰기 대기 16MiB, OPFS 미지원 시 RAM 대체 32MiB 한도를 유지한다. exact와 영상은 별도로 저장하므로 미리보기가 없어도 남아 있는 exact 입력을 사용할 수 있다. 무손실 기록을 미지원하면 영상 기반 부분 재현임을 표시한다. 각 대기열 상한을 합쳐 탭 전체 메모리나 디스크 사용량의 단일 상한으로 해석하지 않는다.

### 재현 파일과 검증 범위

새 버전 3 `.loareplay`는 길이 검증된 메타데이터와 남아 있는 WebM·exact 스트림을 담는다. 미리보기 영상은 생략할 수 있으며 중단 복구 기록의 알 수 없는 누락·성능 값은 미확인으로 보존한다. 전체 파일을 base64나 하나의 ArrayBuffer로 읽지 않는다. 이벤트 헤더는 1MiB씩 묶어 읽고 입력은 한 프레임씩 복원한다. 파일 길이·해제 크기·LZ4 오프셋·프레임 순서·픽셀 해시를 검사한다. 기존 버전 2의 영상·exact 기록과 버전 1의 압축 영상 기록도 구분해 읽는다.

입력 재현은 원래 답안을 넣지 않고 당시 시작 목록과 복원 픽셀을 현재 인식기에 전달한다. 원래 결과와 추가/누락/각성·장수·확인 상태 변경을 비교한다. 원래 결과 자체를 정답으로 간주하지 않는다. 같은 파일을 반복 실행해 결과 안정성을 확인하고, 수정 전후는 코드/데이터 해시를 함께 비교한다.

입력 재현의 검증 대상은 **기록된 인식 입력의 바이트와 캡처 순서·시각**이다. 실행 상태 재생은 저장한 사실의 적용 결과와 종료 해시를 비교하며, 미완료·누락 기록은 전체 일치로 표시하지 않는다. 실제 도착 간격의 처리량·UI 반응·종료 시간 검사는 별도로 수행한다. 브라우저가 애초에 전달하지 않은 화면, OS 스케줄링, 실제 병렬 Worker 완료 순서/소요 시간은 동일 실행으로 강제하지 않는다. 누락 수·입력 해시·필드 결과·실시간 처리 속도를 각각 확인하며 하나의 통과를 나머지 검증으로 대신하지 않는다.

### 실시간 위치 표시와 종료 검사

스캔 중에도 상대 위치 연결을 결과 발행 시 갱신하여 진행창의 판독 칸을 채운다. 관측 프레임·이름·독립 위치 근거가 바뀌었을 때만 그래프를 재계산하며, 별도의 250ms 대기를 두지 않는다.
부분 목록은 전체 보관함으로 간주하지 않으며, 독립적으로 확인된 여섯 열 이상의
절대 위치에서 이어지는 연결만 표시한다. 원점 추론과 끊긴 구간의 유일 배치는
최종 전체 검증 때만 허용한다. 칸의 색은 이번 스캔의 최신 필드 근거로 갱신하고,
새 관측이 미확정이면 완료 표시를 되돌린다. 이 표시용 연결은 인식·자동 종료 근거가 아니다.

판독 완료 후 `observed-inventory-layout.ts`가 테두리·품질 검사를 통과한 카드 관측의 상대 위치를 카드 ID로 다시 연결한다. OCR 필드의 정지 여부와 같은 프레임 안의 상대 위치는 구분한다. 이름순 외 정렬에서도 같은 화면에 보였던 카드의 행·열 간격과 겹치는 카드 ID를 이용한다. 서로 다른 여섯 열 이상의 유효 카드가 있는 화면만 사용하며, 중복 화면은 한 번만 보관한다. 최대 1,024개 화면의 그룹 번호와 최대 40,960개의 그룹-ID 연결만 유지하고 픽셀은 추가 저장하지 않는다. 정렬 변경은 위치 기록을 초기화한다.

전체 검증된 카드가 하나로 연결되고 실제 관측 간격이 빈틈없는 슬롯과 열 정렬을 이루면 전체 위치를 복원한다. 부분 연결은 독립적으로 확인한 여섯 열 이상의 절대 위치가 일치해야 한다. 빠른 이동으로 겹침이 없는 구간은 모든 확정 ID의 실제 위치 관측이 있고, 기준 위치와 모순이 없으며, 남은 공간에 열·간격을 유지하는 배치가 단 하나일 때만 연결한다. 가능한 배치가 여러 개이거나 같은 카드의 열·간격·절대 기준이 충돌하면 추정하지 않는다. 카드 개수로 초록 칸을 만들거나 미관측 칸을 빈 슬롯으로 채우지 않는다. 복원은 표시 전용으로 판독 신뢰도·자동 종료 조건에 관여하지 않는다.

스크롤 손잡이는 아래 화살표와 분리한 트랙 길이로 계산하며 맨 아래 테두리까지 탐색한다. 일부가 커서로 가려진 경우 서로 다른 열의 테두리 쌍과 채워진 내부가 일치해야 위치를 읽는다. 가림이나 높이 오차로 스크롤 위치를 확정하지 못해도 관측을 버리지 않고, 여섯 열 이상의 기존 카드 겹침으로 연결할 수 있다. 이때 이전 스크롤 좌표를 재사용하거나 손잡이 보정을 학습하지 않는다.

스크롤 양 끝도 카드와 손잡이가 안정된 화면에서만 절대 위치로 등록한다. 손잡이가 먼저 끝에 도착한 움직이는 화면은 위치 미리보기만 즉시 이동하며, 카드 슬롯을 끝점에 맞춰 확정하지 않는다. 이후 안정된 끝점과 여섯 열 이상 겹치는 카드로 과거 대기 화면을 연결한다. 안정된 끝점은 스크롤바만으로 예측한 임시 위치를 정정할 수 있지만, 독립적으로 확인한 위치와 검증된 이름순이 충돌하면 등록을 보류한다.

스크롤바가 카드보다 한 줄 먼저 움직인 화면은 겹치는 카드로 위치를 연결할 수 있지만 보정값 학습에는 사용하지 않는다. 위치 보정과 겹침 없는 화면의 보정값 적용은 연속 획득 화면에서 최소 여섯 열의 관측 그룹이 같은 슬롯에 있고 손잡이 이동이 0.12행 이내인 경우에만 허용한다. OCR의 안정 관측은 같은 열의 다른 행도 허용하므로 위치 보정의 정지 조건으로 재사용하지 않는다. 창 검출 실패·손잡이 가림·정렬 변경은 정지 연속성을 끊는다. 나중에 정지 화면이 연결되면 대기 중인 앞뒤 화면도 기존 여섯 열 겹침 조건으로 연결하며, 카드 수만으로 빈칸을 채우지 않는다.

`live-scroll-preview.ts`는 마지막 검출 좌표로 현재 video의 스크롤바(16×942) 하나만 최소 32ms 간격으로 읽는다(60fps 입력에서는 약 30회/초). 새 영상 프레임 콜백에서는 획득·인코딩 전에 위치를 갱신하며, 별도 타이머는 백그라운드에서 영상 콜백이 멎을 때의 보조 경로로 유지한다. 같은 픽셀의 위·아래 화살표 영역을 창 위치 기준으로 재사용하므로 추가 픽셀 읽기는 하지 않는다. 카드 획득 Worker나 OCR 큐를 기다리지 않으며 별도 큰 프레임·기록·판독 근거를 생성하지 않는다. 검출 결과의 나이만으로 좌표를 만료시키지 않고 현재 화살표 픽셀이 일치하는 동안 유지한다. 좌표가 같은 지연 검출은 기준 픽셀을 덮어쓰지 않는다. 지연된 검출 실패도 현재 픽셀로 확인한 위치 강조를 지우지 않는다. 위치만 움직일 때는 마지막 카드 칸 배열을 재사용하고 행 컴포넌트를 메모해 550칸을 매번 다시 렌더링하지 않는다. 화살표 영역이 달라지면 즉시 표시를 숨기고 2초 동안 재확인하며, 계속 다르면 좌표를 폐기한다. 해상도 변화나 픽셀 읽기 실패는 즉시 좌표를 폐기한다. 이 화면 표시용 경로는 원본 재현의 인식 입력이나 판독 완료 조건을 바꾸지 않는다. `scrollPreviewPerformance`에 유효 표본 수·픽셀 검사 시간·획득 중 표시 갱신 횟수를 남긴다.

`scan-monitor-store.ts`는 위치·판독 수·보관함 수량만 별도로 전달한다. 진행창은 `useSyncExternalStore`로 구독하여 카드 목록의 묶음 갱신과 React transition을 기다리지 않는다. 새 스냅샷이어도 칸의 상태·위치·사유와 진행 수치가 같으면 기존 표시 데이터를 재사용하고 알림을 생략한다. 칸이 바뀌면 해당 행만 다시 그린다. 완료 표시가 최신 미확정 관측으로 되돌아가는 변경도 즉시 전달하며, 판독 근거 자체는 합치거나 생략하지 않는다. 카드 이미지·기록 픽셀은 이 저장소에 보관하지 않는다. 본문 진행률과 요약 숫자도 같은 저장소의 숫자만 구독해 App의 200ms 목록 갱신을 기다리지 않는다.

판독 결과는 칸 상태를 먼저 반영한 후 발행한다. 전체 목록은 `coalesced-publisher.ts`의 100ms 주기를 유지하고, `reading-feedback.ts`의 별도 표시 경로는 33ms 간격으로 최신 필드 근거·체크·판독 수를 발행한다. 마지막 변경도 예약 발행하므로 새 프레임 없이 체크가 갱신된다. 브라우저 타이머 지연은 별도이며 33ms는 실제 출력 지연 보장이 아니다. 빠른 경로는 정렬·진단 이미지·위치 그래프를 재계산하지 않고 이미 검증한 위치의 최신 상태만 갱신한다. 이름 보정은 같은 consensus 객체에만 재사용하고 최신 실패는 완료 체크를 철회한다. 이 표시 경로는 watchdog·자동 종료의 진행 근거로 사용하지 않는다. 종료·취소 시 예약과 늦은 콜백을 차단한다. 진행창의 `최근 수집`은 마지막 획득 화면에서 판독 대상으로 받은 칸만 집계하며, 위치 미연결 상태에서도 읽음·읽는 중·확인 필요를 표시한다. 빈칸·가림으로 거절된 크롭은 이 수에 넣지 않고, 현재 게임 화면이나 전체 목록의 완료 수로 해석하지 않는다. 엔진 준비 중에는 판독 대기·최근 화면·지도 대신 준비 안내만 표시한다. 진행 중에는 `미수집`(보관함 수량 - 수집한 이름)과 `확인 필요`(review 카드)를 분리해 표시하며, 두 값을 합친 "부족" 수로 완료 상태를 설명하지 않는다. 새 스캔 시작이나 공유 종료 때 이전 목록을 즉시 지우지 않고, 새 상태가 오기 전까지 유지한다. `begin()`이 40칸과 최근 프레임을 비우는 순간에는 표시 저장소가 마지막 커밋 셀·프레임을 유지해 지도가 매 프레임 깜빡이지 않게 한다. 스캔 후에도 현재 목록의 판독 완료·미수집·확인 필요 요약을 남긴다. 카드 목록은 33ms 진행창 갱신에 굶지 않도록 React transition이 아닌 일반 우선순위로 200ms 코얼레스 갱신한다. 진행창의 `마지막 촬영 화면` 완료 수는 전체 `판독 완료` 수와 별개이며, 현재 행 범위는 `현재 화면 약 N–M행`으로 표시한다.

맨 위·맨 아래의 비활성 화살표나 마우스 오버로 한쪽 끝의 모양만 바뀌면, 반대쪽의 무늬가 있는 화살표 픽셀이 일치하고 현재 손잡이가 검출될 때 추적을 유지한다. 평평한 배경만 일치하는 경우는 근거가 아니다. 위치 미리보기는 별도 타이머에서 읽어 compositor 콜백 지연에도 검사하며, 이 타이머로 획득 프레임이나 녹화 이벤트를 만들지는 않는다.

실시간 위치는 지연 도착한 카드 획득 프레임의 위치보다 우선 표시한다. 둘이 다르면 스크롤 허용 안내도 보류하며, 지도에 저장된 카드 위치를 추정으로 이동시키지 않는다. 위치 미확인은 카드 판독 실패와 구별한다.

고유 카드 수가 목표와 일치할 때 자동 종료 검사는 현재 진행 중인 획득을 기다리는 동안 신규 획득을 잠깐 보류해 검사 기회를 확보한다. 최신 이름·각성·장수 검증과 1초 유지, 헤더 수량 재판독 조건은 그대로 적용한다. 전체 카드 판독 수에 도달했다고 테스트가 입력을 강제로 종료해서는 자동 종료 성능을 검증할 수 없다. 실시간 영상 테스트는 자체 자동 종료 여부, 공유 종료 시각, 최종 종료 시각, `finishTiming`의 마지막 식별 카드 입력 시각 이후 지연을 따로 기록한다. 이 시각은 식별된 입력 기준이며 화면에 있었지만 획득하지 못한 카드의 관측 시각을 증명하지 않는다.

자동 종료 직전에 일시적으로 창 검출에 실패하더라도, 이름·최신 필드·헤더 수량 검증으로 자동 종료했고 마지막 정상 헤더가 종료 시각 1초 이내라면 그 실패만으로 전체 기록 검사를 다시 시작하지 않는다. 수동 종료·오래된 헤더·미처리 작업·획득 누락·최신 필드 불일치는 기존처럼 재검사를 유지한다. `completion-check` 진단으로 이 조건을 따로 확인할 수 있다.
