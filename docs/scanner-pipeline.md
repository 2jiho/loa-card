# 스캐너 구조

화면 공유는 줄 중심 스캔으로 읽는다. 진입점은 `orchestration/scanner.ts`의 `runScanner`이고, 실제 스캔은 `orchestration/row-scanner.ts` → `orchestration/row-scan.ts`에서 돈다. v0.3.0 이전의 프레임 단위 스캐너 루프와 그 구조 설명은 제거됐으며 Git 이력에 남아 있다.

경로는 모두 `src/features/card-scanner/` 기준이다.

## 1. 준비

페이지를 열면 `session/scanner-preparation.ts`가 스캔에 쓸 판독기를 미리 만든다: 획득 워커 1개, 시각 판독 워커 2개(원화 대조·각성·장수), 이름 판독기 1개. 이름 판독기는 빈 카드로 한 번 읽어 두어 텍스트 모델을 미리 올린다. 준비가 끝나야 "화면 공유 시작"을 누를 수 있다.

준비된 묶음은 한 번의 스캔에만 넘겨진다(`claimPreparedScanner`). 스캔은 이것을 그대로 쓰고, 정리는 이름 판독 작업(`session/scanner-name-operation.ts`)이 스캔이 끝난 뒤 한다. 준비 없이 스캔하면(개발 재실행) 스캔이 직접 만들고 직접 정리한다.

## 2. 프레임 줄

공유 트랙의 프레임은 워커(`capture/track-line-worker.ts`)가 `MediaStreamTrackProcessor`로 받아 짧은 줄(기본 12장)에 세운다. 메인 스레드는 한 번에 한 장만 받아 처리한다. 줄이 넘치면 가장 오래된 프레임을 버리고 "지나친 프레임"으로 센다. 실제 공유는 처리할 수 있는 것보다 많은 프레임을 보내므로 지나친 프레임은 매번 생기며, 완료를 막지 않는다(`row-scanner-state.ts` 머리 설명).

## 3. 획득

각 프레임은 획득 워커(`acquisition/acquisition-worker.ts`)에서:

- 카드 창을 찾는다(`acquisition/detector.ts`). 공유 화면 크기로 배율을 먼저 짐작하고(`inputScale`, 2560×1440 = 1) 카드 테두리로 다시 맞춘다. 창이 없는 프레임이 두 번 이어지면 기다리던 프레임을 건너뛰고 가장 새 프레임으로 넘어간다. 한 번만 없으면(알림, 빠른 스크롤) 건너뛰지 않는다(`orchestration/row-scan.ts`).
- 10×4 격자의 40칸을 잘라 품질을 판정한다(`acquisition/card-acquisition.ts`): 네 테두리가 온전한지, 가려지거나 움직였는지, 빈칸(카드 뒷면)인지.
- 보관함 헤더 영역도 함께 넘긴다.

메인 스레드는 스크롤바 띠를 읽어 화면 맨 위 줄이 목록의 몇 번째 줄인지와 스크롤바가 멈춘 시간을 구한다(`session/scroll-position.ts`).

## 4. 줄 판독

`orchestration/row-session.ts`가 프레임마다 보이는 4줄을 읽는다.

- **탐침**: 줄마다 2칸을 먼저 시각 판독한다. 두 칸이 목록 표에 이미 있는 카드이고 같은 줄에 나란히 있으면 그 줄이 목록의 어느 줄인지 알 수 있고, 아직 값이 없는 칸만 읽는다. 조금이라도 불확실하면 줄 전체를 읽는다(`session/row-read-plan.ts`). 이 계획은 일을 줄일 뿐 카드나 값을 채우지 않는다.
- **시각 판독**: 워커 2개가 원화 대조로 카드를 식별하고 각성·장수를 읽는다(`recognition/visual-worker.ts`).
- **이름 판독**: 원화로 식별하지 못한 칸은 이름 판독 줄(1개, 프레임 루프를 기다리게 하지 않음)로 보낸다. 텍스트를 읽기 전에 이름 띠의 밝기 폭을 잰다(`recognition/name-visibility.ts`의 `nameBandSpread`). 폭이 `NAME_TEXT_SPREAD`(12, `recognition/recognizer.ts`)보다 작으면 글자 획이 없는 띠(빈칸, 마우스 강조로 씻긴 띠, 가려진 띠)로 보고 텍스트를 읽지 않는다. 텍스트를 읽고도 이름을 못 찾은 자리는 잠시 다시 읽지 않는다(`session/name-hold.ts`). 같은 원화를 쓰는 카드는 이름과 등급, 차순위 격차로 구분한다. 이름 판독도 원화를 다시 확인하는데, 전체 원화와 비교해 순위를 매기는 무거운 계산은 원화 순위 워커(`recognition/portrait-matcher.ts`의 `rank` → `recognition/portrait-worker.ts`)가 하고, 통과 판정(이름 근거 포함)은 그 순위로 메인 스레드에서 한다. 판정은 직접 순위를 매긴 경우와 같다(`tests/portrait-matcher.test.ts`). 정밀 재정렬(1/4칸)은 드물어 메인 스레드에서 직접 계산한다.
- **목록 표**(`session/list-table.ts`): 카드를 목록의 행·열에 놓는다. 카드를 공유하는 프레임끼리 "조각"으로 이어 붙이고, 스크롤바가 멈춘 프레임이 조각의 위치를 정한다. 움직이는 스크롤바는 위치가 아니다. 위치를 정하지 못한 조각은 버리지 않고 "떠 있는 조각"으로 남는다. 맞지 않는 관측(한 카드가 두 자리, 한 칸의 카드가 바뀜)은 세어 두고 처음 기록을 덮어쓰지 않는다.

## 5. 병합과 확정

읽은 크롭은 모두 `session/row-evidence.ts`를 거친다.

- 필드 수락(`session/field-acceptance.ts`)과 관측 병합(`session/inventory-evidence.ts`): 각성과 장수는 함께 유효한 관측으로만 병합하고, 최신은 처리 완료 시각이 아니라 **캡처 시각** 순서로 정한다. 같은 프레임 재시도나 캐시는 독립 관측으로 세지 않는다.
- 장수의 신뢰도는 그 크롭 자체의 근거로 정한다(`session/field-acceptance.ts`의 `readFieldReliability`).
  - 목록이 멈춰 있다는 것만으로는 확정하지 않는다. 같은 픽셀에서는 잘못 읽은 값도 똑같이 반복되기 때문이다.
  - 숫자 패턴만 읽은 값은 목록이 멈춰 있어도 확정 근거가 아니다.
  - 텍스트 판독기가 따로 같은 값을 읽었으면 멈춘 목록의 값을 근거로 쓴다.
  - 패턴으로 읽기 어려운 장수(1920×1080 등)는 새 텍스트 판독 두 번으로 확정한다(`textCountReading`, `agreesWithEarlierReading`). 두 판독은 서로 다른 프레임이고 0.25초 이상 떨어져야 하며, 각성과 장수가 같아야 한다. 각 판독은 캐시가 아닌 새 판독이고, 패턴의 1순위 후보와 같고, 테두리가 온전한(정렬 0.8 이상) 크롭의 양수여야 한다. 같은 프레임의 재시도는 두 번째 판독이 아니다.
- "확정"은 `session/recovery-completion.ts`의 `confirmedReadingCount`가 이번 스캔의 관측으로 값을 확인한 카드다.
- 장수 0: 미판독(`null`)과 명시적으로 본 0장을 구분한다. 장수가 비거나 확정되지 않은 0인 카드는, 보관한 크롭에 빈 장수 칸이 분명히 보이고 그 뒤 크롭에 양수가 없을 때만 0으로 확정한다(`confirmZeros`). 공유 중에도 약 1초마다 돈다.

## 6. 헤더와 완료

보관함 헤더("보유 수 / 용량")를 처음 보일 때 읽고, 모든 판독이 끝난 뒤 마지막 프레임에서 다시 읽는다. 보유 수는 확정해야 할 카드 수, 용량은 목록에 칸이 있는 줄 수(450 → 45줄, 그 뒤는 잠긴 줄)가 된다.

헤더는 공유 중에도 다시 읽는다(`orchestration/row-scan.ts`).

- 처음 읽은 뒤 기록 시각 약 3초마다 다시 읽는다. 지금 값과 다른 값을 연달아 두 번 읽으면 그 값으로 바꾼다. 한 번 잘못 읽은 헤더 때문에 스캔이 끝나지 못하는 일을 막는다.
- 모든 카드가 확정된 동안에는 약 1초마다 다시 읽는다(`freshExpected`). 공유 자동 종료는 이 값이 지금 값과 같을 때만 한다.

완료(`orchestration/row-scanner-state.ts`)는 모두 성립할 때만이다: 헤더 수량을 다시 읽어 같은 값이었고, 이름을 읽은 카드와 확정된 카드가 모두 그 수와 같고, 기다리는 판독이 없고, 카드가 모자란 동안에는 이름 없이 본 칸이 없을 것. **카드 수가 맞는 것만으로는 완료하지 않는다.** 모든 카드가 확정된 상태가 1초 이어지면 공유를 자동으로 끝내고(`row-scanner.ts`), 남은 판독을 마친 뒤 완료 여부를 정한다. 미완료면 이유를 상태 문구와 확인 항목에 남기고 기존 저장 목록은 바꾸지 않는다(`app/scan-lifecycle.ts`).

### 멈춤 감시

스캔은 감시(`ui/scan-watchdog.ts`의 `guardScan`) 안에서 돈다. 진척은 상태 문구나 대기열이 아니라 끝낸 일의 양으로 잰다.

- 줄 중심 스캔은 끝낸 일의 합을 `workDone`으로 낸다: 읽은 프레임, 이름·장수 판독, 헤더 판독, 0장 확인 판독. 공유가 끝나 프레임이 오지 않아도 이 값은 늘어난다.
- 공유가 끝나면 프레임이 상태를 내보내지 않는다. 그래서 0.5초마다 상태를 다시 낸다(`row-scan.ts`의 heartbeat). 남은 판독의 진척이 감시와 화면에 보인다.
- 한도(`scanLimits`): 진척 없음 15초면 중단, 정리 15초, 준비 180초. 7초 동안 진척이 없으면 지연 안내를 띄운다.
- 공유 중이고 대기·진행 중인 판독이 없으면 입력을 기다리는 것으로 본다. 멈춘 창을 계속 공유해도 중단하지 않는다.
- 중단해도 읽은 카드는 남는다. 스캔은 미완료로 끝난다.

## 7. 화면 표시

표시는 스캔 결과를 바꾸지 않는다.

- **진행 창**(`ui/ScanMonitor.tsx`): 확정 수, 이름 미확인·확인 필요·판독 대기 수, 목록 지도. 지도(`session/list-guidance.ts`의 `listGuidanceMap`)는 지금 화면, 다 읽은 줄, 다시 볼 줄(장수·각성 확인 필요, 카드를 알아보지 못한 칸), 아직 안 본 줄, 헤더로 아는 빈칸·잠긴 칸을 보여 준다. 판독한 프레임의 스크롤바로 본 줄을 칠하므로 스캔 순서와 관계없이 지나간 줄이 칠해진다. 스캔이 끝나기 전에는 일시적인 변화를 붙잡아 둔다. 새 강조는 1.5초 이상 이어질 때만 보인다(`holdNewCardTargets`, `CARD_TARGET_HOLD_MS`). 확정 수의 감소는 3초 이상 이어질 때만 보인다(`displayConfirmed`, `COUNT_DIP_HOLD_MS`, `orchestration/row-scan.ts`). 확정된 카드의 새 관측을 읽는 데 5120×2880에서 약 2초가 걸린 사례가 있어서다. 붙잡는 것은 화면 값뿐이다. 완료와 공유 자동 종료는 실제 확정 수(`confirmed`)로 판단한다. 최종 결과는 붙잡지 않는다. 모든 카드가 확정되면 다시 볼 줄을 비운다.
- **판독 흐름**(`ui/ScanConveyor.tsx`): 대기 수와 방금 읽은 카드.
- **확인 항목**(`ui/ScanAttention.tsx`): 공유를 끝낸 뒤 확인할 카드(화면에서 잘라 온 사진), 미식별 입력, 다시 스캔할 곳(목록 지도와 한 줄 안내).
- **내 카드 목록**: 카드마다 화면에서 잘라 온 작은 사진을 보여 준다(없으면 원화).

## 8. 측정

정확성은 공유 종료 시점의 결과와 최종 결과를 따로 본다. 화면 반응·판독 지연·처리 프레임 수는 기록 재실행으로 잰다([개발과 검증](development.md#스캔-재실행-검사)). 이 PC의 부하에 따라 결과가 달라지므로 한 번의 실행을 실시간 보장으로 보고하지 않는다.

## 한계

- 인식 확인은 한 계정의 보관함과 1600×900~5120×2880 기록에서 한 것이다. 1920×1080 미만은 일부 장수·각성이 미확정으로 남을 수 있다.
- 지나친 프레임에만 보였던 값의 변화와, 가려진 채로만 보였던 값의 변화는 이전 값으로 남는다(`row-scanner-state.ts`).
- 위치를 정하지 못한 조각의 카드는 목록 지도의 정확한 줄에 표시되지 않을 수 있다(카드 확정에는 영향 없음).
