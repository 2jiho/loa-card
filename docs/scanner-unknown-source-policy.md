# 미식별 관측의 출처별 판정 실험

이 문서는 출처별 미식별 판정 실험을 설명한다. 개발 검사 페이지에 `?unknownPolicy=source-v2`를 명시하면 동일 스캐너의 판독·완료 조건에 v2가 적용된다. 기본 개발 검사와 배포 앱은 기존 v1 정책을 유지하며, 운영 경로에서는 v2 선택을 무시한다. 이 실험은 제품 기능이 아니다.

## 문제와 정책

수집 그룹은 유사한 이미지를 효율적으로 묶기 위한 추정값이다. 같은 그룹에 속한 관측이 항상 같은 카드라는 근거는 아니다. v1은 그룹마다 미식별 항목을 하나만 유지하고 같은 그룹의 다른 관측에서 확정한 이름으로 해제할 수 있다. 반면 v2 실험은 세션·그룹과 프레임·관측 ID·순번·시각·phase·slot이 같은 출처만 같은 관측으로 취급한다. 같은 출처의 pending 재시도는 합치고 확정된 이름이 있을 때 그 출처만 해제한다. 다른 출처가 뒤늦게 처리되거나 같은 순번을 사용해도 독립적으로 남는다. 확인이 필요한 이름은 확정 근거가 아니다.

기본 v1의 ledger도 개별 출처가 아니라 그룹별 `identified`를 유지한다. 서로 다른 출처의 실패 후 같은 근사 그룹의 성공이 오면 실패가 해제되고, 성공 후 다른 출처가 실패하면 이미 식별된 그룹이라는 이유로 미해결이 생기지 않는다. 특히 큐 판독이 실패하고 안정적이지 않으며 각성도 판독되지 않은 관측은 기본 경로에서 미식별 목록에 별도 등록되지 않을 수 있어, 목록과 ledger가 모두 이를 놓칠 수 있다. 다른 완료 조건이 충족된다는 **합성 조건**에서는 이 미해결 값이 0으로 전달되어 자동 종료 조건을 통과하는 반례가 있다. 이는 실제 해당 스캔에서 다른 모든 조건이 동시에 충족되었음을 증명하지 않는다.

`node --import tsx --test tests/legacy-group-completion-risk.test.ts`는 서로 다른 출처에 대해 위 두 경우를 실제 ledger·v1/v2 미식별 상태와 종료 조건을 조합해 재현한다. 동일 근사 그룹에서 나온 다른 출처의 성공으로 기존 실패를 해제하는 v1 동작은 안전한 완료 규칙이 아니라 현재 위험을 드러내는 특성화 결과다. v2는 같은 합성 반례에서 해당 실패를 유지하지만, 별도 프레임의 재관측을 기존 출처에 안전하게 연결하지 못하고 큐 한도와 지연도 검증 중이므로 제품 사용이나 실제 입력의 정확한 자동 종료를 보장하지 않는다.

그룹 ID는 스케줄링 정보다. 서로 다른 프레임 사이의 카드 동일성을 판정하지 않으며, 근사 이미지 유사도·스크롤 위치·`pixelKey` 문자열만으로 미확정을 해제하지 않는다. `pixelKey`는 수집기 내부에서 생성되는 범위 한정 키로, 독립된 기록에 있는 문자열만으로 픽셀의 동일성을 입증할 수 없다. **ROI 전체의 픽셀이 같아도 동일 카드의 증거는 아니다.** 같은 툴팁이나 빈 슬롯이 서로 다른 카드를 가릴 수 있고 정렬·필터도 바뀔 수 있다. 수집기의 실험용 픽셀 비교는 진단으로만 사용한다. 서로 다른 프레임에서 재촬영하여 해제하려면 가림과 정렬 변경을 포함해 별도의 신뢰할 수 있는 카드 식별과 최신 필드 근거를 설계하고 검증해야 한다. 근거가 없으면 계속 미확정으로 남기는 보수적인 정책이므로 재촬영 요구가 증가할 수 있다.

같은 **정확한 관측 출처**가 서로 다른 그룹에서 같은 카드로 확인되는 것은 허용하지만, 다른 카드 ID로 확인되면 그룹에 관계없이 충돌을 유지한다. 충돌한 출처의 모든 그룹 확인은 무효화하며, 이후 재시도만으로 충돌을 지우지 않는다. 다른 관측 ID나 phase를 프레임 번호만 같다는 이유로 동일 출처로 합치지 않는다. 확인 출처와 그 그룹 역인덱스는 기존 proof 한도에 함께 묶이며 충돌 처리는 해당 출처의 그룹만 방문한다. 현재 정책은 기록 누락 또는 한도 손실의 완전한 복구를 주장하지 않는다.

상태 해시는 정규화된 이벤트 상태의 재현 확인용이며 픽셀·OCR 결과의 진위 증명이 아니다. v2 상태 해시는 고정 문자열 순서로 정렬하며 기록 손실 시 제공하지 않는다. v1 기록은 v1 판정기로 계속 재생한다. v1 이벤트의 발생 사실만으로 누락된 픽셀이나 독립된 식별 근거를 복원할 수 없으므로 v2 의미로 자동 변환하거나 두 결과를 동등하다고 표시하지 않는다.

활성 미확정이나 확인 근거 한도 초과, 동일 출처의 서로 다른 확정 이름은 손실·충돌로 남기고 자동 완료를 막아야 한다. 기록 이벤트 한도 및 쓰기 실패는 기록 불완전으로 표시하지만, 그것만으로 실시간 인식 실패를 만들어내지는 않는다. 이후 해제되더라도 한도 때문에 이미 잃은 출처의 완전성은 복구된 것으로 단정하지 않는다. proof 한도는 개별 출처에 적용되므로 장시간 스캔에서 빨리 소진될 수 있다. 안전하게 해제할 수 있는 시점은 해당 출처에 대한 모든 비동기 작업이 종료됐다는 명시적 근거가 있어야 하며, 만료도 재현 가능한 이벤트로 기록해야 한다. 무조건 오래된 항목을 지우지 않는다.

## 개발 실험 사용과 한계

### 숨은 실패의 출처 진단

개발 검사 페이지에 `?hiddenUnknownProbe=1`을 명시하면 기본 group-v1 정책을 그대로 사용하면서, 같은 근사 그룹의 다른 출처 성공으로 사라지거나 순서·기존 확정에 의해 숨겨진 **최종 실패**와 기존 경로에서 보고하지 않은 실패를 별도의 출처 장부로 관찰한다. 기본값은 꺼짐이며 배포 빌드에서는 이 옵션을 무시한다. source-v2와 동시 선택은 개발 페이지에서 거부한다. 일반 카드 목록, 진행 UI, 완료 판정, 재시도 큐에는 장부를 사용하지 않는다.

장부는 세션·프레임·관측 ID·촬영 순서·시각·단계·슬롯이 모두 같은 출처의 이름을 직접 확인한 경우에만 해당 숨은 실패를 해제한다. 유사 그룹·위치·수량으로 해제하지 않는다. pending 입력이나 이름 또는 다른 검토 항목이 남은 판독은 확정으로 취급하지 않는다. 이미 보고된 v1 이벤트 기록은 변경하지 않고 `hidden-unknown-event`에 seed, 숨은 최종 실패(`suppressed`, `replaced`, `retired`, `unreported`), 직접 확정을 기록한다. `hidden-unknown-summary` 및 개발 보고서 `hiddenUnknownEvidence`는 진단 전용이며 기록이 없는 예전 실행에서 이 장부를 소급해 완성했다고 가정하지 않는다. 기존 사건만의 반사실 재생은 원래 미보고 실패를 재구성하지 못한다.

숨은 활성 출처는 최대 128건, 직접 확정 출처는 최대 10,000건, 진단 이벤트는 최대 20,000건이다. 출처 한도 또는 같은 출처의 다른 이름은 `evidenceLost`로 남고, 기록 수신 거부·오류·이벤트 한도는 `recording: partial`로 표시한다. `recording: complete`는 요약 **이전의** 진단 이벤트를 설정된 큐가 동기적으로 수락한 결과일 뿐 디스크 저장이나 픽셀·OCR 인증이 아니다. 요약 자체 수신은 `summaryTraceAdmitted`로 별도 표시한다. 숨은 이미지는 추가 저장하지 않는다. 선택한 세션은 이 진단을 포함하는 기록 부하가 증가하므로 비활성 실행과 성능을 분리해 측정한다.

`HiddenGuardReplay`는 별도 시험용 장부로, 발생 순서 해시와 전체 출처별 상태 해시를 검증한다. 상태 검증 중에는 이전 일치 결과를 표시하지 않고, 검사 시작 시점의 검증점 값을 사용한다. `tests/unknown-hidden-replay.test.ts`는 이 동기화·이벤트 순서·한도 경계를 합성 입력으로 검사한다. 이 모듈은 아직 실제 상세 기록의 봉인·저장 확인이나 제품 완료 판정에 연결되지 않았다. 해시 일치 자체는 저장 원본의 완전성, 카드의 정답 또는 실시간 안전 완료를 증명하지 않는다. 미식별 외에 가림·최신 필드 부채에도 동일한 출처 연결 문제가 있으므로 함께 해결해야 한다.

기존 영상5의 비공개 상태 이벤트(원본 SHA 및 이벤트 순서 검증) 1,539개를 현재 진단 장부로 재생하면 기존 v1에서 가려진 출처 1건이 남는다. 이는 원래 픽셀, 실제 정답, 실시간 자동 종료, 현재 코드와 동일한 사용자 화면 공유를 입증하지 않는다. 개발 진단을 제품의 완료 조건으로 승격하기 전에는 미보고 이미지 보존 비용, 원본 출처 재판독의 실제 연결·성공, 장시간 상한, 재촬영 뒤 안전한 해소, 저장 이벤트 재생과 UI 및 전체 실시간 성능을 따로 검증해야 한다.

개발 서버의 `/dev/scanner.html?unknownPolicy=source-v2`에서 입력을 선택해 검사한다. 저장 입력의 재판독도 현재 선택한 정책을 사용한다. 스캐너 구성 기록의 `unknownSourcePolicy`는 `source-v2` 또는 `group-v1`이다. 기본 v1 기록과 v2 기록은 서로의 결과를 대체하지 않는다.

v2 실험은 **다른 프레임의 재관측을 이전 미식별 출처와 연결하지 못한다.** 같은 수집 원본에 대한 직접 보조 판독만 해당 경고를 해제할 수 있다. 보조 판독이 이미 끝난 경우 다시 보여주어도 미해결 상태가 유지되어 자동 종료가 막힐 수 있으며 새 스캔이 필요할 수 있다. 이런 한계는 개발 페이지에도 표시한다. 입력이 없는 가상의 재시도나 단순 그룹 일치에 의한 해제를 만들지 않는다.

`SavedOriginalSourceBindings`는 무손실 원본 재판독을 위해 입력·복구 출처, 프레임 메타데이터와 크롭 기하를 대조하는 별도 실험이다. `unknownPolicy=source-v2`, `prepared=1`, `restoredHandoff=1`, `preparedCropProof=1`을 모두 선택한 개발 스캔에서만 큐 수락 이후 원본 슬롯의 메타데이터를 연결한다. 복구 시 원본과 복구 출처, 저장 확인 연결 여부를 따로 집계하며, 누락이나 한도 초과는 성공으로 세지 않는다. 세션 수명과 한도를 두지만 전달된 해시나 저장 내용을 이 객체가 인증하지 않으므로 결과는 `pixelsAuthenticated: false`다. 이 메타데이터를 미식별 해소나 완료 판정에 사용하지 않는다. 이 메타데이터와 인증된 복원 픽셀, 실제 판독을 결합하는 단리 구성은 아래 `createVerifiedRecoveryRead`가 제공한다.

개발 상태 기록은 출처 연결 이벤트와 요약을 기존 바이트·이벤트 한도 안에서 저장하며, 한도 초과나 유효하지 않은 이벤트는 누락으로 집계한다. 개발 JSON 보고서의 `traceAccepted`는 해당 요약을 기록 큐가 수락했는지만 뜻하며 압축 완료 또는 저장 파일의 무결성을 보증하지 않는다. 기록 전체의 완전성은 별도로 확인한다.


별도 `UnknownRecoveryClaimReplay`는 원본 출처와 복구 출처를 함께 기록한 v3 **주장**을 개발 상태 추적과 상세 기록 재생에서 처리한다. 기존 v1·v2 기록의 의미는 유지하고 라이브 스캐너의 v3 이벤트 생성은 아직 연결하지 않았다. 기록에 적힌 해시와 판독 결과는 생산자가 주장한 값이므로 상태 주장의 일치는 픽셀·OCR·카드 신원의 인증이 아니다. v3에서는 `matchesCapturedState`를 미확인으로 유지해 원본 기록 보호를 해제하지 않는다. 출처 충돌이나 한도 초과는 불완전으로 남긴다.

`createVerifiedCropReader`는 주장된 크롭과 판독 직전 캔버스를 비교하고 별도 캔버스의 픽셀을 확인한 다음 주입된 판독 콜백을 호출하는 개발용 경계다. 콜백이 취소·시간 초과 뒤에도 종료되지 않으면 해당 캔버스와 작업 예약을 유지하고 추가 작업을 받지 않는다. 제한은 인스턴스별이므로 스캐너 통합 시 카드마다 새 인스턴스를 만들지 않고 세션 전체 한도를 검증해야 한다. 예약량은 추정치이며 브라우저·판독기의 전체 메모리 상한이 아니다. 주입된 콜백이 실제 모델인지, 전달된 주장이 저장 원본과 일치하는지 이 경계만으로는 인증하지 못한다. 아직 실제 스캐너에 연결하지 않았으며, 판독 결과를 완료 근거로 사용하지 않는다.

실제 판독 예산이 시간 초과를 반환한 뒤에도 내부 OCR 요청이나 워커 정리가 끝나지 않을 수 있다. 콜백의 반환만으로 내부 작업 종료를 증명할 수 없으므로 현재 크롭 경계를 실제 판독기에 단순 연결하지 않는다. `tests/verified-reader-budget-boundary.test.ts`는 실제 예산과 모의 미완료 작업을 조합한 반례다. 안전한 통합에는 판독기 재사용 격리, 내부 작업·정리 종료 확인, 별도 캔버스의 진단 전달 및 종료 시 자원 정리가 필요하다. 이는 모의 작업 검증이며 브라우저에서 OCR 워커 종료를 측정한 결과는 아니다.

`createVerifiedRecoveryRead`는 위 구성 요소들을 하나로 결합한 개발 전용 실험이다. `SavedOriginalSourceBindings.read`가 넘긴 메타데이터 설명과 같은 원본 출처의 `UnknownCropRetention` 보관 복사본, 그리고 복원 픽셀 capability의 단일 사용 소유권 이전(`consume`)을 받아, 보관 크롭이 복원 원본의 해당 영역과 **바이트로 일치**할 때만 비공개 캔버스 경계에서 주입된 실제 판독 콜백을 실행한다. 동일 픽셀의 재판독이므로 결과의 `independentObservation`과 `completionEvidence`는 항상 false다. 이름·각성·장수가 그 단일 판독에서 모두 확인돼야 `resolved`이고, 장수 실패(null)를 0으로 바꾸지 않으며, 확인된 0장은 유효 관측으로 받아 들인다. 호출자가 제공하는 최신 확인 캡처 시각 오라클이 원래 캡처보다 뒤면 덮어쓰기 대신 `stale`로 남는다(최신 기준은 처리가 아니라 캡처 시각). 해시 불일치·바이트 불일치·복원 래스터 정체 불일치·예산·시간 초과·취소·닫힘은 각 상태와 사유로 미해결을 유지하고, 복원 토큰은 판독 시도 전에 한 번 소비된다. `tests/verified-recovery-read.test.ts`는 합성 픽셀로 성공과 각 실패 경계를 검사한다. 이 구성은 스캐너와 자동 종료에 연결하지 않았으며, 실제 입력에서의 보관 크롭 복원 성공률, 메모리 비용, 재촬영 안내와의 관계는 아직 측정하지 않았다.

복원 픽셀 capability와 단일 소유권 이전은 기본적으로 꺼진 개발 실험이다. 같은 캡처 소유자가 저장 확인 정보와 복원한 RGBA의 SHA-256을 대조하고, 이전 직전 재해시·변경 여부를 확인한 뒤 토큰을 소모하고 원본 버퍼를 분리한다. 개발 검사에서 `?prepared=1&restoredHandoff=1`로 선택하며 실제 복구 입력이 없거나 검사 자체가 생략되면 수행 횟수는 0이다. 전달 횟수와 실패는 개발 보고서에서 따로 확인한다. 취소 신호는 개별 연산을 취소하고 세션의 증거 폐기는 소유자 종료·취소·폐기로 처리한다. capability는 특정 시점의 복원 픽셀 증거일 뿐 크롭·OCR 실행·가림 여부나 카드의 동일성을 증명하지 않는다. 내부 작업 바이트 제한은 전체 브라우저 메모리 상한이 아니다. 영상 5의 부분 기록에서 프레임 74의 복원 픽셀과 기록 해시 일치, 단일 이전, 중복 사용 거부를 로컬 CLI로 확인했다. 그 검사는 테스트용 확인 콜백을 사용했으며 실제 캡처 소유자의 저장 확인 경로 전체나 카드 판독까지 검증하지 않았다. 별도의 바이트 기반 모의 저장소·캔버스 통합 검사는 실제 canonical 제어기와 prefetch, 획득 fallback의 측정 receipt를 연결하지만 실제 브라우저 Worker나 OCR 검증은 아니다.

개발 실험의 원본 발급 및 이전은 각각 전체 RGBA를 복사·해시한다. 예를 들어 2560×1440의 Node 합성 입력 5회에서는 issue 중앙 약 13ms, consume 중앙 약 25ms였다. 이는 캡처·GPU·OCR·브라우저 전체 지연이 아니며 기기별 차이가 있다. 실험 한도는 발급 1,024회·토큰 수명 5분·동시 내부 작업 예약 256MiB로, 전체 브라우저 메모리 사용량의 상한이 아니다. 실제 복구 프레임이 많으면 추가 지연이 누적될 수 있으므로 기본 스캔에는 켜지 않는다.

개발 검사의 `?prepared=1&preparedCropProof=1`은 실제 준비 입력의 검출 캔버스에서 전송 직전 카드 크롭을 같은 프레임의 정수 좌표 RGBA와 비교한다. 프레임도 재해시하고, 메인 스레드의 전달 캔버스와 판독 직전 캔버스를 각각 별도로 대조한다. 소수점·크기 변환·투명 픽셀 등 미지원, 한도, 시간 초과, 캔버스 오류와 미완료는 별도로 기록한다. 워커 측은 최대 40칸·크롭 합계 8MiB·프레임 32MiB·750ms, 전달 캔버스 비교는 250ms 예산이다. 타이머는 동기 코드 실행이나 브라우저 일시 중단을 중지시키지 못한다. 검사는 개발 실험에만 적용되며 전체 프레임과 크롭 복사·해시 비용이 있으므로 성능 측정 시 별도로 표시한다.

검증용 `/dev/prepared-crop-browser-proof.html`은 사용자가 제공한 이미지나 영상을 불러오지 않고 생성한 합성 픽셀과 수동 격자로 실제 브라우저 획득 Worker를 호출한다. 불투명 영역의 크롭 해시와 소유권 이전, 투명 영역의 미지원을 확인하며 실제 창 검출·화면 공유·OCR·카드 정답은 검사하지 않는다. 비공개 영상 5의 부분 기록에 대해선 별도의 로컬 Node 검사에서 원본 프레임 74와 기록된 판독 PNG의 정수 크롭 바이트를 비교했고, 현재 Worker 비교 함수의 한 크롭 결과도 일치했다. 동일 픽셀 5회 반복 중앙 94ms는 Node의 단일 함수 측정이며 브라우저나 전체 스캔의 성능이 아니다.

이 비교는 해당 시점의 프레임/전달/판독 직전 캔버스 픽셀에 관한 진단이다. 캡처 owner의 저장 ACK와 판독 결과의 권한 결합, OCR 모델이 실제로 입력을 처리했는지, 카드 신원·최신 장수·각성·가림 없음은 증명하지 않는다. 입력·판독 결과를 원본 관측의 미식별 해소나 자동 종료에 사용하지 않는다. 판독 진단의 `accountingComplete`는 결과 집계가 끝났는지만 뜻하고, 입력이 없으면 `no-input`, 처리가 남거나 결과가 생략되면 `partial`로 구분한다.

별도의 개발용 수집 Worker 진단은 실제 획득 시 ROI의 전체 RGBA와 정수 기하 비교가 성공했는지 요청·응답의 프레임과 슬롯에 결합한다. 이 결과는 상태 변경에 사용하지 않으며 일반 앱에서는 켜지지 않는다. 소수점 기하나 오래된 출처가 한도 밖으로 밀린 경우에는 해당 비교를 미지원·미확인으로 표시하고 수집을 계속한다. 이 진단은 ObservationSource 인증이나 재현 파일의 픽셀 검증을 대신하지 않으며, 동일한 픽셀을 독립적인 판독 횟수로 세지 않는다.

v2는 품질을 통과한 근사 중복도 별도 출처로 판독하며, 메인 큐 160개와 두 보조 큐 각각 80개로 제한한다. 출처가 정확히 같은 후보만 교체하며, 포화로 처리하지 못한 입력은 손실 또는 미식별로 남겨 완료를 막는다. 정지된 화면도 반복 판독하기 때문에 포화와 지연이 쉽게 생길 수 있다. 이 한도는 항목 수 제한일 뿐 메모리·처리 시간의 실측 결과가 아니고, 아직 제품에 적용할 수 없다. 품질 선별에서 가려진 입력이 움직임으로 오분류되어 제외되는 경우나 저장 관측 재사용은 이 변경만으로 해결하지 못했다. 기록 이벤트는 설정된 기록기 각각의 동기 큐 수락 여부를 확인하지만 이는 저장 파일의 내구성 검증이 아니다. 기록 손실은 재현 불완전으로, 실시간 출처 한도·충돌은 별도의 완료 차단으로 다룬다. 실제 원본 입력과 완료된 파일의 검증은 별도로 필요하다.

개발 전용 `completionDrain` 실험에서 입력을 확보했다는 기록과 실제 카드 획득 처리의 수락을 분리했다. 카드 창을 찾지 못하거나 대기열이 차서 조기에 반환하면 손실을 기록하며, 획득한 카드 칸의 개수·슬롯 순서도 확인한다. 정상 빈 칸은 유효한 슬롯으로 인정한다. 수락은 획득 처리에 관한 것으로 가림 없는 판독을 증명하지 않는다. 조기 반환과 큐 포화에 대한 회귀는 파이프라인과 모의 소비자를 조합해 검증했으며 실제 게임에서 포화 상태에 도달하는지, 전체 스캐너에서 어떻게 동작하는지는 아직 검증하지 못했다. drain 손실과 자동 종료 판정 자체의 상태 기록 재생도 아직 지원하지 않는다.

툴팁 검출 후보를 보수적으로 검토했다. 공개 카드 크롭 6개에서는 정상 5개가 모두 후보가 아니고 툴팁으로 가려진 1개가 후보였으나, 비공개 영상 3의 보조자 육안 확인·수동 좌표 표본에서는 툴팁 크롭 3개 모두 후보가 아니었다. 같은 표본의 정상 2개·스크롤 전후 2개·커서 1개·빈 카드 1개도 후보가 아니었다. 이는 독립 사용자 정답이나 전체 환경의 정확도 검증이 아니지만, 현재 lower-panel 신호만 완료 차단에 연결해도 가림을 빠짐없이 찾지 못한다는 반례다. 잠금 카드의 별도 라벨 표본도 부족하다.

## 제품 통합 전 필요 작업

1. 수집 시 세션 내 고유 출처를 고정하고 워커와 모든 재시도에 전달한다. 다른 프레임·슬롯이나 순번이 같은 다른 출처가 합쳐지지 않도록 수집, 판독, 결과 전달의 경계를 검증한다. 실험용 수명 한정 receipt는 같은 수집기의 실제 ROI 바이트와 geometry가 같다는 사실만 나타낸다. 이를 출처와 연결하더라도 가림 없는 카드 식별이나 정렬·필터 유지의 독립 근거 없이 신원을 이전하거나 미확정을 해제하지 않는다. receipt 누락·기록 가져오기·프로세스 재시작은 비교 근거 없음으로 처리한다.
2. 개발 전용으로 연결한 미식별 레저와 실제 스캐너의 출처 단위 처리를 검증한다. 진단 UI와 사이드카는 출처 단위 키를 지원한다. 같은 그룹 안의 한 항목을 성공 처리하거나 삭제할 때 다른 항목의 상태와 이미지가 사라지지 않아야 한다. 누락·충돌 상태는 사용자에게 재촬영 이유와 확인 가능한 위치를 보여주고 완료 조건에도 반영한다.
3. v2 상태 기록은 정책 버전, 한도, 출처, 순서, 손실과 상태 해시를 보존하며 별도 리듀서로 재생한다. v1은 기존 해석을 유지한다. 개발 실험의 v2 기록과 누락·한도 초과 시의 표시를 실제 입력으로 검증해야 한다. 공개 배포의 제한된 진단과 개발용 상세 기록의 보관 및 개인정보 정책을 따로 적용한다.
4. 실제 화면 공유와 상세 입력 재생에서 동일한 판독·상태 갱신 경로를 사용한다. 동일 그룹 서로 다른 출처, 지연·역순 완료, timeout 후 재시도, 다중 프레임, 기록 손실, 과도한 작업 수와 UI 사이드카 삭제를 자동 종료까지 포함해 검증한다. 최종 확인 대상 수·최신 장수와 각성·미해결 건수·오인식·재촬영 부담을 각각 비교한다.
5. 수집·판독·UI 반응 시간과 메모리, 저장 용량 및 한도 도달률을 실제 입력에서 따로 측정한다. 최대치만을 근거로 실시간성을 보장하지 않는다. 수집 누락·잘못된 판정이 없는지 검증한 뒤 제품 연결을 결정한다.

## 현재 확인 범위

v1 상태 해시에는 라이브 미식별 근거 손실이 포함되지 않는다. 따라서 상태 재생의 `matchesCapturedState`는 이전 해시의 일치만 나타내고, 별도로 이벤트에서 복원한 `liveEvidenceLost`가 명시적으로 `false`일 때만 상세 원본 기록의 검증·보호 해제를 허용한다. 한도 초과나 신원 충돌은 `true`, 불완전한 기록·지원하지 않는 정책·알 수 없는 이벤트는 손실 부재를 증명하지 못해 `null`이다. 이는 과거 기록의 해시 의미를 바꾸지 않으며 카드 신원이나 OCR 결과가 정확하다는 인증도 아니다. 실제 영상 6의 저장된 v1 상태 기록은 기존 해시 일치와 손실 없음으로 재생되었다. 기록되지 않은 관측의 존재까지 확인한 것은 아니다.

영상 6의 기존 비공개 상태 이벤트 기록 3건을 동일 입력 이벤트로 반사실 재생했을 때 v1에서 각각 해제된 31·37·44건은 v2에서도 같은 출처의 확정으로 모두 해제됐고, 남은 미확정 및 손실은 없었다. 이는 **기록된 이벤트만** 비교한 결과다. 새로운 실시간 스캔, 누락된 프레임, 원본 픽셀의 진위, 정답 정확도, 장시간 한도 및 실행 속도는 검증하지 않았다. 단위 테스트는 다중 출처·역순·시간 초과·한도·충돌·기록 손실·v1 의미·상태 해시를 확인한다.

### 영상 5 비공개 상태 이벤트 회귀

선택적 `tests/video5-unknown-source-local.test.ts`는 기존 영상 5 실행 보고서 하나를 `LOACARD_VIDEO5_POLICY_REPORT` 환경 변수로 전달받는다. 보고서 SHA-256, 압축 청크 크기·이벤트 수·전체 연속 순서를 확인하고 동일 그룹에 기록된 입력 성공 및 별도 복구 출처의 미식별 이벤트를 현재 v1·v2 리듀서로 각각 재생한다. 이 부분 재생에서 v1은 실패를 억제하고 v2는 미해결로 남긴다. 파일을 지정하지 않으면 검사를 건너뛴다.

```powershell
$env:LOACARD_VIDEO5_POLICY_REPORT = '<비공개 보고서 경로>'
node --import tsx --test tests/video5-unknown-source-local.test.ts
```

선택한 복구 실패는 당시 공유 종료 이후에 처리됐으며 당시 입력 동영상의 모든 픽셀이 검증된 실행은 아니었다. 이는 **저장된 상태 이벤트 일부의 반사실 재생**이지, 두 관측이 실제로 다른 카드였다는 증거나 실시간 자동 종료 오류·OCR 정확도 검증이 아니다. 보고서는 개인 기록이므로 공개 저장소에 넣지 않는다.
